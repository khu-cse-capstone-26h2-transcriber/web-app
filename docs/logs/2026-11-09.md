### 확정으로 둔 것과 두지 않은 것

- 확정: 엔진이 어떻게 동작하는지(결과 필드, partial·final 규칙, 구간, 끝 신호, 상태 메시지). AI 파트가 정하는 항목이고 문서와 보드 측정으로 밝혔기 때문입니다.
- 확정하지 않음: 세션 주체, 수신 경로, 데몬 동작(대기 상태, 4xx 처리, `/end` 순서, 물리 버튼). 하드웨어 파트의 답이 없고 PR도 병합 전입니다. `segmentId`를 누가 붙일지와 빈 final 처리는 앱 파트가 정할 것으로 남겼습니다.

### 남은 점

- web-app PR #1 `apps/server/src/device/ingest.ts:101`: `end()`가 `sessions.stop()` 전에 `this.current`를 비웁니다. DB가 꺼져 종료가 실패하면 `503`을 주지만, 데몬이 다시 보낸 `/end`는 '모르는 기기 세션'으로 `200`을 받습니다. 세션은 녹음 중으로 남았다가 다음 기기 세션이 시작될 때 `interrupted`로 닫힙니다. T19 '수신 경로'의 `503` 규칙과 다릅니다.
- web-app PR #1 `apps/server/src/device/convert.ts:57`: 빈 final을 버립니다. AI 파트는 'partial 지움'으로 처리해 달라고 요청했습니다. 버리면 흐린 partial이 다음 partial이나 final이 올 때까지 화면에 남습니다. 처리 방법은 앱 파트 결정입니다.
- web-app PR #1은 세션 교체 때 앞 세션을 `interrupted`가 아니라 `ended`로 닫고 늦은 final을 30초 동안 더 받습니다. 데몬이 새 세션 통지를 먼저 보내기 때문이고, T19 '수신 경로' 표와 다릅니다. 채택 여부는 앱 파트 결정입니다.
- PR에 의견을 남기는 일은 하지 않았습니다(사용자 확인 전).
