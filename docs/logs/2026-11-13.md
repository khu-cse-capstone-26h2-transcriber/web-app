찾은 문제(기록만):

1. 녹음 중에 브라우저가 열려 있으면 SIGTERM으로 서버가 꺼지지 않습니다. 끊긴 SSE가 같은 keep-alive 연결로 바로 다시 붙고, 종료 중인 서버가 그 구독을 받아 `server.close`가 끝나지 않습니다. 보드에서는 Express가 웹앱을 직접 내보내 생기는 경로입니다. T26·T27 자동 시작 전에 고칠지 정합니다.
2. 핫스팟에서 Mac의 `rubikpi.local` 이름 해석이 5초(브라우저 첫 접속 9.5초) 걸립니다. Mac의 mDNS 조회에 IPv4 주소가 없어 IPv4 응답을 기다립니다.
3. `npm run dev:server`는 `npm`·`tsx`·`esbuild` 프로세스가 함께 돌아 서버 묶음이 약 100 MB를 씁니다(서버 PSS 약 65 MB).

지침서와 다르게 한 점: 녹음 #1 종료가 1분 20초 늦음, 내려받기는 버튼 대신 curl(브라우저 패널에서 파일 저장은 사용자 확인이 필요), 배너는 SIGKILL로 확인, 응답 시간은 `--resolve`로 이름 해석을 뺌, 지침서의 `pkill` 패턴과 측정 스크립트를 고침.
