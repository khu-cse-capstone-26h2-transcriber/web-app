# D4 협의 질문 목록 — STT 연동 방식

2026-10-12 · 이광호

D4(STT 호출 방법, 오디오 입력 형식, partial/final 이벤트 형식)를 AI 파트(박지윤), 하드웨어 파트(김범수)와 정할 때 물어볼 것을 질문 문장으로 정리했습니다. 이 합의가 끝나야 T19(합의 문서화)와 T20(실제 STT로 교체)을 시작할 수 있습니다.

- ★ 표시는 T20을 시작하려면 꼭 답이 필요한 질문입니다. 시간이 없으면 ★만 묻습니다.
- '답에 따라 앱에서 달라지는 것'은 왜 묻는지 설명할 때 씁니다.
- 세그먼트는 화면의 한 줄, DB의 한 행이 되는 문장 단위 구간을 뜻합니다.

## 회의 전에 설명할 것

질문하기 전에 앱 파트의 현재 상태를 먼저 보여 주면 이야기가 빨라집니다.

- 서버는 `SttAdapter` 인터페이스만 봅니다. 메서드는 `start(onEvent)`와 `stop()` 둘뿐이고, 지금 구현체는 가짜 STT(mock)입니다. 실제 STT가 정해지면 구현체 하나만 바꿉니다.
- 이벤트 초안은 다섯 필드입니다: `type`(`partial` 또는 `final`), `segmentId`, `text`, `startMs`, `endMs`.
- 화면에는 partial과 final을 모두 보내고, DB에는 final만 저장합니다. DB의 한 행은 `(세션 번호, segmentId)`로 구분합니다.
- `npm run dev:stt`를 실행하면 mock이 내는 이벤트를 볼 수 있습니다. 아래는 그 출력의 일부입니다.

```text
[stt] partial #0 0-200ms 안녕하세요
[stt] partial #0 0-400ms 안녕하세요 오늘
[stt] partial #0 0-600ms 안녕하세요 오늘 회의를
[stt] final   #0 0-800ms 안녕하세요 오늘 회의를 시작하겠습니다
[stt] partial #1 800-1000ms 첫
```

지금 코드에는 아래 세 가지 가정이 들어 있습니다. **합의된 것이 아니라 임시로 둔 것**이므로, 맞는지부터 확인합니다.

| 가정 | 코드에서의 모습 | 확인할 질문 |
| --- | --- | --- |
| 서버는 오디오를 다루지 않는다 | `SttAdapter.start`가 오디오를 받지 않음 | D1 |
| STT는 주소 하나로 닿는다 | 환경변수 `STT_URL` (예시 값 `http://localhost:9000`) | A1, B1~B3 |
| 이벤트는 다섯 필드이고 partial의 `text`는 누적이다 | `packages/shared`의 `SttEvent` | E1, E2 |

## 답에 따라 앱에서 크게 바뀌는 것

회의 중에 아래 답이 나오면 앱 쪽 작업량이 달라지므로 그 자리에서 일정에 미치는 영향을 함께 이야기합니다.

| 나온 답 | 앱에서 바뀌는 것 |
| --- | --- |
| 서버가 오디오를 받아 STT에 넘겨야 한다 | `SttAdapter.start`에 오디오 인자를 추가하고, 서버에 오디오를 받는 경로를 만들어야 합니다. 가장 큰 변경입니다 |
| partial을 낼 수 없다 | 이벤트는 final만 쓰고, 실시간 화면은 세그먼트 단위로만 바뀝니다 |
| partial이 추가분으로 온다 | 어댑터에서 이어 붙여 누적 텍스트로 바꿉니다 |
| 세그먼트 번호를 줄 수 없다 | 어댑터가 final마다 번호를 붙입니다 |
| 시각을 줄 수 없다 | 서버가 받은 시각으로 채우거나, `segments`의 `start_ms`, `end_ms`를 비울 수 있게 마이그레이션을 추가합니다 |
| 녹음을 물리 버튼으로 시작한다 | 서버가 시작 알림을 받아 세션을 만드는 경로를 추가합니다 |
| 화자, 신뢰도, 언어를 추가한다 | `SttEvent`에 필드를, `segments`에 컬럼을 더하는 마이그레이션을 추가합니다 |
