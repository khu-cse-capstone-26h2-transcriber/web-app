# [T43] 웹 버튼을 주 제어로(물리 버튼 없는 시연) — 지침서

2026-11-25 · 이광호

## 목표

시연 때까지 기기에 물리 버튼이 없을 수 있습니다. 버튼이 없어도 웹(휴대폰·노트북 브라우저)의 '녹음 시작'·'녹음 종료'만으로 시연할 수 있게 화면을 바꿉니다. 버튼이 생기면 코드를 고치지 않고 서버 `.env` 한 줄로 지금 화면(기기 버튼이 주, 웹 버튼은 보조)으로 돌아갑니다. 끝나면 아래가 됩니다.

1. 서버 `.env`의 `DEVICE_BUTTON`이 비었거나 `0`이면(기본) 웹 버튼이 주 제어입니다. 대기 화면에 크고 채운 빨간 '녹음 시작' 버튼이 있고, 녹음 중에는 크고 채운 '녹음 종료' 버튼이 있습니다. 안내 문구는 화면의 버튼을 가리킵니다.
2. `DEVICE_BUTTON=1`이면 지금 화면 그대로입니다(작은 웹 버튼, '기기의 버튼을 누르면…', '이 화면의 버튼은 보조용입니다').
3. 서버가 기기(`ctrl.sock`)에 닿지 못하면 화면에는 소켓 경로 없이 '기기에 연결하지 못했습니다…'만 보이고, 자세한 이유는 서버 기록에 남습니다. 기기가 명령을 거절했을 때도 서버 기록에 남습니다.

## 배경과 전제, 범위

- 웹 버튼으로 기기 녹음을 켜고 끄는 길은 이미 있습니다. `DEVICE_CTRL_SOCKET`이 있으면 서버가 데몬 `ctrl.sock`에 `session start`·`session stop`을 보냅니다(web-app PR #2, `apps/server/src/device/control.ts`). T27(2026-11-18) 보드 시험 2(웹 버튼만)·3(기기 명령과 섞어서)·4(데몬 꺼짐)를 통과했습니다. 물리 버튼이 보낼 명령도 같아서, 버튼이 생겨도 서버는 고칠 것이 없습니다.
- 바뀌는 것은 2026-10-20 결정('녹음의 주 제어는 기기 물리 버튼, 웹 버튼은 보조')과 2026-11-19 디자인 결정('작은 웹 버튼')입니다. 2026-11-25 사용자 결정으로, 물리 버튼이 없다고 보고 웹 버튼을 주 제어로 하되 버튼이 생기면 되돌릴 수 있게 둡니다.
- '중단'은 '종료'와 같습니다(2026-11-25 사용자 결정). 녹음을 끝내고 히스토리에 저장합니다. 일시정지는 데몬에 명령이 없어 하지 않습니다.
- 보드에서 데몬은 대기 상태(`--idle` 또는 `[session] autostart = false`)로 켜야 합니다. 저장소 기본값은 켜자마자 녹음(`autostart = true`)이고, 서비스 파일에도 `--idle`이 없습니다(로컬 사본 `audio-stack` `a775c37` 기준). 이것은 앱 코드가 아니라 보드 설정이라 T35(서비스 설치)에서 합니다. 버튼이 있든 없든 똑같이 필요합니다.

- 하는 것: `DEVICE_BUTTON` 환경변수, `/health` 응답에 `deviceButton`, `Health` 타입을 `packages/shared`로 옮김, 틀(Layout)이 그 값을 녹음 화면에 넘김, 녹음 화면의 대기 문구·시작 버튼·종료 버튼·아래 안내 줄, 기기 명령 실패 문구와 서버 기록, `.env.example`·`project-overview.md`.
- 하지 않는 것: 일시정지, 물리 버튼 프로그램(T36), 데몬·엔진·서버 서비스 설치와 데몬 대기 상태 설정(T35), 엔진 `BUSY` 답을 `503`으로(T37), 히스토리 화면, 보드 시험(보드는 T35에서), 단위 테스트(핵심 로직이 아님), `git push`.

- 확인하지 못한 것: 보드(실제 `audiostackd`)에서 웹 버튼만으로 시작·종료하는 것은 이번에 하지 않았습니다(T27 시험 2에서 확인, 이번 변경은 성공 길에 기록 한 줄만 더함). 기기 거절(`502`) 기록은 실제로 띄우지 않았습니다. 실제 휴대폰에서는 열어 보지 않았습니다.
- 확인 방법 메모: `npm run start:server`는 `apps/server/dist`를 쓰므로 서버 코드를 고친 뒤에는 `npm run build:server`를 먼저 해야 합니다(처음에 옛 빌드로 떠서 다시 함).
