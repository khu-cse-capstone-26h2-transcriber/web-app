# [T26] Rubik Pi에서 실제 모델과 서버 연동(WAV 입력) — 지침서

2026-11-15 · 이광호 (2026-11-16 AI-1~7 답과 사용자 결정 2개 반영, 같은 날 학교에서 하도록 네트워크를 바꿈: 1-1단계)

## 목표

보드(Rubik Pi 3)에서 AI 파트의 엔진을 NPU로 돌리고, 그 결과가 같은 보드의 앱 서버를 거쳐 웹 화면·DB·히스토리까지 이어지는지 확인합니다. 마이크 대신 WAV를 넣습니다. 끝나면 아래가 모두 됩니다.

1. 보드에 엔진(`stt-engine`), 모델(Release `v0.1`), QNN 2.50 런타임, `audio-stack`의 `feed_wav.py`가 있고, 엔진이 빌드되어 NPU에서 돕니다.
2. 앱 서버가 T33 방식(`node … apps/server/dist/index.js`)의 systemd 서비스로 돌고, 앱 서버와 PostgreSQL은 작은 코어(0~3), 엔진은 큰 코어에서 돕니다.
3. `feed_wav.py`로 넣은 WAV가 엔진 → 서버 `/api/device/sessions` → Mac 브라우저의 실시간 자막 → DB → 히스토리 → txt·md까지 이어집니다.
4. final 지연, CER, 세 프로그램(앱 서버, PostgreSQL, 엔진)을 함께 돌릴 때의 메모리·CPU가 기록되어 있습니다(D8 판단 근거). 엔진만 돌릴 때의 값도 함께 있습니다.
5. 앞선 작업에서 T26으로 넘긴 확인(T32 SIGTERM, T33 보드 실행 등)의 결과가 기록되어 있습니다.

## 준비물

- 보드와 전원 어댑터, Mac, 핫스팟을 켤 휴대폰(T30에서 보드가 붙었던 핫스팟), 학교 와이파이 계정과 학교 안내의 접속 설정값(EAP 방식 등). 학교 계정 비밀번호는 사용자가 직접 입력합니다.
- 핫스팟에서는 Mac이 IPv6로만 접속하고 `rubikpi.local` 해석에 5초가 걸립니다(T30, T21 '찾은 문제'). `ssh rubikpi`는 그대로 되고, 브라우저와 `curl`의 `<보드 IP>` 자리에는 `rubikpi.local`이나 `[<보드 IPv6>]`를 씁니다.
  - 2026-11-16 학교에서는 `rubikpi.local`이 아예 풀리지 않았습니다. `ping6 ff02::1%en0`로 핫스팟의 기기를 찾아 보드의 링크 로컬 IPv6를 Mac `~/Desktop/stt-lab/t26/ssh_hotspot.conf`(`HostKeyAlias rubikpi.local`, 나머지는 `~/.ssh/config`)에 넣고 `ssh -F ~/Desktop/stt-lab/t26/ssh_hotspot.conf rubikpi`로 접속했습니다. 아래 `ssh rubikpi`는 그날 이 형태로 씁니다. 학교 와이파이용은 같은 폴더 `ssh_khu.conf`.
  - 아이폰 핫스팟은 **설정 → 개인용 핫스팟 화면이 열려 있을 때만** 보드가 다시 찾았습니다(2026-11-16, 1-1단계 3). 보드가 핫스팟으로 돌아오거나 재부팅할 때는 이 화면을 열어 두고 휴대폰 화면이 꺼지지 않게 합니다.
- 학교 와이파이에서는 `.local`이 되는지 모릅니다. 그때 `ssh rubikpi`·`scp … rubikpi:`에는 `-o HostName=<보드 IP> -o HostKeyAlias=rubikpi.local`을 붙여 씁니다(T21 방식). 보드 IP는 문서에 적지 않습니다.
- 확인: `ssh -o BatchMode=yes rubikpi true; echo $?`가 `0`.
- Mac: `gh` 로그인(모델 받기), `~/Desktop/stt-lab`의 `stt-engine`(지금 `c8f5bd3`, 1단계에서 `d87d229` 이후로 받아 옴)·`samples/`·`t29/cer.py`.
- QNN SDK 묶음 `qnn250_bundle.tar.gz`(AI-1, 지금 Mac `~/Downloads`에 있음). SHA-256 `6420c7031f56eda0feb1120d01425143710eeec9c72ba066633d3f225947887a`.

```python
gap = b"\x00\x00" * 16000  # 1초 무음
with wave.open(str(lab / "t26/zeroth100_long.wav"), "wb") as out:

            assert (src.getnchannels(), src.getsampwidth(), src.getframerate()) == (1, 2, 16000), name

print(len(rows), "files")
```

```bash
#!/bin/bash
# T26: 보드를 학교 와이파이로 잠깐 옮겨 IP·인터넷·시계를 적고, 정한 시간 뒤 핫스팟으로 되돌린다. root로 실행

LOG=/home/ubuntu/t26/net-$(date +%H%M%S).log

  echo "stay ${STAY}s"
  sleep "$STAY"
fi
echo "back $(date +%T)"

rc=1
for _ in $(seq 10); do
```

```bash
#!/bin/bash
# T26: feed_wav.py(데몬 대신)와 엔진(run_engine.sh, NPU)을 함께 돌리고 로그를 ~/t26/<label>-feed.log, -engine.log에 남긴다.
#   bash ~/t26/run_feed.sh <label> <wav> <backend:1|0> [엔진 추가 옵션...]
# 줄마다 앞에 epoch 초(소수 3자리)를 붙인다. 끝나면 두 로그 끝에 '[exit N]'. 엔진 환경변수(PARTIAL 등)는 앞에 붙여 넘긴다.
set -u
LABEL=$1; WAV=$2; BACKEND=$3; shift 3
SOCK=/tmp/astk/engine.sock; OUT=$HOME/t26
TS() { perl -MTime::HiRes=time -ne 'BEGIN{$|=1} printf "%.3f %s", time, $_'; }
BK=()
[ "$BACKEND" = 1 ] && BK=(--backend-url http://127.0.0.1:3000 --backend-prefix /api/device/sessions)
rm -f "$SOCK"
( python3 -u ~/audio-stack/tools/feed_wav.py "$WAV" --socket "$SOCK" ${BK[@]+"${BK[@]}"}; echo "[exit $?]" ) 2>&1 | TS > "$OUT/$LABEL-feed.log" &
for _ in $(seq 50); do [ -S "$SOCK" ] && break; sleep 0.1; done
perl -MTime::HiRes=time -e 'printf "%.3f engine launch\n", time' > "$OUT/$LABEL-engine.log"
( ASTK_ENGINE_SOCKET="$SOCK" PYTHONUNBUFFERED=1 sh ~/rubikpi/runner/run_engine.sh --once "$@"; echo "[exit $?]" ) 2>&1 | TS >> "$OUT/$LABEL-engine.log" &

```

`~/t26/sample.sh`는 T21 `sample.sh`에 엔진·`feed_wav.py`·온도를 더하고 간격을 인자로 받게 한 것입니다.

```bash
#!/usr/bin/env bash
# T26 실측: 일정 간격으로 앱 서버·PostgreSQL·엔진·feed_wav의 메모리(PSS)와 누적 CPU 시간, 시스템 메모리, 가장 높은 온도를 적는다. sudo로 실행
# 사용: sudo bash ~/t26/sample.sh <횟수> <간격 초> <출력 파일>
n=${1:-20}; gap=${2:-60}; out=${3:-/home/ubuntu/t26/samples.txt}
tick=$(getconf CLK_TCK)
# 주어진 프로세스들의 PSS 합(kB)과 누적 CPU 시간 합(초). 프로세스가 없으면 "0 0.00"
sum() {
  local p pss=0 cpu=0
  for p in "$@"; do
    pss=$((pss + $(awk '/^Pss:/ {print $2}' /proc/$p/smaps_rollup 2>/dev/null || echo 0)))
    cpu=$((cpu + $(awk '{print $14+$15}' /proc/$p/stat 2>/dev/null || echo 0)))
  done
  awk -v a="$pss" -v c="$cpu" -v t="$tick" 'BEGIN {printf "%d %.2f", a, c/t}'
}
echo "time srv_pss_kb srv_cpu_s pg_pss_kb pg_cpu_s eng_pss_kb eng_cpu_s feed_pss_kb feed_cpu_s mem_used_mb mem_avail_mb temp_max_c" | tee "$out"
for i in $(seq 1 "$n"); do
  srv=$(ss -ltnpH 'sport = :3000' | grep -o 'pid=[0-9]*' | head -1 | cut -d= -f2)
  m=$(free -m | awk '/^Mem:/ {print $3, $7}')
  t=$(cat /sys/class/thermal/thermal_zone*/temp 2>/dev/null | sort -n | tail -1 | awk '{printf "%.1f", $1/1000}')
  echo "$(date +%T) $(sum $srv) $(sum $(pgrep -u postgres)) $(sum $(pgrep -f 'board_stream.py|whisper_npu')) $(sum $(pgrep -f feed_wav.py)) $m ${t:--}" | tee -a "$out"
  [ "$i" -lt "$n" ] && sleep "$gap"
done
```

- 1분 사이 CPU 사용률은 `(다음 CPU 시간 − 이번 CPU 시간) / 간격 × 100`(%)입니다. 코어 하나를 다 쓰면 100%입니다.

### 9단계. systemd로 끄기 (T32 보드 확인)

1. 브라우저를 녹음 화면에 둡니다. `ssh rubikpi 'bash ~/t26/run_feed.sh s4-stop ~/t26/demo_long.wav 1'`을 백그라운드로 시작합니다.
2. 자막이 30초쯤 흐르면 `ssh rubikpi 'date +%T.%N; sudo systemctl stop transcriber-server; date +%T.%N; systemctl is-active transcriber-server'`.
3. `journalctl -u transcriber-server -n 10 --no-pager -o cat`으로 종료 순서를 봅니다. 브라우저 화면(끊김 배너 또는 상세)을 적습니다.
4. `feed_wav.py`가 끝날 때까지 기다린 뒤(서버가 없어 POST 실패가 찍힘) 서버를 다시 켭니다: `sudo systemctl start transcriber-server`. 이어서 그 세션의 상태와 행 수를 psql로 봅니다.

- 확인: 2의 `systemctl stop`이 5초 안에 끝나고 `inactive`. 기록에 `SIGTERM 받음` → `#N 중단 (서버 종료)` → `종료 완료`. 세션 `interrupted`, 행 수 = 기록의 `저장 N개`. 다시 켤 때 `녹음 중으로 남아 있던 세션을 중단 처리했습니다` 줄이 없습니다. 브라우저가 끊김 배너 뒤 서버가 돌아오면 배너가 사라집니다.
