# [T26] Rubik Pi에서 실제 모델과 서버 연동(WAV 입력) — 지침서

2026-11-15 · 이광호 (2026-11-16 AI-1~7 답과 사용자 결정 2개 반영)

## 목표

보드(Rubik Pi 3)에서 AI 파트의 엔진을 NPU로 돌리고, 그 결과가 같은 보드의 앱 서버를 거쳐 웹 화면·DB·히스토리까지 이어지는지 확인합니다. 마이크 대신 WAV를 넣습니다. 끝나면 아래가 모두 됩니다.

1. 보드에 엔진(`stt-engine`), 모델(Release `v0.1`), QNN 2.50 런타임, `audio-stack`의 `feed_wav.py`가 있고, 엔진이 빌드되어 NPU에서 돕니다.
2. 앱 서버가 T33 방식(`node … apps/server/dist/index.js`)의 systemd 서비스로 돌고, 앱 서버와 PostgreSQL은 작은 코어(0~3), 엔진은 큰 코어에서 돕니다.
3. `feed_wav.py`로 넣은 WAV가 엔진 → 서버 `/api/device/sessions` → Mac 브라우저의 실시간 자막 → DB → 히스토리 → txt·md까지 이어집니다.
4. final 지연, CER, 세 프로그램(앱 서버, PostgreSQL, 엔진)을 함께 돌릴 때의 메모리·CPU가 기록되어 있습니다(D8 판단 근거). 엔진만 돌릴 때의 값도 함께 있습니다.
5. 앞선 작업에서 T26으로 넘긴 확인(T32 SIGTERM, T33 보드 실행 등)의 결과가 기록되어 있습니다.

## 진행 순서

모든 명령은 Claude가 Mac에서 실행합니다. 보드 명령은 `ssh rubikpi '…'`로 보냅니다. 비대화형 SSH에서는 nvm을 읽지 않으므로 Node 명령 앞에 `source ~/.nvm/nvm.sh`를 붙입니다. 1~3단계(설치)와 4~9단계(시험)는 따로 앉아서 해도 됩니다.

### 1단계. Mac에서 보낼 것 만들기

```bash
mkdir -p ~/Desktop/stt-lab/bins ~/Desktop/stt-lab/t26
cd ~/Desktop/stt-lab/bins && gh release download v0.1 -R khu-cse-capstone-26h2-transcriber/stt-engine \
  -p enc_10s.bin -p dec_10s.bin -p SHA256SUMS --skip-existing && shasum -a 256 -c --ignore-missing SHA256SUMS
git -C ~/Desktop/stt-lab/stt-engine pull --ff-only && git -C ~/Desktop/stt-lab/stt-engine log -1 --format='%h %ad' --date=short
git -C ~/Desktop/stt-lab/stt-engine bundle create "$TMPDIR/stt-engine.bundle" main
cd ~/Desktop/speech_transcriber && git bundle create "$TMPDIR/web-app-main.bundle" main && git rev-parse --short main
```

- 확인: `enc_10s.bin: OK`, `dec_10s.bin: OK`. `stt-engine`은 `d87d229`(2026-11-15, 잡음 옵션 기본 켬)이거나 그 뒤여야 합니다. `d87d229`보다 더 바뀌었으면 바뀐 점(README '설치'·'실행')을 읽고 이 지침서와 다르면 멈춰 사용자에게 알립니다.
- 확인: `samples/fleurs_ko_30s.txt` 첫 줄이 `수소 이온은 전자가 벗겨져 나간 양성자이다`로 끝납니다(AI-6, `3561128`).

QNN 묶음(AI-1)을 확인하고 풉니다. 묶음 안에 `qnn250/`이 들어 있어 `~/Desktop/stt-lab`에 풀면 바로 아래 모양이 됩니다.

```bash
shasum -a 256 ~/Downloads/qnn250_bundle.tar.gz
tar -xzf ~/Downloads/qnn250_bundle.tar.gz -C ~/Desktop/stt-lab
cat ~/Desktop/stt-lab/qnn250/README.txt; grep BUILD_ID ~/Desktop/stt-lab/qnn250/include/QnnSdkBuildId.h
ls ~/Desktop/stt-lab/qnn250/sdk250/gcc11.2/lib ~/Desktop/stt-lab/qnn250/sdk250/dsp; du -sh ~/Desktop/stt-lab/qnn250/*
```

```text
qnn250/
├─ README.txt       ← 묶음 사용법(팀 내부용)
├─ include/         ← SDK의 include/QNN/*.h가 한 단계 올라온 것 (QnnInterface.h, HTP/, System/ …, 2.8 MB)
└─ sdk250/          ← 132 MB
   ├─ gcc11.2/lib/  ← SDK의 lib/aarch64-oe-linux-gcc11.2 라이브러리 7개 (libQnnHtp.so, libQnnSystem.so …)
   ├─ gcc11.2/bin/  ← QNN 도구 4개 (qnn-net-run, qnn-platform-validator …, 엔진은 쓰지 않음)
   └─ dsp/          ← SDK의 lib/hexagon-v68/unsigned 중 3개 (libQnnHtpV68.so, libQnnHtpV68Skel.so, libCalculator_skel.so)
```

- 확인: SHA-256이 '준비물'의 값과 같습니다. 빌드 ID `v2.50.0.260828221209`. `lib` 7개, `dsp` 3개.
- `stt-engine` README는 런타임 출처를 `lib/aarch64-ubuntu-gcc11.2`로 적지만 묶음은 `aarch64-oe-linux-gcc11.2`에서 가져왔습니다. AI 파트가 실제로 쓴 묶음이라 그대로 씁니다. 4단계에서 라이브러리를 읽지 못하면 이 차이를 함께 박지윤에게 묻습니다.

```python
"""T26: zeroth 테스트 100개를 1초 무음을 넣어 이은 WAV와 정답 파일을 만든다(16 kHz 모노 16bit).
  python3 ~/Desktop/stt-lab/t26/make_zeroth_long.py"""
import pathlib
import wave

lab = pathlib.Path(__file__).resolve().parent.parent
rows = [line.split("\t") for line in (lab / "samples/refs.tsv").read_text(encoding="utf-8").splitlines() if line.strip()]
gap = b"\x00\x00" * 16000  # 1초 무음
with wave.open(str(lab / "t26/zeroth100_long.wav"), "wb") as out:
    out.setnchannels(1); out.setsampwidth(2); out.setframerate(16000)
    for i, (name, _, _) in enumerate(rows):
        with wave.open(str(lab / "samples" / name)) as src:
            assert (src.getnchannels(), src.getsampwidth(), src.getframerate()) == (1, 2, 16000), name
            if i:
                out.writeframes(gap)
            out.writeframes(src.readframes(src.getnframes()))
(lab / "t26/zeroth100_long.ref.txt").write_text("\n".join(text for _, _, text in rows) + "\n", encoding="utf-8")
print(len(rows), "files")
```

#!/bin/bash
# T26: feed_wav.py(데몬 대신)와 엔진(run_engine.sh, NPU)을 함께 돌리고 로그를 ~/t26/<label>-feed.log, -engine.log에 남긴다.

# 줄마다 앞에 epoch 초(소수 3자리)를 붙인다. 끝나면 두 로그 끝에 '[exit N]'. 엔진 환경변수(PARTIAL 등)는 앞에 붙여 넘긴다.

SOCK=/tmp/astk/engine.sock; OUT=$HOME/t26
TS() { perl -MTime::HiRes=time -ne 'BEGIN{$|=1} printf "%.3f %s", time, $_'; }
BK=()
[ "$BACKEND" = 1 ] && BK=(--backend-url http://127.0.0.1:3000 --backend-prefix /api/device/sessions)
rm -f "$SOCK"
( python3 -u ~/audio-stack/tools/feed_wav.py "$WAV" --socket "$SOCK" ${BK[@]+"${BK[@]}"}; echo "[exit $?]" ) 2>&1 | TS > "$OUT/$LABEL-feed.log" &

`~/t26/sample.sh`는 T21 `sample.sh`에 엔진·`feed_wav.py`·온도를 더하고 간격을 인자로 받게 한 것입니다.

```bash
#!/usr/bin/env bash
# T26 실측: 일정 간격으로 앱 서버·PostgreSQL·엔진·feed_wav의 메모리(PSS)와 누적 CPU 시간, 시스템 메모리, 가장 높은 온도를 적는다. sudo로 실행
# 사용: sudo bash ~/t26/sample.sh <횟수> <간격 초> <출력 파일>
n=${1:-20}; gap=${2:-60}; out=${3:-/home/ubuntu/t26/samples.txt}
tick=$(getconf CLK_TCK)
# 주어진 프로세스들의 PSS 합(kB)과 누적 CPU 시간 합(초). 프로세스가 없으면 "0 0.00"
sum() {
  local p pss=0 cpu=0
  for p in "$@"; do
    pss=$((pss + $(awk '/^Pss:/ {print $2}' /proc/$p/smaps_rollup 2>/dev/null || echo 0)))
    cpu=$((cpu + $(awk '{print $14+$15}' /proc/$p/stat 2>/dev/null || echo 0)))
  done
  awk -v a="$pss" -v c="$cpu" -v t="$tick" 'BEGIN {printf "%d %.2f", a, c/t}'
}
echo "time srv_pss_kb srv_cpu_s pg_pss_kb pg_cpu_s eng_pss_kb eng_cpu_s feed_pss_kb feed_cpu_s mem_used_mb mem_avail_mb temp_max_c" | tee "$out"
for i in $(seq 1 "$n"); do
  srv=$(ss -ltnpH 'sport = :3000' | grep -o 'pid=[0-9]*' | head -1 | cut -d= -f2)
  m=$(free -m | awk '/^Mem:/ {print $3, $7}')
  t=$(cat /sys/class/thermal/thermal_zone*/temp 2>/dev/null | sort -n | tail -1 | awk '{printf "%.1f", $1/1000}')
  echo "$(date +%T) $(sum $srv) $(sum $(pgrep -u postgres)) $(sum $(pgrep -f 'board_stream.py|whisper_npu')) $(sum $(pgrep -f feed_wav.py)) $m ${t:--}" | tee -a "$out"
  [ "$i" -lt "$n" ] && sleep "$gap"
done
```

- 1분 사이 CPU 사용률은 `(다음 CPU 시간 − 이번 CPU 시간) / 간격 × 100`(%)입니다. 코어 하나를 다 쓰면 100%입니다.

### 9단계. systemd로 끄기 (T32 보드 확인)

1. 브라우저를 녹음 화면에 둡니다. `ssh rubikpi 'bash ~/t26/run_feed.sh s4-stop ~/t26/demo_long.wav 1'`을 백그라운드로 시작합니다.
2. 자막이 30초쯤 흐르면 `ssh rubikpi 'date +%T.%N; sudo systemctl stop transcriber-server; date +%T.%N; systemctl is-active transcriber-server'`.
3. `journalctl -u transcriber-server -n 10 --no-pager -o cat`으로 종료 순서를 봅니다. 브라우저 화면(끊김 배너 또는 상세)을 적습니다.
4. `feed_wav.py`가 끝날 때까지 기다린 뒤(서버가 없어 POST 실패가 찍힘) 서버를 다시 켭니다: `sudo systemctl start transcriber-server`. 이어서 그 세션의 상태와 행 수를 psql로 봅니다.

- 확인: 2의 `systemctl stop`이 5초 안에 끝나고 `inactive`. 기록에 `SIGTERM 받음` → `#N 중단 (서버 종료)` → `종료 완료`. 세션 `interrupted`, 행 수 = 기록의 `저장 N개`. 다시 켤 때 `녹음 중으로 남아 있던 세션을 중단 처리했습니다` 줄이 없습니다. 브라우저가 끊김 배너 뒤 서버가 돌아오면 배너가 사라집니다.

### 10단계. 마무리

```bash
ssh rubikpi 'sudo systemctl stop transcriber-server; systemctl is-active transcriber-server; systemctl is-enabled transcriber-server'
ssh rubikpi 'sudo systemctl set-property --runtime postgresql@16-main.service AllowedCPUs=; systemctl is-active postgresql'
ssh rubikpi 'sudo sh ~/rubikpi/runner/set_governor.sh schedutil; free -h; df -h /; sudo du -sh /var/lib/postgresql ~/rubikpi; uptime'
mkdir -p ~/Desktop/stt-lab/t26/board && scp 'rubikpi:t26/*.log' 'rubikpi:t26/samples-*.txt' ~/Desktop/stt-lab/t26/board/
```

- 확인: 서버 `inactive`·`disabled`, PostgreSQL `active`, 클럭 정책 `schedutil`. 로그와 측정 파일이 Mac에 있습니다. 측정 파일과 로그는 저장소에 커밋하지 않습니다.
- 보드를 끌지는 사용자가 정합니다. 끌 때는 `sudo systemctl poweroff`(11-14와 같음).

## 덧붙이는 단계 (HW-1 답이 온 뒤, 완료 기준 밖)

실제 `audiostackd`를 거치는 시험입니다(`audio-stack` `docs/UBUNTU-INPUT.md`의 `snd-aloop`). HW-1에서 김범수가 보드 설정 파일 변경에 동의하면 합니다.

- `~/audio-stack`에서 데몬을 빌드하고(`scripts/build.sh`), `config/loopback.conf`에 `[backend]` 세 경로(`/api/device/sessions`, `…/{session}/transcripts`, `…/{session}/end`)를 넣어 `scripts/feed_wav_loopback.sh`로 띄웁니다. 경로를 넣지 않으면 데몬 내장 기본값(`/api/sessions`)으로 보내 앱 서버의 mock 녹음이 켜집니다.
- 서버를 다시 켠 뒤에는 `ctrl.sock`에 `session rotate`를 보내 새 세션으로 시작합니다(B 10). 엔진 소켓은 `/run/audiostack/engine.sock`이고, 엔진을 돌리는 사용자가 `audio` 그룹이어야 합니다.
- 보는 것: 데몬 재전송·대기열, 세션 교체 때 늦은 결과(T19 앱 결정 '앞 세션은 `ended`, 늦은 final 30초 저장'), `feed_wav.py` 경로와의 지연 차이. 지침서를 따로 쓸지는 그때 정합니다.
