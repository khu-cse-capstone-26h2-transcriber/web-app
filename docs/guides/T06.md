# [T06] 세션 시작/종료 API와 상태 전이 — 지침서

2026-10-13 · 이광호

## 목표

`POST /api/sessions`로 녹음 세션을 시작하면 DB에 세션이 생기고 mock STT가 켜집니다. `POST /api/sessions/:id/stop`으로 끝내면 STT가 꺼지고 세션이 닫힙니다. `GET /api/sessions/active`로 지금 녹음 중인 세션을 알 수 있습니다. 서버가 꺼졌다 켜져도 녹음 중으로 남는 세션이 없습니다. T07(SSE)과 T08(세그먼트 저장)은 이 세션이 받는 이벤트를 가져가는 방식으로 만듭니다.

## 배경과 전제, 범위

선행 작업은 T04(서버 뼈대)와 T05(STT 어댑터)이고 모두 끝났습니다. 실행 전에 Docker Desktop이 켜져 있고 `docker compose up -d`로 DB가 떠 있어야 합니다.

이 지침서는 구현과 같은 세션에서 썼습니다. 그래서 T04 지침서와 달리 코드 전문을 싣지 않았습니다. 코드는 저장소의 파일(커밋 `5ea62d5`)이 기준이고, 여기에는 결정과 동작, 확인 방법을 적습니다.

- 하는 것: 마이그레이션 `002`(`status` 컬럼), 공용 `Session` 타입, `sessions` 테이블 SQL, 진행 중인 세션과 상태 전이를 맡는 `SessionManager`, 라우트 세 개, 서버를 켤 때의 정리와 끌 때의 중단 처리.
- 하지 않는 것: SSE(T07), 세그먼트 저장(T08), 히스토리 목록·상세(T10), 환경변수로 mock과 실제 STT를 고르는 팩토리(T20), 단위 테스트(T17), CORS(T12).
- 협의가 필요해 가정하지 않는 것 (D4): 물리 버튼으로 녹음을 시작하는 경로(하드웨어 파트 김범수), 정지 뒤 마지막 final을 기다리는 신호와 STT가 세션 번호를 알아야 하는지(AI 파트 박지윤). T06은 웹앱에서 시작하는 경로만 mock으로 만듭니다.

## 세션 상태

DB의 `sessions.status`에 남는 값입니다. `recording`인 세션만 `ended_at`이 비어 있습니다.

| 상태 | 뜻 |
| --- | --- |
| `recording` | 녹음 중 |
| `ended` | 사용자가 종료함 |
| `interrupted` | 사용자가 종료하지 않았는데 끊김 |

| 전이 | 일어나는 때 | `ended_at`에 들어가는 시각 |
| --- | --- | --- |
| (없음) → `recording` | 시작 요청 | 비어 있음 |
| `recording` → `ended` | 종료 요청 | 종료한 시각 |
| `recording` → `interrupted` | 녹음 중에 서버를 정상 종료(Ctrl+C, `SIGTERM`) | 서버를 끈 시각 |
| `recording` → `interrupted` | 서버가 강제로 꺼져 닫지 못한 세션을, 서버를 다시 켤 때 정리 | 다시 켠 시각 (실제로 끊긴 시각보다 늦음) |
| `recording` → `interrupted` | 세션을 만든 직후 STT를 켜지 못함 | 그 시각 |

서버는 진행 중인 세션을 메모리에도 들고 있습니다. `SessionManager`의 상태는 `idle → starting → recording → stopping → idle`로 움직이고, `idle`이 아닐 때 온 시작 요청은 409입니다. 시작 요청 두 개가 동시에 와도 하나만 성공합니다.

## 응답 형식

성공 응답은 `{ "session": … }`으로 감쌉니다. 에러 응답은 T04의 `{ "error": { "code", "message" } }`를 그대로 씁니다.

| 요청 | 상태 코드 | 본문 |
| --- | --- | --- |
| `POST /api/sessions` | 201 | `{"session":{"id":1,"status":"recording","startedAt":"…","endedAt":null}}` |
| `POST /api/sessions`, 진행 중인 세션 있음 | 409 | `code`가 `SESSION_ALREADY_ACTIVE` |
| `GET /api/sessions/active`, 녹음 중 | 200 | `{"session":{…}}` |
| `GET /api/sessions/active`, 녹음 중이 아님 | 200 | `{"session":null}` |
| `POST /api/sessions/:id/stop` | 200 | `{"session":{…,"status":"ended","endedAt":"…"}}` |
| `stop`, 번호가 양의 정수가 아님 | 400 | `code`가 `INVALID_SESSION_ID` |
| `stop`, 없는 번호 | 404 | `code`가 `SESSION_NOT_FOUND` |
| `stop`, 진행 중인 세션이 아님 | 409 | `code`가 `SESSION_NOT_ACTIVE` |
| DB에 연결하지 못함 | 500 | `code`가 `INTERNAL_ERROR` (T04의 공통 처리 그대로) |

`Session`의 필드입니다. 타입은 `packages/shared/src/session.ts`에 있고 서버와 웹이 함께 씁니다.

| 필드 | 타입 | 담는 값 |
| --- | --- | --- |
| `id` | `number` | 서버가 붙이는 세션 번호. 1부터 증가 |
| `status` | `'recording'` \| `'ended'` \| `'interrupted'` | 위 '세션 상태' |
| `startedAt` | `string` | 시작 시각 (ISO 8601) |
| `endedAt` | `string` \| `null` | 끝난 시각. 녹음 중이면 `null` |

## 구현 순서

1. DB를 띄우고 `main`에서 새 브랜치를 만듭니다.

    ```bash
    docker compose up -d
    git switch -c feat/t06-session-api
    ```

2. `apps/server/migrations/002_session_status.sql`을 씁니다. 이미 적용한 `001_init.sql`은 고치지 않습니다.

    ```sql
    -- 세션 상태 컬럼을 추가한다.
    -- recording: 녹음 중, ended: 사용자가 종료함, interrupted: 서버가 꺼져서 끊김.
    alter table sessions
      add column status text not null default 'recording'
      constraint sessions_status_check check (status in ('recording', 'ended', 'interrupted'));

    -- 이미 있던 행은 ended_at을 보고 상태를 맞춘다.
    update sessions set status = 'ended' where ended_at is not null;

    -- 녹음 중인 세션만 ended_at이 비어 있다.
    alter table sessions
      add constraint sessions_status_ended_at_check check ((status = 'recording') = (ended_at is null));
    ```

3. `packages/shared/src/session.ts`에 `Session`, `SessionStatus` 타입을 쓰고 `index.ts`에서 내보냅니다.

4. `apps/server/src/sessions/repository.ts`에 SQL 함수 네 개를 씁니다. `pg`는 `bigint`를 문자열로, `timestamptz`를 `Date`로 주므로 여기서 `Session` 모양으로 바꿉니다.

    | 함수 | 하는 일 |
    | --- | --- |
    | `insertSession` | `insert into sessions default values`. `status`의 기본값이 `recording`입니다 |
    | `findSession` | 번호로 한 행을 읽습니다. `stop`에서 404와 409를 구분할 때 씁니다 |
    | `closeSession` | `status = 'recording'`인 행만 `ended` 또는 `interrupted`로 닫습니다. 이미 닫힌 행이면 `undefined` |
    | `interruptOpenSessions` | `recording`으로 남은 행을 모두 `interrupted`로 닫고 번호를 돌려줍니다 |

5. `apps/server/src/sessions/manager.ts`에 `SessionManager`를 씁니다.

    | 메서드 | 하는 일 |
    | --- | --- |
    | `start()` | `idle`이 아니면 409. 남은 세션을 정리하고, 행을 만들고, 어댑터를 새로 만들어 켭니다. 어댑터를 켜지 못하면 방금 만든 행을 `interrupted`로 닫습니다 |
    | `stop(id)` | 진행 중인 세션의 번호가 아니면 DB를 읽어 404 또는 409. 맞으면 어댑터를 먼저 멈추고 행을 `ended`로 닫습니다 |
    | `getActive()` | 메모리에 든 진행 중인 세션. DB를 읽지 않습니다 |
    | `recover()` | `interruptOpenSessions`를 부르고, 닫은 세션이 있으면 로그를 남깁니다 |
    | `shutdown()` | 진행 중인 세션이 있으면 어댑터를 멈추고 `interrupted`로 닫습니다 |

    세션과 이벤트는 서버가 묶습니다. 어댑터를 세션마다 새로 만들고, 그 어댑터가 준 이벤트는 그 세션의 것으로 봅니다. `SttEvent` 초안에는 세션 번호를 넣지 않습니다. T06에서는 받은 이벤트의 개수만 세어 종료 로그에 찍습니다. T07과 T08은 `handleEvent`에서 이벤트를 받아 갑니다.

6. `apps/server/src/sessions/routes.ts`에 `createSessionRouter(sessions)`를 쓰고, `app.ts`에서 `app.use('/api/sessions', …)`로 붙입니다. `/active`는 나중에 더할 `/:id`(T10)보다 앞에 둡니다.

7. `apps/server/src/index.ts`를 고칩니다.
    - `new SessionManager(pool, () => new MockSttAdapter())`를 만들어 `createApp`에 넘깁니다. 실제 STT로 바꿀 때는 이 함수가 만드는 어댑터만 바뀝니다(T20).
    - `listen` 전에 `sessions.recover()`를 부릅니다. 실패해도(DB가 꺼져 있어도) 서버는 띄웁니다.
    - 종료 처리에서 `server.close` 뒤, `pool.end()` 앞에 `sessions.shutdown()`을 부릅니다.

8. 동작을 확인하고 커밋합니다. push와 `main` 병합은 사용자가 따로 지시할 때 합니다.

    ```bash
    npm run db:migrate
    npm run typecheck
    npm run dev:server
    curl -i -X POST localhost:3000/api/sessions
    curl -i localhost:3000/api/sessions/active
    curl -i -X POST localhost:3000/api/sessions/1/stop
    git add -A
    git commit -m "feat: 세션 시작/종료 API와 상태 전이 추가"
    ```

9. 기록을 남깁니다. `docs/logs/`의 그날 일지, `docs/project-overview.md`, 이 지침서의 '결과'를 채웁니다. `TODO.md`는 변경안을 사용자에게 먼저 보고한 뒤 허락을 받고 고칩니다.

## 결정 사항과 남은 질문

- 이미 정한 것: 위 '착수 전 확인'의 다섯 가지, T04의 에러 응답 형식.
- 이 지침서에서 정한 것:
  - **세션과 이벤트를 묶는 일은 서버가 맡습니다.** `SttEvent` 초안은 바꾸지 않았습니다. D4에서 STT가 세션 번호를 알아야 한다고 정해지면 다시 봅니다.
  - **`interrupted`는 정상 종료(Ctrl+C)에도 씁니다.** 사용자가 종료를 누르지 않았는데 끝난 세션은 모두 `interrupted`입니다.
  - **진행 중인지는 서버 메모리가 기준입니다.** `GET /api/sessions/active`는 DB를 읽지 않습니다. 메모리에 진행 중인 세션이 없는데 DB에 `recording`으로 남은 행은 닫지 못한 세션으로 봅니다.
  - **남은 세션 정리는 두 군데서 합니다.** 서버를 켤 때 한 번 하고, 녹음을 시작할 때마다 한 번 더 합니다. 서버를 켤 때 DB가 꺼져 있어 정리하지 못한 경우를 위해서입니다.
  - **종료는 STT를 먼저 멈추고 DB를 닫습니다.** 세션을 닫은 뒤에 이벤트가 오지 않게 하려는 순서입니다. DB를 닫는 데 실패하면 세션은 녹음 중으로 남고, 종료를 다시 요청할 수 있습니다. 이때 STT는 이미 멈춰 있어서 그 사이의 이벤트는 없습니다.
  - **세션 번호는 JSON에서 숫자입니다.** DB의 `bigint`를 `number`로 바꿉니다.
  - **한 번에 하나의 세션만 진행하는 것은 서버 메모리의 상태로 막습니다.** DB에 유일 제약은 두지 않았습니다. 서버 프로세스가 하나라는 전제입니다.
- 아직 정해야 하는 것:
  - DB가 꺼져 있을 때 세션 API는 500(`INTERNAL_ERROR`)을 냅니다. `/health`처럼 503(`DB_UNAVAILABLE`)으로 맞출지는 화면에서 오류를 보여 주는 T13 전에 정합니다.
  - 강제로 꺼진 세션의 `ended_at`은 다시 켠 시각이라 실제보다 늦습니다. T08 이후에는 마지막 세그먼트의 시각으로 보정할 수 있습니다.
  - 정지 뒤 마지막 final을 기다릴지(D4의 C3, AI 파트 박지윤). 정해지면 `stopping` 단계가 길어지고 상태가 늘 수 있습니다.
  - 물리 버튼으로 녹음을 시작하는 경로(D4의 C1, 하드웨어 파트 김범수). 필요하면 서버가 시작 알림을 받아 세션을 만드는 경로를 추가합니다.
