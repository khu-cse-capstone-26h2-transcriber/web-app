# [T41] 다음 멘토링 발표 자료 — 1부: 시연 영상 촬영 — 지침서

2026-11-25 · 이광호

T41은 다음 멘토링 발표 자료(측정값 그래프·표, 시연 영상)입니다. 이 지침서에는 오늘(2026-11-25) 하는 **시연 영상 촬영**만 적습니다. 그래프·표는 나중에 같은 지침서에 2부로 더합니다(사용자 결정).

## 목표

보드(Rubik Pi 3) 한 대에서 실제 마이크(XVF3800) → `audiostackd` → 엔진(NPU) → 앱 서버 → 웹 실시간 자막·히스토리가 이어지는 모습을 영상으로 남깁니다. 2~3명이 1~2분 대화하는 장면을 두 번 찍습니다. 끝나면 아래가 됩니다.

1. 보드 앱이 `main`(`280d9a8`)입니다. 웹 화면은 확정 디자인(T38~T40)이고 웹 버튼이 녹음의 주 제어입니다(T43, `DEVICE_BUTTON` 비움).
2. 2인 대본과 3인 대본으로 녹음한 세션이 하나씩 히스토리에 있고, 각각 `ended`이며 문장이 저장되어 있습니다.
3. 두 세션의 화면 녹화 영상과 txt 파일이 Mac에 있습니다.

## 배경과 전제, 범위

- 2차 멘토링(2026-11-22)에서 발표 자료와 영상을 효과적으로 보여 달라는 의견이 있었습니다(T41).

- 웹 버튼으로 녹음하는 길은 T27 시험 2(2026-11-18)에서 확인했습니다. 웹 버튼이 서버를 거쳐 데몬 `ctrl.sock`에 `session start`·`session stop`을 보냅니다.

- 대본은 STT 특성에 맞춰 썼습니다. 줄이 짧고(대부분 3~5초), 사람마다 1초 쉬고, 겹쳐 말하지 않습니다. 근거: 엔진은 말이 끊긴 곳에서 문장을 나누고 10초에서 강제로 자름(T42 디코더 `dec_10s`), 긴 문장에서 가운데 단어가 빠지는 일(AI-9), 화자 분리는 확장 기능이라 없음.

- 하는 것: 핫스팟에서 보드 찾기와 상태 확인, 보드 앱 갱신(`main`), 데몬(대기 상태)·엔진·서버 켜기, 웹페이지 열기, 리허설, 2인·3인 촬영, 세션 확인과 txt 받기, 정리.
- 하지 않는 것: 서비스 설치와 부팅 자동 시작(T35), RNNoise, 물리 버튼(T36), 보드 DB 정리(시험 녹음은 그대로 둠), 영상 편집, 그래프·표(T41 2부), `git push`.

## 진행 순서

### 0단계. Mac 준비 (5분)

```bash
cd ~/Desktop/speech_transcriber && nvm use && npm run build:web

git bundle create ~/Desktop/stt-lab/t41/web-app-main.bundle main && git bundle verify ~/Desktop/stt-lab/t41/web-app-main.bundle
```

- 확인: 빌드 성공, bundle `is okay`, `web-dist.tgz`가 있음. `main`이 `280d9a8`(또는 그 뒤 기록 커밋).
- `--no-xattrs`가 없으면 보드에서 풀 때 `Ignoring unknown extended header keyword 'LIBARCHIVE.xattr.com.apple.provenance'` 경고가 파일마다 나옵니다(해는 없음, 2026-11-25).

### 1단계. 핫스팟에서 보드 찾기와 상태 확인 (10분)

Mac을 보드와 같은 핫스팟에 붙인 뒤 보드를 찾습니다.

```bash
ipconfig getifaddr en0                          # Mac 주소(아이폰 핫스팟은 보통 172.20.10.x)
ping6 -c 3 ff02::1%en0 | grep -v "$(ipconfig getifaddr en0)"   # 핫스팟의 기기들(IPv6 링크 로컬)
```

- 응답한 주소를 하나씩 `ssh -o BatchMode=yes -o ConnectTimeout=5 -o HostName=<주소>%en0 -F ~/Desktop/stt-lab/t26/ssh_hotspot.conf rubikpi hostname`으로 시험해, 답이 오는 주소를 설정 파일 `HostName`에 넣습니다(`%`는 설정 파일에서 `%%`).

```bash
ssh rubikpi 'mkdir -p ~/t41; uname -r; timedatectl | grep synchronized; nmcli -t -f NAME connection show --active; ip -4 -o addr show wlan0 | awk "{print \$4}"; ip -6 addr show wlan0 | grep "scope global"; lsusb -d 2886:001a; arecord -l | grep -i -E "xvf|card"; systemctl is-active transcriber-server; pgrep -a -f "[a]udiostackd|[b]oard_stream|[w]hisper_npu"; echo "도는 프로그램 위"'
ssh rubikpi 'git -C ~/rubikpi/runner log -1 --format="runner %h"; git -C ~/audio-stack log -1 --format="daemon %h"; git -C ~/web-app log -1 --format="app %h"; git -C ~/web-app status --short | head -3; ls ~/t27/xvf3800.conf ~/audio-stack/build/audiostackd; grep -E "^(DEVICE_CTRL_SOCKET|DEVICE_BUTTON|STT_MODE)=" ~/web-app/.env'
```

- 확인: 시계 `synchronized: yes`(핫스팟이 인터넷에 붙어 있으면 맞춰짐. `no`면 녹음 시작 시각이 틀리게 나오므로 1~2분 기다림). 보드 IPv4와, IPv6 중 `temporary`가 아닌 `mngtmpaddr` 주소(웹페이지 주소에 씀, 4단계). XVF3800이 `lsusb`·`arecord -l`에 보임. 서버 `inactive`, 도는 프로그램 없음. runner `d7da535`, 데몬 `32124c7`, 앱 `40d7e1f`, `git status` 비어 있음. `.env`에 `DEVICE_CTRL_SOCKET=/run/audiostack/ctrl.sock`, `DEVICE_BUTTON` 없음(또는 `0`).
- 시계가 맞지 않거나 XVF3800이 안 보이면 멈추고 적습니다(XVF3800은 다시 꽂아 봄).

### 2단계. 보드 앱 갱신 (10분)

```bash
scp ~/Desktop/stt-lab/t41/web-app-main.bundle ~/Desktop/stt-lab/t41/web-dist.tgz rubikpi:t41/
ssh rubikpi 'cd ~/web-app && git pull -q ~/t41/web-app-main.bundle main && git log -1 --format=%h && git status --short | head -3'

```

- 확인: 앱 `280d9a8`(fast-forward), `git status` 비어 있음(`dist`는 무시됨). `apps/web/dist`에 `index.html`·`assets`. 서버 빌드 성공(`dist/index.js`).
- 서버 빌드가 실패하면 Mac에서 `npm run build:server` 뒤 `scp apps/server/dist/index.js* rubikpi:web-app/apps/server/dist/`로 보냅니다(esbuild가 express·pg만 빼고 묶음).

### 3단계. 실행 (5분)

```bash
ssh rubikpi 'sudo install -d -o ubuntu -g audio -m 0775 /run/audiostack; sudo sh ~/rubikpi/runner/set_governor.sh performance; sudo systemctl set-property --runtime postgresql@16-main.service AllowedCPUs=0-3'
ssh rubikpi 'cd ~/t41 || exit 1; setsid nohup ~/audio-stack/build/audiostackd --config ~/t27/xvf3800.conf --idle > ~/t41/daemon.log 2>&1 < /dev/null & sleep 3; tail -5 ~/t41/daemon.log; ls -l /run/audiostack'
ssh rubikpi 'cd ~/rubikpi/runner || exit 1; setsid nohup sh run_engine.sh > ~/t41/engine.log 2>&1 < /dev/null & sleep 20; tail -3 ~/t41/engine.log; ~/audio-stack/build/astk-ctl status'
ssh rubikpi 'sudo systemctl start transcriber-server && sleep 3; systemctl is-active transcriber-server; journalctl -u transcriber-server -n 8 --no-pager -o cat | grep -E "device|ready|button"; curl -s localhost:3000/health; echo'
```

- 확인: `/run/audiostack`에 `ctrl.sock`·`engine.sock`. 데몬이 대기 상태(녹음하지 않음), 엔진이 붙음(`astk-ctl status`). 서버 `active`, 기록에 `ready`와 기기 제어 줄, `/health`가 `{"status":"ok","deviceButton":false}`.
- 데몬은 `&`가 `cd` 뒤 명령에만 걸리게 `;`로 씁니다(T27에서 `&&`로 쓰면 SSH가 끝나지 않았음).

### 4단계. 웹페이지 열기와 리허설 (10분)

1. Mac 브라우저로 보드 웹페이지를 엽니다. 사이드바 아래 `서버 정상`, 가운데 `녹음하고 있지 않습니다`와 큰 빨간 `녹음 시작`.
   - 먼저 `curl -s -m 5 http://<보드 IPv4>:3000/health`로 닿는지 봅니다. 닿으면 `http://<보드 IPv4>:3000`.
   - 2026-11-25에는 Mac이 핫스팟에서 IPv4를 받지 못했습니다(`ifconfig en0`의 `inet`이 `192.0.0.2`뿐, IPv6 전용 망의 변환 주소). 그때는 보드의 고정 IPv6(`mngtmpaddr`)를 대괄호로 씁니다: `http://[<보드 IPv6>]:3000`. `temporary` 주소는 하루쯤 뒤 바뀝니다.
   - 핫스팟에서 보드는 공인 IPv6 주소를 받고, 서버에는 로그인이 없습니다. 촬영이 끝나면 바로 6단계로 서버를 끕니다.
2. 리허설: `녹음 시작` → 2인 대본 1~4줄 → 마지막 줄이 확정되면 `녹음 종료` → 히스토리 상세로 넘어감.
3. 확인: 자막이 말하는 동안 흐리게 뜨고 줄마다 확정됨. 사람이 바뀔 때 줄이 나뉨. 숫자가 `12월 3일`처럼 나옴. 말소리가 작거나 자꾸 틀리는 단어가 있으면 마이크 거리를 고치거나 대본 단어를 바꿉니다.
4. 화면 녹화(`⌘⇧5`)를 시험으로 몇 초 찍어, 화면과 소리가 담기는지 봅니다.

### 5단계. 촬영 (2인 10분, 3인 10분)

대본마다 아래를 합니다.

1. 화면 녹화를 시작하고, 웹 녹음 화면을 보여 줍니다.
2. `녹음 시작` → 대본대로 대화 → 마지막 줄이 확정된 뒤 `녹음 종료`.
3. 히스토리 상세에서 문장과 시각을 천천히 보여 주고 `txt 내려받기`(또는 `md 내려받기`)를 누릅니다. 내려받은 파일을 열어 보여 줘도 좋습니다.
4. 화면 녹화를 멈춥니다.
5. 세션 확인(번호는 히스토리 상세 주소 `/history/<번호>`):

```bash
ssh rubikpi 'sudo -u postgres psql -d transcriber -At -c "select id, status from sessions order by id desc limit 2" -c "select session_id, count(*) from segments where session_id >= (select max(id) - 1 from sessions) group by session_id"'
ssh rubikpi 'journalctl -u transcriber-server --since "-5 min" --no-pager -o cat | grep -iE "device|error|오류" | tail -5; grep -i -E "warn|error|xrun|drop" ~/t41/daemon.log | tail -3'
```

- 확인: 방금 세션이 `ended`, 문장 수가 대본 줄 수와 비슷(사람이 바뀌는 곳마다 나뉘면 2인 약 18줄, 3인 약 19줄). 서버·데몬 기록에 오류 없음.
- 다시 찍으면 새 세션이 생깁니다. 쓸 영상의 세션 번호를 일지에 적습니다.

### 말하는 요령

- 한 사람이 끝나면 **1초쯤 쉬고** 다음 사람이 말합니다. 말이 끊긴 곳에서 줄이 나뉘어, 화면에서 한 사람의 말이 한 줄이 됩니다.
- **겹쳐 말하지 않습니다.** 맞장구("네", "음")도 소리 내지 않습니다. 겹친 말은 한 줄에 섞입니다.
- 화면에는 누가 말했는지 나오지 않습니다(화자 분리 없음). 필요하면 편집할 때 이름 자막을 넣습니다.
- 한 번에 길게 이어 말하지 않습니다. 줄은 대부분 3~5초이고, 가장 긴 정리 줄(2인 16번, 3인 17번)도 8초 안쪽입니다.
- 숫자는 또박또박 말합니다. 화면에 `12월 3일`, `3시`처럼 숫자로 나올 때가 많습니다.
- 모두 마이크 쪽을 보고, 마이크와 거리를 비슷하게 둡니다.

걸리는 시간(줄 사이 1초 쉼 포함, 음절 수로 어림): 2인 1분 25초~1분 40초, 3인 1분 35초~1분 55초. 3인이 길면 9·15·16번 줄을 빼면 15초쯤 줄어듭니다.

## 완료 기준

| 확인 | 기대 |
| --- | --- |
| 보드 앱 | `git -C ~/web-app log -1 --format=%h` → `280d9a8`, `/health` → `"deviceButton":false` |
| 웹 화면 | 대기 화면에 큰 빨간 `녹음 시작`, 녹음 중 큰 `녹음 종료` |
| 세션 | 2인·3인 세션이 `ended`이고 문장이 있음. 번호를 일지에 적음 |
| 파일 | Mac에 두 세션의 화면 녹화와 txt(또는 md) |
| 정리 | 데몬·엔진·서버 꺼짐, 클럭 `schedutil` |

## 확인하지 않는 것

- 인식 정확도(CER) 측정. 대본 정답과 비교는 하지 않습니다(필요하면 T41 2부에서).
- 부팅 뒤 자동 시작(T35), 물리 버튼(T36).

## 막히면

- 핫스팟에서 보드가 안 보임: 보드가 핫스팟에 붙었는지 휴대폰의 연결된 기기 수로 봅니다. 보드가 다른 네트워크에 붙어 있으면 그 네트워크로 Mac을 옮기거나 사용자에게 묻습니다.
- `녹음을 시작하지 못했습니다: 기기에 연결하지 못했습니다…`: 데몬이 꺼졌거나 `/run/audiostack`이 없음. `tail ~/t41/daemon.log`를 보고 3단계 데몬 줄을 다시 합니다.
- 녹음은 되는데 자막이 안 나옴: `tail ~/t41/engine.log`, `astk-ctl status`로 엔진이 붙었는지 봅니다. 엔진이 죽었으면 3단계 엔진 줄을 다시 합니다.
- 화면 위에 `실시간 연결이 끊겼습니다`: 핫스팟 연결을 봅니다. 자동으로 다시 붙고, 녹음은 보드에서 계속됩니다.
- 서버가 답하지 않음(2026-11-25에 한 번): Mac에서 보드로 `curl`·SSH가 모두 막혔지만 보드 쪽 서버·와이파이는 그대로였고, 조치 없이 다시 닿았습니다. 촬영 중에는 휴대폰의 개인용 핫스팟 화면을 열어 두고, 다시 닿을 때까지 기다린 뒤 새로고침합니다. 그래도 안 되면 `ping6 -c 3 ff02::1%en0`로 보드가 보이는지 봅니다.
- 녹음이 끝나지 않음: `ssh rubikpi '~/audio-stack/build/astk-ctl session stop'` 뒤 화면을 새로고침합니다.
