- 실행 전에 Docker Desktop과 DB 컨테이너, 루트 `.env`, `~/Desktop/stt-lab`의 가상환경과 모델 캐시가 있어야 합니다.

범위는 다음과 같습니다.

- 하는 것: `~/Desktop/stt-lab`의 스트리밍 엔진 스크립트, 서버의 엔진 어댑터, 어댑터를 고르는 환경변수, 관련 기록.

## 엔진과 어댑터 사이의 약속

한 줄에 JSON 하나, UTF-8입니다. 엔진의 로그는 표준 오류로 내고, 서버가 `[stt-local]`을 붙여 찍습니다.

| 방향 | 줄 | 뜻 |
| --- | --- | --- |
| 엔진 → 서버 | `{"type":"ready","device":"mps"}` | 모델을 불러왔습니다. 이 뒤로 WAV 재생을 시작합니다 |
| 엔진 → 서버 | `{"type":"partial","text":"…","startMs":0,"endMs":1000}` | 말하는 중의 결과 |
| 엔진 → 서버 | `{"type":"final","text":"…","startMs":0,"endMs":4200,"latencyMs":850}` | 구간이 끝난 결과. 빈 텍스트면 내지 않습니다 |
| 엔진 → 서버 | `{"type":"end"}` | `stop`을 받고 마지막 final까지 냈습니다 |
| 엔진 → 서버 | `{"type":"error","message":"…"}` | 계속할 수 없는 오류 |
| 서버 → 엔진 | `stop` | 녹음을 끝냅니다 |

세션 시작 시각과 오디오 0초 사이에는 모델을 불러오는 시간만큼 차이가 있습니다. 히스토리의 문장 시각은 오디오 기준이라 이 차이를 포함하지 않습니다.

## 완료 기준

CER은 1단계와 같은 정규화(공백과 문장부호 제외)로, 내려받은 txt의 문장을 이어 붙여 `demo_long.tsv`의 정답 12문장과 비교합니다.

| 명령어·동작 | 기대 출력 |
| --- | --- |
| `npm run typecheck` | 종료 코드 0 |
| `npm run dev:stt` | 마지막 줄 `[stt] stopped - partial 11개, final 3개` |
| `STT_MODE` 없이 `npm run dev:server`, 웹에서 녹음 | 지금과 같은 mock 문장 |
| `STT_MODE=local`인데 `LOCAL_STT_SCRIPT`가 없음 | `[env]`가 빠진 이름을 알리고 종료 코드 1 |
| 엔진 단독 실행 | `ready` 뒤 partial·final 줄. `stop`을 입력하면 `end`가 나오고 종료 코드 0 |
| `STT_MODE=local`로 서버를 띄우고 웹에서 '녹음 시작' | 30초 안에 `녹음 중`. 흐린 줄이 1초 안팎 간격으로 바뀌고, final이 쌓임 |

| txt 내려받기와 정답 비교 | CER을 기록합니다. 1단계(6.91%)와 비교만 하고 합격선은 두지 않습니다 |
| final 지연 | 서버 로그 `latencyMs`의 평균과 최대를 기록 |

## 결정 사항과 남은 질문

- 이미 정한 것: 위 '착수 전 확인', 세션·SSE·DB 구조(T06~T09), 웹 화면(T13~T16).

- 정하지 않는 것: 최종 연동 방식(T19), 기기 실행(T26), 마이크(T27), 이 브랜치의 `main` 병합 여부.
