# [T02] 로컬 PostgreSQL(docker-compose)과 환경변수 로더 — 지침서

2026-10-12 · 이광호

## 목표

`docker compose up -d` 한 번으로 노트북에 PostgreSQL이 뜨고, `npm run dev:server`가 `.env`에서 읽은 `PORT`, `DB_URL`, `STT_URL`을 확인한 뒤 시작합니다. 빠진 값이 있으면 어떤 변수가 없는지 알리고 종료 코드 1로 끝납니다.

## 배경과 전제, 범위

`CLAUDE.md`의 확정된 결정에 따라 DB는 PostgreSQL이고, 노트북에서 먼저 개발하며, STT·DB 주소는 코드에 쓰지 않고 환경변수로 받습니다. 선행 작업은 T01(완료)이고, 새로 설치할 npm 패키지는 없습니다.

이 작업은 DB를 띄우고 주소를 읽는 데까지만 합니다. 서버가 DB에 실제로 접속하는 것은 T04입니다.

- 하는 것: 루트 `docker-compose.yml`, `.env` 만들기, 환경변수 로더, 서버 진입점에서 로더 호출, `dev` 스크립트에 `--env-file` 연결, 서버 tsconfig에 Node 타입 추가.
- 하지 않는 것: `pg` 설치와 연결 풀(T04), 테이블과 마이그레이션(T03), 서버 프레임워크 도입(D2), `STT_URL`을 실제로 쓰는 코드(T20), 단위 테스트(T17).

## 착수 전 확인

아래 네 가지는 사용자가 2026-10-12에 확정했습니다.

| 항목 | 결정 | 비고 |
| --- | --- | --- |
| 브랜치 이름 | `feat/t02-postgres-env` | T05와 같은 형식 |
| PostgreSQL 버전 | 16 (`postgres:16` 이미지) | Rubik Pi에서 쓸 버전(D5)이 정해지면 맞춥니다 |

Docker Desktop이 켜져 있어야 합니다. `docker info`가 서버 버전을 보여 주면 됩니다.

## 구현 순서

1. `main`에서 새 브랜치를 만듭니다.

    ```bash
    git switch -c feat/t02-postgres-env
    ```

2. 루트에 `docker-compose.yml`을 씁니다. 계정·비밀번호·DB 이름은 `.env.example`의 `DB_URL`(`postgres://user:password@localhost:5432/transcriber`)과 같게 둡니다.

    ```yaml
    # 로컬 개발용 PostgreSQL. 계정·비밀번호·DB 이름은 .env.example의 DB_URL과 같게 둔다.
    # 프로젝트 이름을 고정해 워크트리에서 실행해도 같은 컨테이너와 볼륨을 쓴다.
    name: speech-transcriber

    services:
      db:
        image: postgres:16
        environment:
          POSTGRES_USER: user
          POSTGRES_PASSWORD: password
          POSTGRES_DB: transcriber
        ports:
          # 이 컴퓨터에서만 접속할 수 있게 연다.
          - '127.0.0.1:5432:5432'
        volumes:
          - db-data:/var/lib/postgresql/data
        healthcheck:
          test: ['CMD-SHELL', 'pg_isready -U user -d transcriber']
          interval: 5s
          timeout: 3s
          retries: 10

    volumes:
      db-data:
    ```

3. `.env`를 만듭니다. `.env.example`의 값이 2단계와 이미 같으므로 그대로 복사합니다.

    ```bash
    cp .env.example .env
    ```

4. `apps/server/tsconfig.json`에 Node 타입을 추가합니다. 지금 설정에서는 `process`를 찾지 못해 타입 검사가 실패합니다.

    ```json
    {
      "extends": "../../tsconfig.base.json",
      "compilerOptions": {
        "types": ["node"]
      },
      "include": ["src"]
    }
    ```

5. `apps/server/src/config/env.ts`에 로더를 씁니다. 빈 문자열도 빠진 값으로 봅니다.

    ```ts
    // 환경변수를 읽어 서버 설정으로 만든다. 주소 같은 값은 코드에 쓰지 않고 여기서만 받는다.
    const REQUIRED_KEYS = ['PORT', 'DB_URL', 'STT_URL'] as const;
    type EnvKey = (typeof REQUIRED_KEYS)[number];

    export interface Env {
      port: number;
      dbUrl: string;
      sttUrl: string;
    }

    function fail(message: string): never {
      console.error(`[env] ${message}`);
      process.exit(1);
    }

    // 빠진 값이 있으면 이름을 모두 알리고 종료 코드 1로 끝낸다. 빈 문자열도 빠진 값으로 본다.
    export function loadEnv(): Env {
      const missing = REQUIRED_KEYS.filter((key) => !process.env[key]);
      if (missing.length > 0) {
        fail(`환경변수가 없습니다: ${missing.join(', ')} (.env.example을 .env로 복사했는지 확인하세요)`);
      }

      const { PORT, DB_URL, STT_URL } = process.env as Record<EnvKey, string>;
      const port = Number(PORT);
      if (!Number.isInteger(port) || port < 1 || port > 65535) {
        fail(`PORT는 1~65535 사이의 정수여야 합니다: ${PORT}`);
      }

      return { port, dbUrl: DB_URL, sttUrl: STT_URL };
    }

    // 로그에 찍을 DB 주소. 비밀번호 자리를 가린다.
    export function maskDbUrl(dbUrl: string): string {
      return dbUrl.replace(/(:\/\/[^:@/]*):[^/]*@/, '$1:***@');
    }
    ```

6. `apps/server/src/index.ts`에서 로더를 부릅니다. 기존 `ready` 줄은 그대로 둡니다.

    ```ts
    // 임시 진입점. 환경변수를 읽어 설정을 확인한다. (HTTP 서버는 T04에서 만든다)
    import { APP_NAME } from '@app/shared';
    import { loadEnv, maskDbUrl } from './config/env';

    const env = loadEnv();

    console.log(`[server] ready - ${APP_NAME}`);
    // 비밀번호는 가리고 찍는다.
    console.log(
      `[server] config - PORT=${env.port} DB_URL=${maskDbUrl(env.dbUrl)} STT_URL=${env.sttUrl}`,
    );
    ```

7. `apps/server/package.json`의 `dev` 스크립트를 고칩니다. 스크립트는 `apps/server`에서 실행되므로 루트 `.env`는 `../../.env`입니다. `dev:stt`는 고치지 않습니다.

    ```json
    "dev": "tsx --env-file=../../.env src/index.ts"
    ```

8. 동작을 확인하고 커밋합니다. push와 `main` 병합은 사용자가 따로 지시할 때 합니다.

    ```bash
    docker compose up -d
    docker compose ps
    docker compose exec db psql -U user -d transcriber -c 'select 1'
    npm run typecheck
    npm run dev:server
    DB_URL= npm run dev:server
    npm run dev:stt
    git add -A
    git commit -m "feat: 로컬 PostgreSQL과 환경변수 로더 추가"
    ```

9. 기록을 남깁니다. `docs/logs/2026-10-12.md`에 단계별 상태를 적고, `TODO.md`는 변경안을 사용자에게 먼저 보고한 뒤 허락을 받고 고칩니다. 이 지침서 맨 아래 '결과'도 채웁니다.

## 완료 기준

| 명령어 | 기대 출력 |
| --- | --- |
| `docker compose up -d` 뒤 `docker compose ps` | `db` 서비스의 STATUS에 `(healthy)` |
| `docker compose exec db psql -U user -d transcriber -c 'select 1'` | `1`이 든 한 행과 `(1 row)` |
| `npm run typecheck` | tsc 에러 없이 종료 코드 0 |
| `npm run dev:server` | 아래 두 줄 출력 후 종료 코드 0 |
| `DB_URL= npm run dev:server` | `[env] 환경변수가 없습니다: DB_URL …` 출력 후 종료 코드 1 |
| `npm run dev:stt` | T05 지침서의 15줄과 같은 출력, 종료 코드 0 |
| `git check-ignore .env` | `.env` (커밋 대상이 아님) |
| `git branch --show-current` | `feat/t02-postgres-env` |
| `git log --oneline -1` | `feat: 로컬 PostgreSQL과 환경변수 로더 추가` |

`npm run dev:server`의 기대 출력입니다.

```text
[server] ready - speech-transcriber
[server] config - PORT=3000 DB_URL=postgres://user:***@localhost:5432/transcriber STT_URL=http://localhost:9000
```

`DB_URL= npm run dev:server`는 `DB_URL`을 빈 값으로 넘겨 실행합니다. 셸에 이미 있는 환경변수가 `.env` 파일의 값보다 먼저 쓰이므로, `.env`를 고치지 않고도 빠진 경우를 확인할 수 있습니다.

## 사전 검증 (2026-10-12)

지침서를 쓰면서 `apps/server/src`에 임시 파일을 만들어 실행해 본 뒤 지웠습니다. 저장소에는 남아 있지 않습니다.

| 확인한 것 | 결과 |
| --- | --- |
| `docker info` | 서버 29.2.0, Docker Compose v5.0.2. 5432 포트는 비어 있음 |
| 지금 tsconfig로 `process.env`, `process.exit`를 쓴 파일 타입 검사 | 실패 (`TS2591: Cannot find name 'process'`) |
| 같은 파일을 `--types node`로 타입 검사 | 통과 (종료 코드 0). 4단계를 넣은 이유입니다 |
| `apps/server`에서 `tsx --env-file=../../.env.example`로 실행 | `PORT` 값 `3000`을 읽음 |
| `PORT=`(빈 값)을 앞에 붙여 같은 명령 실행 | 빈 문자열이 읽힘. 셸의 값이 파일보다 먼저 쓰임 |
| `.env`가 없을 때 `--env-file=../../.env` | `node: ../../.env: not found`, 종료 코드 9. 3단계를 먼저 해야 합니다 |
| 2단계의 compose 파일, 5~6단계의 코드 | 실행하지 않음. 구현 때 처음 실행합니다 |

## 결정 사항과 남은 질문

- 이미 정한 것: PostgreSQL 16, 브랜치 이름, Node 내장 `--env-file`, `pg`는 T04에서 설치, 변수 이름 `PORT`·`DB_URL`·`STT_URL`.
- 이 지침서에서 정한 것:
  - compose 파일에 계정·비밀번호를 직접 씁니다. 노트북 개발 전용 값이고 `.env.example`에 이미 공개된 값과 같습니다. 기기나 배포 환경에서는 쓰지 않습니다.
  - 포트는 `127.0.0.1:5432`로만 엽니다. 같은 네트워크의 다른 기기에서는 접속할 수 없습니다.
  - compose 프로젝트 이름을 `speech-transcriber`로 고정합니다. 컨테이너는 `speech-transcriber-db-1`, 볼륨은 `speech-transcriber_db-data`가 됩니다.
  - 로더가 `PORT`가 1~65535 사이의 정수인지도 확인합니다.
- 아직 정해야 하는 것: Rubik Pi에서 쓸 PostgreSQL 버전과 메모리 설정(D5, D8, 하드웨어 파트 김범수와 협의·실측 후). 정해지면 이미지 태그를 맞춥니다.
