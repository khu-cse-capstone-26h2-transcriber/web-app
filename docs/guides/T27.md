# [T27] 하드웨어 파이프라인 연동(XVF3800 마이크, `audiostackd`, 웹 버튼) — 지침서

2026-11-18 · 이광호

## 목표

보드(Rubik Pi 3)에 XVF3800 USB 마이크를 꽂아, 말한 소리가 `audiostackd` → 엔진(NPU) → 앱 서버 → 웹 실시간 자막·DB·히스토리까지 이어지는지 처음으로 확인합니다. 지금까지는 WAV 파일만 넣었습니다(T26). 녹음 시작·종료는 두 길로 해 봅니다. 하나는 기기 명령(`astk-ctl`, 물리 버튼이 쓸 길)이고, 하나는 웹 버튼(`DEVICE_CTRL_SOCKET`, web-app PR #2)입니다. 끝나면 아래가 모두 됩니다.

1. 보드가 XVF3800을 USB 오디오 장치로 알아봅니다. 마이크가 알려 주는 형식(표본율, 채널 수)에 맞는 설정 파일을 골랐습니다(범수 님 보드에서는 16 kHz 2채널). 우리 보드의 `arecord -l`이 기록되어 있습니다.
2. Codeberg `audio-stack` `main`의 데몬이 보드에 빌드되어 대기 상태(`--idle`)로 뜨고, XVF3800 소리를 엔진에 넘깁니다.
3. `astk-ctl session start`로 시작한 녹음이 웹 화면에 저절로 나타납니다. 말하는 동안 자막이 흐르고, `session stop` 뒤 히스토리 상세로 넘어갑니다. DB 행 수, 상세, txt가 서로 맞습니다. 원고를 읽은 녹음의 CER과 final 지연이 기록되어 있습니다.
4. 웹 '녹음 시작'·'녹음 종료'가 `ctrl.sock`으로 데몬을 켜고 끕니다. 서버 세션과 데몬 세션 번호가 같습니다. 한쪽에서 시작하고 다른 쪽에서 끝내도 세션이 하나로 닫힙니다.
5. 데몬이 꺼져 있을 때 웹 '녹음 시작'이 어떻게 되는지 기록되어 있습니다.

## 배경과 전제, 범위

- 마이크: 2026-11-18 하드웨어 파트에서 두 개를 받습니다. XVF3800(USB)과 Sipeed 6+1 Microphone Array입니다.
  - XVF3800은 하드웨어 파트가 정한 기준 마이크입니다(HW-7). `audio-stack`에 설정 파일 3개와 문서(`docs/XVF3800.md`)가 있습니다.
  - 범수 님 확인(2026-11-18, HW-7·HW-12 '답'): XVF3800이 `config/xvf3800-16k2ch.conf`(16 kHz 2채널)로 잡히고, RNNoise를 켠 채 60초 녹음해도 끊김·손실이 없었습니다. 업데이트한 커널·펌웨어(`6.8.0-1089-qcom`, `linux-firmware-dragonwing` 20260825)에서 XVF3800을 꽂은 채 보드 오디오(`plughw:0,2`, 48 kHz)와 `audiostackd`도 정상이었고, 기본값을 그대로 쓰면 된다고 했습니다. 범수 님 보드에서 본 것이라, 우리 보드에서 같은지는 1단계에서 봅니다.
  - Sipeed 6+1은 I2S 디지털 마이크 7개(데이터 선 4개)를 쓰는 보드입니다. 40핀 헤더에 연결하고, 장치 트리 오버레이와 커널 드라이버가 있어야 소리를 받습니다. `audio-stack`에는 마이크 1개용 실험 틀(`dts/inmp441-i2s-overlay.dts`)만 있습니다. 그래서 이번에는 XVF3800만 하고, Sipeed 6+1을 어디에 쓸지는 범수 님께 묻습니다(아래 '남은 질문').
- 보드 상태(T26 끝, 2026-11-16. T34는 보드에서 하지 않음): Ubuntu 24.04.2 서버 이미지(화면 없음), 커널 `6.8.0-1089-qcom`, 엔진 `~/rubikpi/runner`(빌드됨, NPU), 모델·QNN `~/rubikpi/`, 앱 서버 `transcriber-server.service`(`User=ubuntu`, 꺼져 있음, `disabled`), PostgreSQL 켜짐, `~/audio-stack`은 GitHub 조직 저장소에서 받은 PR #2 브랜치(데몬은 빌드 안 함), SSH 비밀번호 로그인 꺼짐.
- 앱: `main` `40d7e1f`에 web-app PR #2가 들어 있습니다. `DEVICE_CTRL_SOCKET`이 있으면 웹 녹음 버튼이 mock 대신 데몬의 `ctrl.sock`에 `session start`·`session stop`을 보냅니다(`apps/server/src/device/control.ts`).
  - 시작: 데몬의 답(`OK sess-…`) 번호로 서버 세션을 먼저 만듭니다. 뒤에 오는 데몬의 세션 통지는 같은 번호라 무시됩니다.
  - 종료: 데몬의 `/end`를 10초까지 기다리고, 오지 않으면 서버에서 닫습니다.
  - 오류: 데몬에 닿지 못하면 `503`(`DEVICE_UNAVAILABLE`), 데몬이 `OK`가 아닌 답을 주면 `502`(`DEVICE_ERROR`)입니다. `BUSY`도 아직 `502`입니다(HW-5 '앱에서 할 일', 이번에 고치지 않음).
  - 보드의 `~/web-app`은 T26 때 커밋이라 갱신해야 합니다.

- 데몬은 `ubuntu` 계정으로 직접 띄웁니다(2026-11-18 사용자 결정). 소켓 주인이 `ubuntu`라 앱 서버(`User=ubuntu`)와 엔진(`ubuntu`)이 바로 씁니다. 마이크 장치(`/dev/snd/pcmC*D*c`)는 보통 `root:audio 0660`이라 `ubuntu`가 `audio` 그룹이어야 엽니다(1단계에서 확인).

- 하는 것: 보드 상태와 XVF3800 확인, 설정 파일 고르기, Codeberg `main` 받기와 데몬 빌드, 10초 녹음, 보드 앱 갱신과 `.env`에 `DEVICE_CTRL_SOCKET`, 실시간 연동 시험 4가지(기기 명령, 웹 버튼, 섞어서, 데몬이 꺼졌을 때), 메모리·CPU 한 줄, 정리, 기록.
- 하지 않는 것: 앱 코드 변경(찾은 문제는 기록만), 데몬·엔진·앱 서버 서비스 설치와 부팅 자동 시작, 물리 버튼, 엔진 상태 알림 경로(HW-4)와 `BUSY` 응답(HW-5), XVF3800 펌웨어·빔 경로 바꾸기(`xvf_host.py`로 쓰기), RNNoise 비교, Sipeed 6+1, 잡음 환경·먼 거리·긴 녹음, `git push`.

### 0단계. Mac 준비 (5분)

```bash
mkdir -p ~/Desktop/stt-lab/t27
cd ~/Desktop/speech_transcriber && git rev-parse --short main && git bundle create ~/Desktop/stt-lab/t27/web-app-main.bundle main
```

- 확인: `main`이 `40d7e1f`입니다(원격 `main`과 같음).

녹음 파일의 길이와 크기를 보는 Mac 스크립트를 만듭니다(저장소 밖 `~/Desktop/stt-lab/t27/level.py`, T34에서 쓰려던 것과 같음).

```bash
cat > ~/Desktop/stt-lab/t27/level.py <<'EOF'
"""T27: WAV(S16_LE 모노)의 표본율, 길이, 최대·평균 크기(dBFS)를 찍는다. 무음이면 -inf.
  python3 ~/Desktop/stt-lab/t27/level.py <wav>"""
import array
import math
import sys
import wave

w = wave.open(sys.argv[1])
a = array.array("h", w.readframes(w.getnframes()))
peak = max((abs(x) for x in a), default=0)
rms = math.sqrt(sum(x * x for x in a) / len(a)) if a else 0
db = lambda v: 20 * math.log10(v / 32768) if v else float("-inf")
print(f"{w.getframerate()} Hz, {len(a) / w.getframerate():.1f} s, peak {db(peak):.1f} dBFS, rms {db(rms):.1f} dBFS")
EOF
```

### 1단계. 보드 상태와 XVF3800 확인 (15분)

마이크를 꽂기 전:

```bash
ssh rubikpi 'mkdir -p ~/t27; uname -r; timedatectl | grep synchronized; id -nG; nmcli -t -f NAME connection show --active; arecord -l; cat /proc/asound/cards'
```

- 확인: 시계가 `synchronized: yes`(HW-10). 보드 자체 사운드카드 목록을 일지에 적습니다. 범수 님 보드처럼 보드 오디오가 카드 0인지 봅니다(HW-12 답, 다르면 기록만).
- `id -nG`에 `audio`가 없으면 `ssh rubikpi 'sudo usermod -aG audio ubuntu'`를 하고, 아래부터는 새 SSH 접속에서 그룹이 적용됩니다(명령마다 새로 접속하므로 따로 할 일 없음).

XVF3800을 꽂고:

```bash
ssh rubikpi 'sleep 2; lsusb -d 2886:001a; arecord -l; sudo dmesg | grep -i -E "usb|audio" | tail -8'
ssh rubikpi 'cat /proc/asound/card<N>/stream0; ls -l /dev/snd/pcmC<N>D0c'
```

`<N>`은 `arecord -l`에서 XVF3800 줄의 카드 번호입니다. `stream0`의 Capture 쪽 형식(표본율, 채널 수)으로 설정 파일을 고릅니다. 범수 님이 시험한 마이크는 첫 줄(16 kHz, 2채널)이었습니다.

| `stream0` Capture 형식 | 설정 파일 | 3단계 `--native-rate`, `--channels` |
| --- | --- | --- |
| 16 kHz, 2채널 (범수 님 확인) | `config/xvf3800-16k2ch.conf` | `16000`, `2` |
| 16 kHz, 6채널 | `config/xvf3800-16k6ch.conf` | `16000`, `6` |
| 48 kHz, 2채널 | `config/xvf3800-48k2ch.conf` | `48000`, `2` |

- 확인: `lsusb`에 `2886:001a` 한 줄, `arecord -l`에 XVF3800 카드가 새로 생김, 장치 파일이 `audio` 그룹. 고른 파일과 `stream0` 전체를 일지에 적습니다.
- `lsusb`에 없으면: 충전 전용 케이블이거나 XIAO 쪽 포트일 수 있습니다. 케이블·포트를 바꿔 봅니다.
- 위 세 형식 중 어느 것도 아니면 **멈춥니다.** `stream0` 전체를 적고 범수 님께 묻습니다(펌웨어 바꾸기는 하드웨어 파트 몫).

### 3단계. 10초 녹음 (15분)

데몬과 같은 코드로 고른 빔 채널만 10초 녹음합니다. 마이크에서 50 cm~1 m 떨어져 보통 목소리로 원고 첫 두 문장을 읽습니다. `<R>`, `<C>`는 1단계 표의 값입니다.

```bash
ssh rubikpi 'cd ~/audio-stack && ./build/astk-capture-wav --device auto:xvf3800 --native-rate <R> --channels <C> --channel-index 0 --no-highpass --seconds 10 --out ~/t27/x1-beam.wav'
scp rubikpi:t27/x1-beam.wav ~/Desktop/stt-lab/t27/ && python3 ~/Desktop/stt-lab/t27/level.py ~/Desktop/stt-lab/t27/x1-beam.wav && afplay ~/Desktop/stt-lab/t27/x1-beam.wav
```

- 확인: `16000 Hz, 10.0 s`, 들어 보면 목소리가 알아들을 만큼 나옵니다. peak와 rms를 적습니다(말할 때 peak가 -20 dBFS 위면 충분).

| 결과 | 할 일 |
| --- | --- |
| 목소리가 들림 | 4단계 |
| 장치를 열지 못함 | 오류 전체, `id -nG`, `ls -l /dev/snd/pcmC<N>D0c`, `fuser -v /dev/snd/*`를 적습니다. 장치를 여러 개 찾았다는 오류면 `--device hw:CARD=<카드 이름>,DEV=0`으로 다시 합니다(4단계에서 설정 파일 `device`도 같은 값으로) |
| 완전 무음이거나 아주 작음 | 원본 채널을 함께 녹음해 봅니다: `arecord -D hw:CARD=<카드 이름>,DEV=0 -f S16_LE -c <C> -r <R> -d 10 ~/t27/x1-raw.wav`. 원본에는 소리가 있고 빔 채널만 비면 빔 경로 문제입니다. 마이크 설정은 바꾸지 않고 **멈추고** 범수 님께 묻습니다 |
| 쇳소리·끊김 | 데몬 기록이 없으니 그대로 적고 진행합니다. 7단계 데몬 기록의 XRUN과 함께 봅니다 |
