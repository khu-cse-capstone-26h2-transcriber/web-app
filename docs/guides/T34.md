# [T34] 에어팟(블루투스) 마이크로 보드 실시간 받아쓰기 시험 — 지침서

2026-11-17 · 이광호

> **취소(2026-11-18, 사용자 결정).** 시연용 마이크가 11-18에 도착해 에어팟 대체 시험을 하지 않습니다. 보드에서 돌린 단계는 없습니다. 마이크 연결은 T27에서 하고, 아래 '목요일 마이크로 바꿀 때' 절(데몬 빌드, 실행 순서, `[capture]`·`[pre]` 변경)은 T27 지침서를 쓸 때 참고합니다.

## 목표

보드(Rubik Pi 3)에 에어팟을 블루투스로 연결해, 말한 소리가 `audiostackd` → 엔진(NPU) → 앱 서버 → 웹 실시간 자막·DB·히스토리까지 이어지는지 확인합니다. 지금까지는 WAV 파일만 넣었습니다(T26). 이번이 처음으로 마이크로 받는 시험입니다. 끝나면 아래가 모두 됩니다.

1. 보드 블루투스가 켜지고 에어팟이 짝 맺기·연결되어, 통화(헤드셋) 프로필에서 보드가 에어팟 마이크 소리를 녹음합니다. 쓰인 코덱(mSBC 16 kHz 또는 CVSD 8 kHz)을 알고 있습니다.
2. 보드에 `audiostackd`(Codeberg `audio-stack` `main`)가 빌드되어 있고, 에어팟 소리를 받아 엔진에 넘깁니다.
3. `astk-ctl session start`로 시작한 녹음이 웹 화면에 저절로 나타나고, 말하는 동안 자막이 흐르고, `session stop` 뒤 히스토리 상세로 넘어갑니다. DB 행 수, 상세, txt가 서로 맞습니다.
4. 원고를 읽은 녹음의 CER과 final 지연이 기록되어 있습니다.
5. 목요일(11-19)에 하드웨어 파트에서 받을 시연용 마이크로 바꿀 때 그대로 쓸 것(데몬 빌드, 실행 순서, 확인 명령)과 바꿀 것이 정리되어 있습니다.

## 배경과 전제, 범위

- 마이크는 하드웨어 파트가 정합니다(HW-7: XVF3800 기준, 그 전에는 4극 3.5 mm 이어폰). 에어팟은 **목요일 전에 마이크 경로를 미리 확인하려는 시험용 대체 마이크**입니다. 마이크 선택을 바꾸지 않습니다. 목요일에는 하드웨어 파트에서 실제 시연용 마이크를 받아 연결합니다(2026-11-17 사용자).
- 보드 상태(T26 끝, 2026-11-16): Ubuntu 24.04.2 **서버 이미지**(화면 없음), 커널 `6.8.0-1089-qcom`, 엔진 `~/rubikpi/runner`(빌드됨, NPU), 모델·QNN `~/rubikpi/`, 앱 서버 `transcriber-server.service`(꺼져 있음, `disabled`), PostgreSQL 켜짐, `~/audio-stack`은 GitHub 조직 저장소에 PR #2 브랜치를 받은 것(데몬은 빌드 안 함), SSH 비밀번호 로그인 꺼짐.
- 에어팟 마이크는 블루투스 **통화 모드(HFP)** 에서만 켜집니다. 음악 모드(A2DP)는 소리를 보내기만 합니다. 통화 모드 코덱은 mSBC(16 kHz) 또는 CVSD(8 kHz)입니다. 엔진 입력이 16 kHz라 mSBC가 맞고, CVSD면 4 kHz 위 소리가 없어 받아쓰기가 나빠질 수 있습니다.
- 블루투스 소리는 PipeWire로 받습니다(2026-11-17 사용자 결정). Thundercomm 매뉴얼('Wi-Fi and Bluetooth')도 블루투스 전에 PipeWire를 깝니다. Ubuntu 24.04 판은 PipeWire 1.0.5, WirePlumber 0.4.17(설정이 Lua 파일)입니다. 다른 방식인 BlueALSA(`bluez-alsa-utils` 4.1.1)는 패키지가 mSBC에 필요한 `spandsp` 없이 빌드된 것으로 보여(의존성 목록에 없음) 고르지 않았습니다.
- `audiostackd`는 ALSA 장치 이름을 그대로 `snd_pcm_open`에 넘깁니다(`src/alsa_capture.cpp`). PipeWire의 ALSA 다리(`pipewire-alsa`)가 만드는 `pipewire` 장치를 `[capture] device`에 쓰면 됩니다. `audio-stack` `docs/UBUNTU-INPUT.md`도 사운드 서버가 있을 때 'ALSA bridge PCM'을 쓰라고 적습니다.
- PipeWire는 사용자(`ubuntu`) 서비스로 돕니다. 그래서 이번 시험의 데몬도 `ubuntu` 계정으로 직접 띄웁니다. 서비스 파일(`User=root`)로 설치하지 않습니다.
- PipeWire는 보드 사운드카드와 USB 마이크를 잡지 않게 합니다(WirePlumber ALSA 감시 끔). 목요일 마이크(3.5 mm 또는 XVF3800 USB)는 `audiostackd`가 ALSA로 직접 열기 때문입니다.
- 앱 서버·웹 코드는 바꾸지 않습니다. 기기 수신 경로(`/api/device/sessions`)는 T20·T26 그대로입니다.

- 하는 것: 블루투스 장치 확인, BlueZ·PipeWire 설치와 화면 없는 보드 설정, 에어팟 짝 맺기, 통화 프로필 녹음, Codeberg `audio-stack` `main` 받기와 데몬 빌드, 데몬 설정 파일, 실시간 연동(원고 읽기, 자유 발화), (선택) 에어팟 끊김 관찰, 정리, 기록.
- 하지 않는 것: 저장소 코드 변경(찾은 문제는 기록만), 데몬·엔진 서비스 설치와 부팅 자동 시작(T27), 물리 버튼(T27), 엔진 상태 알림 경로(HW-4, 앱에 받을 경로가 없어 `engine_path`는 빈 값), 3.5 mm·XVF3800 시험(목요일), 잡음 환경 비교, 긴 녹음, 에어팟으로 소리 내보내기, `git push`.

## 진행 순서

### 0단계. Mac 준비

```bash
mkdir -p ~/Desktop/stt-lab/t34
cat ~/Desktop/stt-lab/stt-engine/samples/fleurs_ko_30s.txt
```

녹음 파일의 길이와 크기를 보는 Mac 스크립트를 만듭니다(저장소 밖 `~/Desktop/stt-lab/t34/level.py`).

```bash
cat > ~/Desktop/stt-lab/t34/level.py <<'EOF'
"""T34: WAV(S16_LE 모노)의 표본율, 길이, 최대·평균 크기(dBFS)를 찍는다. 무음이면 -inf.
  python3 ~/Desktop/stt-lab/t34/level.py <wav>"""
import array
import math
import sys
import wave

w = wave.open(sys.argv[1])
a = array.array("h", w.readframes(w.getnframes()))
peak = max((abs(x) for x in a), default=0)
rms = math.sqrt(sum(x * x for x in a) / len(a)) if a else 0
db = lambda v: 20 * math.log10(v / 32768) if v else float("-inf")
print(f"{w.getframerate()} Hz, {len(a) / w.getframerate():.1f} s, peak {db(peak):.1f} dBFS, rms {db(rms):.1f} dBFS")
EOF
```

### 1단계. 보드 상태와 블루투스 장치 확인 (10분)

```bash
ssh rubikpi 'mkdir -p ~/t34; uname -r; timedatectl | grep synchronized; id -nG; dpkg -l bluez pipewire wireplumber 2>/dev/null | grep -E "^(ii|un)"; systemctl is-active bluetooth; ls /sys/class/bluetooth; rfkill list bluetooth'
ssh rubikpi 'sudo dmesg | grep -i -E "bluetooth|hci|qca" | tail -20'
ssh rubikpi 'arecord -l; cat /proc/asound/cards; fuser -v /dev/snd/* 2>&1 | tail -5'
```

- 확인: `/sys/class/bluetooth`에 `hci0`이 있습니다. 시계가 `synchronized: yes`입니다.
- `arecord -l`과 `/proc/asound/cards`를 일지에 적습니다. 업그레이드한 커널에서 3.5 mm 장치가 그대로인지(HW-12)에 쓸 수 있습니다.

| 결과 | 할 일 |
| --- | --- |
| `hci0` 있음 | 2단계 |
| `rfkill`이 `Soft blocked: yes` | `ssh rubikpi 'sudo rfkill unblock bluetooth'` 뒤 다시 확인 |
| `bluez`가 없음(`un` 또는 줄 없음) | 2단계에서 함께 설치한 뒤 `hci0`을 다시 확인 |
| `hci0`이 없고 `dmesg`에 펌웨어 오류 | **멈춥니다.** 오류 줄을 적고 범수 님께 알립니다(업그레이드한 펌웨어 `linux-firmware-dragonwing`과 관계있을 수 있음, HW-12와 함께). 목요일 마이크로 넘어갑니다 |

### 2단계. BlueZ·PipeWire 설치와 화면 없는 보드 설정 (20분)

```bash
ssh rubikpi 'sudo apt-get update -q && sudo apt-get install -y bluez pipewire-audio pulseaudio-utils alsa-utils 2>&1 | grep -E "^Need to get|newly installed"'
```

`pipewire-audio`가 `pipewire-alsa`, `pipewire-pulse`, `wireplumber`, `libspa-0.2-bluetooth`를 함께 깝니다. `pulseaudio-utils`는 `pactl`(프로필·기본 입력 바꾸기)용입니다. 받은 양을 적습니다.

WirePlumber 설정 두 개(보드 `~/.config/wireplumber/`):

```bash
ssh rubikpi 'mkdir -p ~/.config/wireplumber/bluetooth.lua.d ~/.config/wireplumber/main.lua.d'
ssh rubikpi 'cat > ~/.config/wireplumber/bluetooth.lua.d/51-t34-headless.lua' <<'EOF'
-- T34: 화면 없는 보드(SSH만)에서도 블루투스 소리를 켠다. 로그인 좌석 확인(logind)을 끈다
bluez_monitor.properties["with-logind"] = false
EOF
ssh rubikpi 'cat > ~/.config/wireplumber/main.lua.d/51-t34-no-alsa.lua' <<'EOF'
-- T34: PipeWire는 블루투스만 맡는다. 보드 사운드카드와 USB 마이크는 audiostackd가 ALSA로 직접 연다
alsa_monitor.enabled = false
EOF
```

켜기:

```bash
ssh rubikpi 'sudo systemctl enable --now bluetooth && sudo loginctl enable-linger ubuntu && systemctl --user restart pipewire pipewire-pulse wireplumber && sleep 2; systemctl is-active bluetooth; systemctl --user is-active pipewire pipewire-pulse wireplumber'
ssh rubikpi 'ls /sys/class/bluetooth; pactl info | grep -E "Server Name|Default Source"; wpctl status | sed -n "1,25p"; fuser -v /dev/snd/* 2>&1 | grep -c pipewire'
```

- 확인: `active` 네 줄. `Server Name: PulseAudio (on PipeWire 1.0.5)`. `wpctl status`의 Audio → Devices에 보드 사운드카드가 없습니다. 마지막 숫자가 `0`(PipeWire가 `/dev/snd`를 잡지 않음).
- 사운드카드가 보이면 ALSA 감시 설정이 먹지 않은 것입니다. `systemctl --user status wireplumber`와 `journalctl --user -u wireplumber -n 20`을 적고 파일 이름·경로를 다시 봅니다.

### 3단계. 에어팟 짝 맺기와 연결 (15분)

아이폰·Mac 블루투스를 끈 것을 확인합니다. 에어팟을 케이스에 넣고 뚜껑을 연 채, 케이스 뒷면 버튼을 **하얀 불이 깜빡일 때까지** 누릅니다.

```bash
ssh rubikpi 'bluetoothctl power on; bluetoothctl show | grep -E "Name|Powered|Pairable"'
ssh rubikpi 'bluetoothctl --timeout 30 scan on' | grep -i -E "airpods|NEW"
```

에어팟 줄의 주소를 보드 파일에 저장하고(문서에는 적지 않음) 짝 맺기·신뢰·연결을 합니다.

```bash
ssh rubikpi 'echo <에어팟 주소> > ~/t34/airpods.addr'
ssh rubikpi 'A=$(cat ~/t34/airpods.addr); bluetoothctl pair $A && bluetoothctl trust $A && bluetoothctl connect $A; sleep 2; bluetoothctl info $A | grep -E "Name|Paired|Trusted|Connected|Handsfree|Audio Sink"'
```

- 확인: `Paired: yes`, `Trusted: yes`, `Connected: yes`, UUID에 `Handsfree`가 있습니다.
- 짝 맺기가 안 되면: `bluetoothctl remove $A` 뒤 케이스 버튼부터 다시. 그래도 안 되면 `/etc/bluetooth/main.conf`의 `ControllerMode`를 `bredr`로 바꾸고 `sudo systemctl restart bluetooth` 뒤 다시 합니다(지침서와 다른 점으로 적음).
- 한 줄로 안 되면 `ssh -t rubikpi bluetoothctl` 안에서 `agent on`, `default-agent`, `scan on`, `pair`, `trust`, `connect`를 차례로 입력해도 됩니다.

### 4단계. 통화 프로필과 10초 녹음 (20분)

```bash
ssh rubikpi 'pactl list cards | grep -E "Name: bluez|headset-head-unit|a2dp-sink|Active Profile"'
ssh rubikpi 'C=bluez_card.$(tr : _ < ~/t34/airpods.addr); pactl set-card-profile $C headset-head-unit && sleep 1; pactl list cards | grep "Active Profile"; pactl list sources short'
ssh rubikpi 'S=$(pactl list sources short | grep -o "bluez_input[^[:space:]]*" | head -1); pactl set-default-source $S; pactl get-default-source; pactl list sources | grep -A45 "Name: $S" | grep -E "Sample Specification|api.bluez5.codec"'
```

- 확인: 활성 프로필이 `headset-head-unit`, 기본 입력이 `bluez_input…`. 코덱(`api.bluez5.codec`)과 표본율을 적습니다. `msbc`·16000 Hz면 기대한 대로, `cvsd`·8000 Hz면 음질이 낮습니다(그래도 진행).

에어팟을 귀에 끼고, 아래 명령을 실행한 뒤 원고 첫 두 문장을 읽습니다.

```bash

scp rubikpi:t34/a1-arecord.wav ~/Desktop/stt-lab/t34/
python3 ~/Desktop/stt-lab/t34/level.py ~/Desktop/stt-lab/t34/a1-arecord.wav

```

- 확인: 10.0초, 들어 보면 내 목소리가 알아들을 만큼 나옵니다. peak와 rms를 적습니다(말할 때 peak가 -20 dBFS 위면 충분).

| --- | --- |
| 목소리가 들림 | 5단계 |
| 완전 무음(`-inf`) | 에어팟을 귀에 꼈는지, `pactl list sources short`에서 그 입력이 `RUNNING`인지 봅니다. 그래도 무음이면 녹음하는 동안 다른 터미널에서 `ssh rubikpi 'sudo timeout 10 btmon' \| grep -c "SCO Data"`. 0이면 보드 블루투스 칩이 통화 소리를 HCI가 아닌 다른 길로 보내는 설정일 수 있습니다. **멈추고** 기록해 범수 님께 알립니다. 목요일 마이크로 넘어갑니다 |

### 7단계. 실시간 연동 (40분)

```bash

```

- 확인: 데몬 기록에 `ALSA opened: device=pipewire rate=16000 ch=1`. 엔진 기록에 소켓 연결과 모델 준비. `astk-ctl status`가 대기 중(녹음 아님)이고 엔진이 붙어 있으며 장치가 `pipewire`.
- 데몬이 바로 끝나면 `daemon.log` 전체를 적습니다. `/run/audiostack` 권한이나 PipeWire 접속(`XDG_RUNTIME_DIR`) 문제일 수 있습니다.

Mac 브라우저 패널로 `http://<보드 IP>:3000`을 엽니다. `녹음하고 있지 않습니다`, 위쪽 `서버: 정상`. **웹 '녹음 시작'은 누르지 않습니다**(T26 B 11).

**시험 1. 원고 읽기.** 에어팟을 끼고 시작합니다.

```bash
ssh rubikpi '~/audio-stack/build/astk-ctl session start; sleep 1; ~/audio-stack/build/astk-ctl status'
```

1. 화면이 저절로 녹음 중으로 바뀌면 원고 5문장을 보통 속도로 읽습니다. 문장 사이에 1~2초 쉽니다.
2. 다 읽고 3초 뒤 멈춥니다: `ssh rubikpi '~/audio-stack/build/astk-ctl session stop; sleep 6; ~/audio-stack/build/astk-ctl status'`
3. 화면이 히스토리 상세로 넘어가면 세션 번호를 적고 txt를 내려받습니다.

```bash

```

- 확인: 세션 `ended`. DB 행 수 = 서버 기록의 `저장 N개` = 상세 문장 수 = txt 문장 줄 수. `segment_id`가 0부터 빈 번호 없이 이어집니다. 말하는 동안 partial이 흐르고 문장마다 final로 바뀌었는지 적습니다.

- 데몬 기록의 XRUN·버림(`drop`) 수를 적습니다.

**시험 2. 자유 발화 1~2분.** 같은 방법으로 시작·종료합니다. 평소 말투로 이야기하고, 자막이 뜨기까지 체감 지연과 틀리는 곳을 적습니다(CER 없음). 끝나기 전에 메모리·CPU를 한 번 봅니다.

## 목요일 마이크로 바꿀 때 (이 작업 밖)

받는 마이크가 정해지면 지침서를 따로 씁니다(T27 또는 새 번호). 이번에 확인한 것 중 그대로 쓰는 것과 바꾸는 것입니다.

- 그대로: 5단계 데몬 빌드, 7단계 실행 순서(서버 → 데몬 → 엔진 → `session start`·`stop`), 확인 명령(psql, 서버 기록, `cer.py`).
- 바꿈: `[capture]`·`[pre]`만 마이크에 맞춥니다(`[backend]`는 그대로, HW-7 '앱에서 할 일'). XVF3800이면 `config/xvf3800-*.conf` 중 하나(`device = auto:xvf3800`), 3.5 mm면 `plughw:0,2`와 믹서 경로(`amixer -c 0 cset "name=MultiMedia3 Mixer PRIMARY_MI2S_TX" 1`).
- PipeWire가 필요 없습니다. 데몬은 ALSA로 직접 엽니다. 시작 전에 `fuser -v /dev/snd/*`에 PipeWire가 없는지 봅니다. 데몬을 `ubuntu`로 띄우면 `ubuntu`가 `audio` 그룹인지(1단계 `id -nG`) 봅니다.
