## 점검 순서

'psql'은 `docker compose exec db psql -U user -d transcriber_m1`으로 같은 내용을 읽는다는 뜻입니다. 서버 PID는 `lsof -tiTCP:3000 -sTCP:LISTEN`으로 찾습니다.

### 1. 준비 (새 클론, 빈 DB)

```bash
git clone --branch main <메인 체크아웃 경로> "$M1_DIR"
cd "$M1_DIR"
node -v                       # v20.20.2
npm ci
cp .env.example .env          # DB_URL의 DB 이름만 transcriber_m1으로 바꿈
docker compose up -d --wait
docker compose exec db createdb -U user transcriber_m1
npm run db:migrate
npm run db:migrate            # 두 번째는 모두 skip
npm run typecheck
npm run build -w @app/web
npm run dev:stt               # mock 이벤트가 찍히면 Ctrl+C
npm run dev:server
npm run dev:web               # 5173이 열리는지만 보고 끔
npm run preview -w @app/web   # 4173
```

### 2. 기본 흐름 (#1)

1. `http://localhost:4173/`을 엽니다. 녹음하고 있지 않고, 히스토리는 비어 있습니다.
2. '녹음 시작'을 누르고 약 30초 동안 자막을 봅니다.
3. '녹음 종료'를 누릅니다. 히스토리 상세로 넘어갑니다.
4. 히스토리 목록으로 가서 방금 녹음을 확인합니다.
5. 상세에서 txt·md를 내려받고, 내용을 화면·psql과 비교합니다.
6. 375px 너비로 녹음 화면과 상세를 봅니다.

### 3. 실패 경로 A: 녹음 중 조용히 끊김 (#2)

녹음을 시작하고 10초 뒤 서버에 `SIGSTOP`을 보내 30초 넘게 기다립니다. 배너를 확인한 뒤 `SIGCONT`를 보내고, 다시 연결된 다음 웹 버튼으로 종료합니다.

### 4. 실패 경로 B: 녹음 중 서버 재시작 (#3)

녹음을 시작하고 10초 뒤 서버에 `SIGINT`를 보내 끕니다. 배너를 확인한 뒤 서버를 다시 켭니다. 화면이 스스로 히스토리 상세로 넘어가야 합니다.
