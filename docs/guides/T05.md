# [T05] STT 어댑터 인터페이스와 mock STT — 지침서

2026-10-11 · 이광호

## 목표

`npm run dev:stt` 한 번으로 mock STT가 partial → final 순서로 이벤트를 내보내는 것이 콘솔에 찍힙니다. 서버의 다른 코드는 `SttAdapter` 인터페이스만 보고, 나중에 실제 STT로 바꿀 때 구현체 하나만 갈아 끼우면 됩니다.

## 배경과 전제, 범위

`CLAUDE.md`의 확정된 결정에 따라 STT는 Node 내부 mock으로 시작해 실제 STT로 교체하고, 구현체는 어댑터 인터페이스 뒤에 둡니다. 서버와 웹이 함께 쓰는 타입은 `packages/shared`에 둡니다. 선행 작업은 T01(완료)이고, 새로 설치할 패키지는 없습니다.

이 작업에서 정하는 이벤트 형식은 **초안**입니다. 최종 형식은 D4 합의(T19, AI 파트 박지윤·하드웨어 파트 김범수)에서 확정하고, 이 초안이 그 협의의 출발점이 됩니다.

- 하는 것: STT 이벤트 타입(shared), `SttAdapter` 인터페이스, `MockSttAdapter`, 확인용 실행 스크립트, `dev:stt` 명령어.
- 하지 않는 것: 실제 오디오 입력과 오디오 형식(D4), 환경변수로 mock/실제 STT를 고르는 팩토리(T20), 세션 API(T06), SSE(T07), DB 저장(T08), 단위 테스트(T17), 서버 진입점 `apps/server/src/index.ts` 수정.

## 착수 전 확인

작업을 시작하기 전에 사용자가 아래 두 가지를 확인합니다. 답이 다르면 해당 단계의 코드만 바꿉니다.

| 항목 | 제안 | 비고 |
| --- | --- | --- |
| 브랜치 이름 | `feat/t05-stt-adapter` | 브랜치 이름 규칙이 아직 없어 제안한 이름입니다 |
| 이벤트 필드 | `type`, `segmentId`, `text`, `startMs`, `endMs` | 아래 '이벤트 형식 초안' 참고 |

## 이벤트 형식 초안

| 필드 | 타입 | 뜻 |
| --- | --- | --- |
| `type` | `'partial'` \| `'final'` | partial은 아직 바뀔 수 있는 중간 결과, final은 확정된 결과 |
| `segmentId` | `number` | 세션 안에서 0부터 증가. 같은 세그먼트의 partial과 final은 같은 값 |
| `text` | `string` | 세그먼트 시작부터 지금까지의 전체 텍스트(추가분만 보내지 않음) |
| `startMs` | `number` | 세션 시작 기준 세그먼트 시작 시각(ms) |
| `endMs` | `number` | 세션 시작 기준 이 이벤트 시점의 끝 시각(ms) |

이 형식에서 화면은 같은 `segmentId`의 줄을 새 `text`로 덮어쓰기만 하면 되고, DB에는 final만 저장하면 됩니다(T08).

## 구현 순서

1. `main`에서 새 브랜치를 만듭니다.

    ```bash
    git switch main
    git switch -c feat/t05-stt-adapter
    ```

2. `packages/shared/src/stt.ts`에 이벤트 타입을 씁니다.

    ```ts
    // STT 이벤트 타입 초안. 최종 형식은 T19(D4) 협의에서 확정한다.
    export type SttEventType = 'partial' | 'final';

    export interface SttEvent {
      // partial: 아직 바뀔 수 있는 중간 결과, final: 확정된 결과
      type: SttEventType;
      // 세션 안에서 0부터 증가한다. 같은 세그먼트의 partial과 final은 같은 값을 쓴다.
      segmentId: number;
      // 세그먼트 시작부터 지금까지의 전체 텍스트 (추가분만 보내지 않는다)
      text: string;
      // 세션 시작 기준 세그먼트 시작·끝 시각(ms)
      startMs: number;
      endMs: number;
    }
    ```

3. `packages/shared/src/index.ts`에서 타입을 내보냅니다. 기존 `APP_NAME`은 그대로 둡니다.

    ```ts
    // 서버와 웹이 함께 쓰는 상수와 타입.
    export const APP_NAME = 'speech-transcriber';

    export type { SttEvent, SttEventType } from './stt';
    ```

4. `apps/server/src/stt/adapter.ts`에 인터페이스를 씁니다. 실제 STT는 연결에 시간이 걸릴 수 있어 `start`와 `stop`을 `Promise`로 둡니다. 오디오를 어떻게 넘길지는 D4에서 정하므로 여기에는 넣지 않습니다.

    ```ts
    // STT 구현체가 따라야 하는 인터페이스. mock과 실제 STT를 바꿔 끼우는 경계다.
    import type { SttEvent } from '@app/shared';

    export type SttEventHandler = (event: SttEvent) => void;

    export interface SttAdapter {
      // 인식을 시작한다. 이벤트가 생길 때마다 onEvent를 호출한다.
      start(onEvent: SttEventHandler): Promise<void>;
      // 인식을 멈춘다. 멈춘 뒤에는 onEvent를 호출하지 않는다.
      stop(): Promise<void>;
    }
    ```

5. `apps/server/src/stt/mock.ts`에 mock 구현을 씁니다. 정해진 문장을 단어 하나씩 늘려 가며 partial로 내보내고, 문장의 마지막 단어에서 final을 내보냅니다. 문장 목록이 끝나면 처음으로 돌아가 `stop()`까지 반복합니다.

    ```ts
    // 정해진 문장을 단어 단위로 흘려보내는 가짜 STT. 실제 STT가 붙기 전까지 쓴다.
    import type { SttAdapter, SttEventHandler } from './adapter';

    export const MOCK_SENTENCES = [
      '안녕하세요 오늘 회의를 시작하겠습니다',
      '첫 번째 안건은 일정 공유입니다',
      '다음 주까지 초안을 정리해 주세요',
    ];

    export interface MockSttOptions {
      sentences?: string[];
      // 단어 하나가 나오는 간격(ms)
      intervalMs?: number;
    }

    export class MockSttAdapter implements SttAdapter {
      private readonly sentences: string[];
      private readonly intervalMs: number;
      private timer: ReturnType<typeof setInterval> | undefined;

      constructor(options: MockSttOptions = {}) {
        this.sentences = options.sentences ?? MOCK_SENTENCES;
        this.intervalMs = options.intervalMs ?? 200;
      }

      async start(onEvent: SttEventHandler): Promise<void> {
        if (this.timer) throw new Error('이미 시작된 어댑터입니다');

        let segmentId = 0;
        let wordCount = 0;
        let elapsedMs = 0;
        let startMs = 0;

        // 문장 목록을 끝까지 내보내면 처음 문장으로 돌아가 stop()까지 반복한다.
        this.timer = setInterval(() => {
          const words = this.sentences[segmentId % this.sentences.length].split(' ');
          wordCount += 1;
          elapsedMs += this.intervalMs;
          const isLastWord = wordCount === words.length;

          onEvent({
            type: isLastWord ? 'final' : 'partial',
            segmentId,
            text: words.slice(0, wordCount).join(' '),
            startMs,
            endMs: elapsedMs,
          });

          if (isLastWord) {
            segmentId += 1;
            wordCount = 0;
            startMs = elapsedMs;
          }
        }, this.intervalMs);
      }

      async stop(): Promise<void> {
        clearInterval(this.timer);
        this.timer = undefined;
      }
    }
    ```

    타이머 타입은 `NodeJS.Timeout`이 아니라 `ReturnType<typeof setInterval>`로 씁니다. 현재 tsconfig에서는 `NodeJS` 네임스페이스를 찾지 못해 타입 검사가 실패합니다.

6. `apps/server/src/stt/demo.ts`에 확인용 스크립트를 씁니다. 변수 타입을 `SttAdapter`로 두어, 사용하는 쪽이 인터페이스만 본다는 것을 확인합니다.

    ```ts
    // mock STT가 내보내는 이벤트를 콘솔에 찍어 보는 확인용 스크립트.
    import type { SttAdapter } from './adapter';
    import { MOCK_SENTENCES, MockSttAdapter } from './mock';

    const adapter: SttAdapter = new MockSttAdapter();
    let partialCount = 0;
    let finalCount = 0;

    await adapter.start((event) => {
      if (event.type === 'partial') partialCount += 1;
      else finalCount += 1;

      console.log(
        `[stt] ${event.type.padEnd(7)} #${event.segmentId} ${event.startMs}-${event.endMs}ms ${event.text}`,
      );

      // 문장 목록을 한 바퀴 돌면 멈춘다. 멈춘 뒤 프로세스가 끝나면 타이머가 정리된 것이다.
      if (finalCount === MOCK_SENTENCES.length) {
        void adapter.stop().then(() => {
          console.log(`[stt] stopped - partial ${partialCount}개, final ${finalCount}개`);
        });
      }
    });
    ```

7. 실행 명령어를 추가합니다.

    - `apps/server/package.json`의 `scripts`에 `"dev:stt": "tsx src/stt/demo.ts"`를 추가합니다.
    - 루트 `package.json`의 `scripts`에 `"dev:stt": "npm run dev:stt -w @app/server"`를 추가합니다.

8. 동작을 확인하고 커밋합니다. push와 `main` 병합은 사용자가 따로 지시할 때 합니다.

    ```bash
    npm run typecheck
    npm run dev:stt
    npm run dev:server
    git add -A
    git commit -m "feat: STT 어댑터 인터페이스와 mock STT 추가"
    ```

## 결정 사항과 남은 질문

- 이미 정한 것: STT는 mock으로 시작해 실제 STT로 교체, 구현체는 어댑터 인터페이스 뒤에 둠, 공용 타입은 `packages/shared`.
- 이 지침서에서 제안한 것(사용자 확인 필요): 브랜치 이름, 이벤트 필드 5개, partial의 `text`를 누적 전체 텍스트로 보내는 방식.
- 아직 정해야 하는 것(D4, AI·하드웨어 파트 협의): STT 호출 방법, 오디오 입력 형식, partial/final 이벤트의 최종 형식. 협의 결과에 따라 `SttEvent`와 `SttAdapter.start`의 인자가 바뀔 수 있습니다.
