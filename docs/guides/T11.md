# [T11] 히스토리 내보내기 API — 지침서

2026-10-27 · 이광호

## 목표

`GET /api/sessions/:id/export?format=txt|md`로 끝난 녹음 하나를 파일 하나로 내려받습니다. 파일에는 머리말(녹음 번호, 시작 시각, 길이, 상태) 아래에 문장마다 시작 시각을 붙여 씁니다. T16(히스토리 화면과 다운로드 버튼)이 이 API를 씁니다.

## 배경과 전제, 범위

선행 작업 T10(히스토리 API)은 끝났습니다. T10의 `findSession`과 `listSegments`로 세션과 저장된 세그먼트를 읽고, 그것을 글로 바꿔 파일로 응답합니다. 실행 전에 Docker Desktop이 켜져 있고 `docker compose up -d`로 DB가 떠 있어야 하며, 루트 `.env`가 있어야 합니다.

D6(히스토리 다운로드 포맷)은 2026-10-27에 txt와 md 둘 다로 정했습니다(사용자 결정).

- 하는 것: 공용 `ExportFormat` 타입, txt·md 포매터(`apps/server/src/export/format.ts`), 라우트 `GET /:id/export`.
- 하지 않는 것: 다운로드 버튼과 히스토리 화면(T16), 포매터 단위 테스트(T17), 여러 세션을 한 번에 내보내기(백로그에 없음), 다른 포맷(srt 등), 스키마 변경, `ended_at` 값 자체를 고치는 것(아래 '녹음 길이' 참고).

## 착수 전 확인

아래는 사용자가 2026-10-27에 확정했습니다(추천안 그대로). 다시 묻지 않고 이대로 진행합니다.

| 항목 | 결정 | 비고 |
| --- | --- | --- |
| 다운로드 포맷 (D6) | txt와 md 둘 다 | 포매터가 순수 함수라 하나를 더 만드는 비용이 작습니다 |
| 브랜치 이름 | `feat/t11-history-export` | 기존 형식과 같습니다. `main`의 `1e40bd3`에서 만들었습니다 |
| API 주소 | `GET /api/sessions/:id/export?format=txt\|md` | T10에서 예고한 대로 세션 아래에 붙입니다. `format`은 꼭 있어야 합니다 |
| 파일 내용 | 머리말(번호, 시작 시각, 길이, 상태) 아래에 문장마다 시작 시각 | 끝 시각은 쓰지 않습니다 |
| 시작 시각 시간대 | 한국 시간(`Asia/Seoul`) 고정 | 기기 시간대 설정과 상관없이 같은 결과가 나옵니다 |
| 녹음 길이 | 마지막 문장의 끝 시각(`endMs`) | T06부터 미뤄 온 `ended_at` 보정의 답입니다. 서버가 꺼져 끊긴 세션도 같은 규칙입니다. T16 화면도 같은 규칙을 씁니다 |
| 녹음 중인 세션 | `409`로 거절 | 히스토리 목록에도 끝난 세션만 나옵니다 |
| 파일 이름 | `session-42.txt`, `session-42.md` | 영문으로 씁니다. 한글 파일 이름은 따로 인코딩 처리가 필요합니다 |
| 문장이 없는 끝난 세션 | 머리말과 `(저장된 문장이 없습니다)` 한 줄 | `404`로 막지 않습니다. 상세 API와 같습니다 |

## API 동작

| 요청 | 응답 |
| --- | --- |
| `GET /api/sessions/:id/export?format=txt` | `200`, `Content-Type: text/plain; charset=utf-8`, `Content-Disposition: attachment; filename=session-42.txt` |
| `GET /api/sessions/:id/export?format=md` | `200`, `Content-Type: text/markdown; charset=utf-8`, `Content-Disposition: attachment; filename=session-42.md` |
| `format`이 없거나 `txt`, `md`가 아님(여러 번 준 경우 포함) | `400` `INVALID_EXPORT_FORMAT` |
| 번호가 양의 정수가 아님 | `400` `INVALID_SESSION_ID` (T10과 같음) |
| 없는 번호 | `404` `SESSION_NOT_FOUND` |
| 녹음 중인 세션(서버가 종료를 처리하는 중 포함) | `409` `SESSION_RECORDING` |
| DB가 꺼짐 | `503` `DB_UNAVAILABLE` (T13과 같음) |

확인 순서는 번호, `format`, DB 순서입니다. 잘못된 요청은 DB에 닿기 전에 `400`으로 끝납니다.

녹음 중인지는 DB의 `status`로 봅니다. 서버는 밀린 세그먼트를 모두 쓴 뒤에 세션을 닫으므로(T08), `ended`가 된 세션의 문장은 모두 DB에 있습니다.

### 파일 모양

txt:

```text
녹음 #42
시작: 2026-10-23 14:05
길이: 3분 12초
상태: 종료됨

[00:00] 안녕하세요 오늘 회의를 시작하겠습니다
[00:08] 첫 번째 안건은 일정 공유입니다
```

md:

```markdown
# 녹음 #42

- 시작: 2026-10-23 14:05
- 길이: 3분 12초
- 상태: 종료됨

## 내용

- `00:00` 안녕하세요 오늘 회의를 시작하겠습니다
- `00:08` 첫 번째 안건은 일정 공유입니다
```

| 항목 | 쓰는 방법 |
| --- | --- |
| 시작 | `startedAt`을 한국 시간 `YYYY-MM-DD HH:mm`으로 |
| 길이 | 세그먼트 `endMs` 중 가장 큰 값. 초 아래는 버림. `12초`, `3분 12초`, `1시간 2분 3초`. 문장이 없으면 `0초` |
| 상태 | `ended`는 `종료됨`, `interrupted`는 `중단됨 (서버가 꺼져 끊김)` |
| 문장 앞 시각 | `startMs`를 `00:08` 모양으로. 1시간이 넘으면 `1:02:03`. 초 아래는 버림 |
| 문장 | `segmentId` 순서로 한 줄에 하나. 문장 안에 줄바꿈이 있으면 공백으로 바꿈 |
| 줄 끝 | `\n`. 파일 끝에도 `\n` 하나 |

md 특수문자(`*`, `_` 등)는 이스케이프하지 않습니다. STT 결과는 말한 문장이라 거의 나오지 않고, 이스케이프하면 메모장으로 열었을 때 읽기 어려워집니다.

| 타입 (`packages/shared`) | 내용 |
| --- | --- |
| `EXPORT_FORMATS`, `ExportFormat` (`export.ts`) | `['txt', 'md']`와 그 유니언 타입. 서버는 `format` 검사에, T16 웹앱은 버튼을 만들 때 씁니다 |

## 구현 순서

1. DB가 떠 있는지 확인하고 `main`에서 새 브랜치를 만듭니다.

    ```bash
    docker compose up -d --wait
    git switch -c feat/t11-history-export
    ```

2. `packages/shared/src/export.ts`에 `EXPORT_FORMATS`와 `ExportFormat`을 두고 `index.ts`에서 내보냅니다.

3. `apps/server/src/export/format.ts`를 씁니다. DB와 Express를 모르는 순수 함수로 둡니다(T17이 그대로 테스트할 수 있게).
    - `formatOffset(ms)`, `formatDuration(ms)`, 한국 시간 시작 시각
    - `formatTxt(session, segments)`, `formatMd(session, segments)`
    - `exportSession(format, session, segments)`: `{ filename, contentType, body }`

4. `apps/server/src/sessions/routes.ts`에 `GET /:id/export`를 더합니다. 번호와 `format`을 읽고, 세션을 찾고(없으면 `404`), 녹음 중이면 `409`, 아니면 세그먼트를 읽어 `res.attachment`, `res.type`, `res.send`로 응답합니다. `/:id`와 같이 쓰는 '세션을 찾고 없으면 `404`'는 함수로 묶습니다.

5. 확인하고 커밋합니다.

    ```bash
    npm run typecheck
    git add packages/shared/src apps/server/src docs/guides/T11.md
    git commit -m "feat: 히스토리 txt·md 내보내기 API 추가"
    ```

6. 기록을 남깁니다. `docs/logs/`의 그날 일지, `docs/project-overview.md`, 이 지침서의 '결과'를 채웁니다. `TODO.md`는 변경안을 사용자에게 먼저 보고한 뒤 허락을 받고 고칩니다.

## 완료 기준

'psql과 같음'은 `docker compose exec db psql -U user -d transcriber`로 같은 내용을 읽어 비교한다는 뜻입니다. 서버는 3000번, Vite 개발 서버는 5173번입니다.

| 명령어·동작 | 기대 출력 |
| --- | --- |
| `npm run typecheck` | tsc 에러 없이 종료 코드 0 |
| `curl -i '…/api/sessions/<끝난 세션>/export?format=txt'` | `200`, `Content-Type: text/plain; charset=utf-8`, `Content-Disposition: attachment; filename=session-<번호>.txt`, 본문이 위 '파일 모양'과 같음 |
| 같은 세션 `format=md` | `200`, `Content-Type: text/markdown; charset=utf-8`, `filename=session-<번호>.md`, 본문이 위 '파일 모양'과 같음 |
| 위 두 파일의 문장 | 줄 수, 첫 문장, 마지막 문장이 psql과 같음 |
| 위 두 파일의 머리말 | 시작 시각이 psql `started_at at time zone 'Asia/Seoul'`과 같음(분까지). 길이가 psql `max(end_ms)`와 같음 |
| `interrupted` 세션 내보내기 | `상태: 중단됨 (서버가 꺼져 끊김)`, 길이가 `ended_at - started_at`이 아니라 `max(end_ms)` |
| 문장이 없는 끝난 세션 | `200`, `길이: 0초`, `(저장된 문장이 없습니다)` |
| 녹음 중인 세션 | `409` `SESSION_RECORDING` |
| `format` 없음, `format=pdf`, `format=txt&format=md` | 모두 `400` `INVALID_EXPORT_FORMAT` |
| 번호 `abc`, 없는 번호 | `400` `INVALID_SESSION_ID`, `404` `SESSION_NOT_FOUND` |
| DB를 멈추고 요청 | `503` `DB_UNAVAILABLE` |
| 포매터에 1시간이 넘는 값(임시 스크립트) | 문장 앞 `1:02:03`, 길이 `1시간 2분 3초` |
| 내려받은 파일을 `file`로 확인 | `UTF-8` 텍스트(한글이 깨지지 않음) |
| Vite 개발 서버(5173)를 거쳐 같은 요청 | 3000번과 같은 헤더와 본문 (T16이 이 경로로 받음) |
| `GET /api/sessions`, `GET /api/sessions/:id` | 전과 같음 |
| `git log --oneline -1` (코드 커밋 직후) | `feat: 히스토리 txt·md 내보내기 API 추가` |
