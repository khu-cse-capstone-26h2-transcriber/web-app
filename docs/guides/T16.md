# [T16] 히스토리 화면과 다운로드 버튼 — 지침서

2026-10-28 · 이광호

## 목표

히스토리 목록(`/history`)에서 지난 녹음을 고르고, 상세(`/history/:id`)에서 문장을 시각과 함께 읽고 txt·md 파일로 내려받습니다. 화면에 보이는 시작 시각, 길이, 상태, 문장 앞 시각은 내려받은 파일과 같습니다.

## 배경과 전제, 범위

선행 작업 T10(히스토리 API), T11(내보내기 API), T12(웹앱 뼈대)는 끝났습니다. 지금 두 화면은 T12에서 만든 서버 연결 확인용 자리라, 목록은 번호와 요약을 그대로 늘어놓고 상세는 요약 한 줄만 보입니다. 실행 전에 Docker Desktop이 켜져 있고 `docker compose up -d`로 DB가 떠 있어야 하며, 루트 `.env`가 있어야 합니다.

- 하는 것: 시각·길이·상태 표시 함수를 `packages/shared`로 옮기기(서버 내보내기는 그 함수를 가져다 씀), 파일 응답을 받는 `requestFile`, 내보내기 API 함수, 다운로드 버튼, 목록·상세 화면.
- 하지 않는 것: 목록 API에 길이 더하기(아래 '착수 전 확인'), 목록 화면의 다운로드 버튼, 검색(T23), 페이지 나누기, 녹음 화면(`RecordPage.tsx`)의 `formatElapsed`를 공용 함수로 바꾸기, 단위 테스트(T17), 서버 API 동작 변경.

## 화면 동작

### 목록 (`/history`)

| 상태 | 보이는 것 |
| --- | --- |
| 불러오는 중 | `불러오는 중…` |
| 실패 | 에러 문구(`role="alert"`). 서버가 꺼졌으면 `서버에 연결하지 못했습니다`, DB가 꺼졌으면 `503`의 문구 |
| 녹음이 없음 | `지난 녹음이 없습니다` |
| 녹음이 있음 | `지난 녹음 N개`와 목록. 한 항목은 첫 줄 `#45 · 2026-10-23 14:05 · 문장 7개`, 둘째 줄 첫 문장 미리보기(한 줄로 자르고 `…`). 항목 전체가 상세로 가는 링크 |

서버가 꺼져 끊긴 세션은 첫 줄 끝에 상태 이름(`중단됨 (서버가 꺼져 끊김)`)을 붙입니다. 순서는 API 그대로(최근에 시작한 것부터)입니다.

### 상세 (`/history/:id`)

```text
← 히스토리
녹음 #45
시작 2026-10-23 09:53 · 길이 6초 · 종료됨
[txt 내려받기] [md 내려받기]

[00:00] 안녕하세요 오늘 회의를 시작하겠습니다
[00:03] 첫 번째 안건은 일정 공유입니다
```

| 상황 | 보이는 것 |
| --- | --- |
| 끝난 세션 | 위 모양. 문장은 `segmentId` 순서 |
| 문장이 없는 끝난 세션 | 머리말, 버튼, `저장된 문장이 없습니다`. 내려받으면 머리말만 있는 파일 |
| 녹음 중인 세션 | 지금까지 저장된 문장. 버튼은 눌리지 않고 `녹음 중이라 아직 내려받을 수 없습니다`와 녹음 화면 링크 |
| 내려받는 중 | 누른 버튼이 `받는 중…`, 두 버튼 모두 눌리지 않음 |
| 내려받기 실패 | 버튼 아래 `내려받지 못했습니다: <서버 문구>`(`role="alert"`). 다시 누를 수 있음 |
| 없는 번호, 잘못된 번호 | 에러 문구(`세션을 찾을 수 없습니다: 999999`, `세션 번호는 양의 정수여야 합니다: abc`) |

### 공용 표시 함수 (`packages/shared/src/format.ts`)

| 이름 | 내용 (T11의 규칙 그대로) |
| --- | --- |
| `formatStartedAt(iso)` | 한국 시간 `YYYY-MM-DD HH:mm` |
| `formatOffset(ms)` | `00:08`, 1시간이 넘으면 `1:02:03`. 초 아래는 버림 |
| `formatDuration(ms)` | `12초`, `3분 12초`, `1시간 2분 3초` |
| `recordingLengthMs(segments)` | 세그먼트 `endMs` 중 가장 큰 값. 문장이 없으면 0 |
| `SESSION_STATUS_LABELS` | `녹음 중`, `종료됨`, `중단됨 (서버가 꺼져 끊김)` |

서버의 `export/format.ts`는 이 함수들을 `@app/shared`에서 가져다 쓰고, 문장 한 줄 만들기(`oneLine`)와 txt·md 모양만 남깁니다. 내보내기 API의 응답은 한 글자도 바뀌지 않아야 합니다.

## 구현 순서

1. DB가 떠 있는지 확인하고 `main`에서 새 브랜치를 만듭니다. 서버를 켜고 지금의 내보내기 결과를 모든 세션에 대해 저장해 둡니다(5단계에서 비교).

    ```bash
    docker compose up -d --wait
    git switch -c feat/t16-history-screen
    ```

2. `packages/shared/src/format.ts`를 만들어 표시 함수를 옮기고 `index.ts`에서 내보냅니다. 서버 `export/format.ts`는 shared에서 가져오게 고칩니다.

3. 웹 API를 더합니다.
    - `client.ts`: `fetch`를 부르는 부분과 실패 응답을 `ApiError`로 바꾸는 부분을 함수로 묶어 `request`와 `requestFile`이 같이 씁니다. `requestFile`은 `{ filename, blob }`을 돌려줍니다.
    - `endpoints.ts`: `exportSession(id, format)`.

4. 화면을 만듭니다.
    - `DownloadButtons.tsx`: `EXPORT_FORMATS`마다 버튼 하나. 받은 Blob을 임시 링크로 저장합니다.
    - `HistoryListPage.tsx`, `HistoryDetailPage.tsx`: 위 '화면 동작'대로.

5. 확인하고 커밋합니다.

    ```bash
    npm run typecheck
    npm run build -w @app/web
    git add packages/shared/src apps/server/src apps/web/src docs/guides/T16.md
    git commit -m "feat: 히스토리 화면과 txt·md 다운로드 버튼 추가"
    ```

6. 기록을 남깁니다. `docs/logs/`의 그날 일지, `docs/project-overview.md`, 이 지침서의 '결과'를 채웁니다. `TODO.md`는 변경안을 사용자에게 먼저 보고한 뒤 허락을 받고 고칩니다.

## 완료 기준

'psql과 같음'은 `docker compose exec db psql -U user -d transcriber`로 같은 내용을 읽어 비교한다는 뜻입니다. 서버는 3000번, Vite 개발 서버는 5173번이고, 화면 확인은 5173번에서 합니다.

| 명령어·동작 | 기대 출력 |
| --- | --- |
| `npm run typecheck` | tsc 에러 없이 종료 코드 0 |
| `npm run build -w @app/web` | 빌드 성공 |
| 모든 세션의 내보내기(txt, md)를 1단계에서 저장한 것과 비교 | 모두 바이트까지 같음(`cmp`) |
| `/history` | `지난 녹음 N개`의 N이 목록 API 개수, psql의 '끝났고 문장이 있는 세션' 수와 같음. 첫 항목이 가장 최근 녹음 |
| 목록의 한 항목 | 시작 시각이 psql 한국 시간과 같음(분까지), 문장 수가 psql과 같음. 미리보기가 한 줄로 잘림 |
| 목록의 `interrupted` 세션 | 첫 줄 끝에 `중단됨 (서버가 꺼져 끊김)` |
| 항목을 누름 | `/history/<번호>`로 감 |
| 상세의 머리말 | 시작, 길이, 상태가 같은 세션 txt 파일의 머리말과 같음 |
| 상세의 문장 | 줄 수가 psql과 같고, 각 줄의 `[시각] 문장`이 txt 파일의 줄과 같음 |
| `txt 내려받기`, `md 내려받기` | 파일 이름 `session-<번호>.txt`, `.md`. 내용이 curl로 받은 것과 바이트까지 같음 |
| 문장이 없는 세션(#1) | `길이 0초`, `저장된 문장이 없습니다`, 내려받기 성공 |
| 녹음 중인 세션의 상세 | 버튼이 눌리지 않고 `녹음 중이라 아직 내려받을 수 없습니다`, 녹음 화면 링크 |
| 상세를 연 뒤 DB를 멈추고 내려받기 | `내려받지 못했습니다:`와 `503` 문구. DB를 켜고 다시 누르면 성공 |
| 상세를 연 뒤 서버를 끄고 내려받기 | `내려받지 못했습니다: 서버에 연결하지 못했습니다` |
| `/history/999999`, `/history/abc` | `404`, `400`의 문구 |
| 녹음 화면에서 시작하고 종료 | 상세로 가고, 저장된 문장이 보이고, 내려받기가 됨 |
| 브라우저 콘솔 | 에러 없음 |
| `git log --oneline -1` (코드 커밋 직후) | `feat: 히스토리 화면과 txt·md 다운로드 버튼 추가` |
