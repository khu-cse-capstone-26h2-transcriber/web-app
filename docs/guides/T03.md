# [T03] DB 스키마 v0와 마이그레이션 스크립트 — 지침서

2026-10-12 · 이광호

## 목표

`npm run db:migrate` 한 번으로 로컬 PostgreSQL에 세션 테이블과 세그먼트 테이블이 만들어집니다. 다시 실행하면 이미 적용한 파일은 건너뜁니다. 스키마를 바꿀 때는 번호를 붙인 SQL 파일을 하나 더 추가하면 됩니다.

## 배경과 전제, 범위

`CLAUDE.md`의 확정된 결정에 따라 DB는 PostgreSQL이고, `pg` 라이브러리로 직접 SQL을 쓰며 ORM을 쓰지 않습니다. 선행 작업은 T02(완료)입니다. `docker compose up -d`로 DB가 떠 있고 루트에 `.env`가 있어야 합니다.

세그먼트 테이블의 컬럼은 `SttEvent` **초안**을 따릅니다. 최종 형식은 D4 합의(T19, AI 파트 박지윤·하드웨어 파트 김범수)에서 확정하며, 형식이 바뀌면 마이그레이션 파일을 추가해 맞춥니다.

- 하는 것: `pg`와 `@types/pg` 설치, 스키마 v0 SQL 파일, 마이그레이션 실행 스크립트, `db:migrate` 명령어.
- 하지 않는 것: 연결 풀과 HTTP 서버(T04), 세션 API와 상태 전이(T06), 세그먼트를 저장하는 코드(T08), 히스토리 조회(T10), DB 행 타입을 `packages/shared`에 두는 일(쓰는 작업에서 추가), 단위 테스트(T17).

## 스키마 v0

`sessions` — 녹음 세션 하나가 한 행입니다.

| 컬럼 | 타입 | 뜻 |
| --- | --- | --- |
| `id` | `bigint`, 자동 증가, 기본 키 | 세션 번호 |
| `started_at` | `timestamptz`, 기본값 `now()` | 녹음을 시작한 시각 |
| `ended_at` | `timestamptz`, 비어 있을 수 있음 | 녹음을 끝낸 시각. 비어 있으면 아직 녹음 중 |

`segments` — final 이벤트 하나가 한 행입니다. partial은 저장하지 않습니다.

| 컬럼 | 타입 | 뜻 |
| --- | --- | --- |
| `session_id` | `bigint`, `sessions.id` 참조 | 속한 세션. 세션을 지우면 세그먼트도 함께 지워집니다 |
| `segment_id` | `integer` | `SttEvent.segmentId`. 세션 안에서 0부터 증가 |
| `text` | `text` | final의 전체 텍스트 |
| `start_ms` | `integer` | 세션 시작 기준 세그먼트 시작 시각(ms) |
| `end_ms` | `integer` | 세션 시작 기준 세그먼트 끝 시각(ms) |

기본 키는 `(session_id, segment_id)`입니다. 같은 세션에 같은 세그먼트 번호가 두 번 들어가지 않습니다.

`schema_migrations` — 실행 스크립트가 만들고 관리합니다. 적용한 파일 이름(`name`)과 적용 시각(`applied_at`)을 기록합니다.

## 구현 순서

1. `main`에서 새 브랜치를 만듭니다.

    ```bash
    git switch -c feat/t03-db-schema
    ```

2. 서버 워크스페이스에 `pg`와 타입을 설치합니다.

    ```bash
    npm install pg -w @app/server
    npm install -D @types/pg -w @app/server
    ```

3. `apps/server/migrations/001_init.sql`에 스키마 v0를 씁니다.

    ```sql
    -- 스키마 v0. 녹음 세션과, 세션에 속한 확정(final) 세그먼트를 저장한다.

    -- 녹음 세션. ended_at이 비어 있으면 아직 녹음 중이다.
    create table sessions (
      id bigint generated always as identity primary key,
      started_at timestamptz not null default now(),
      ended_at timestamptz
    );

    -- final 이벤트만 저장한다. 컬럼은 SttEvent 초안(D4 합의 전)의 필드를 따른다.
    create table segments (
      session_id bigint not null references sessions (id) on delete cascade,
      -- SttEvent.segmentId. 세션 안에서 0부터 증가한다.
      segment_id integer not null,
      text text not null,
      -- 세션 시작 기준 세그먼트 시작·끝 시각(ms)
      start_ms integer not null,
      end_ms integer not null,
      primary key (session_id, segment_id)
    );
    ```

4. `apps/server/src/db/migrate.ts`에 실행 스크립트를 씁니다. 파일 하나를 트랜잭션 하나로 실행하고, 적용한 파일 이름을 `schema_migrations`에 기록합니다.

    ```ts
    // 아직 적용하지 않은 마이그레이션 SQL 파일을 이름 순서대로 실행한다.
    import { readdir, readFile } from 'node:fs/promises';
    import { Client } from 'pg';
    import { loadEnv } from '../config/env';

    const MIGRATIONS_DIR = new URL('../../migrations/', import.meta.url);

    // 연결 거부는 메시지가 비어 있어 에러 코드로 알아본다.
    function describeError(error: unknown): string {
      if (!(error instanceof Error)) return String(error);
      if ((error as { code?: unknown }).code === 'ECONNREFUSED') {
        return 'DB에 연결하지 못했습니다. docker compose up -d로 DB가 떠 있는지 확인하세요';
      }
      return error.message || error.name;
    }

    const env = loadEnv();
    const client = new Client({ connectionString: env.dbUrl });

    try {
      await client.connect();

      // 적용한 파일 이름을 기록해 두어, 다시 실행해도 같은 파일을 두 번 적용하지 않는다.
      await client.query(`
        create table if not exists schema_migrations (
          name text primary key,
          applied_at timestamptz not null default now()
        )
      `);
      const { rows } = await client.query<{ name: string }>('select name from schema_migrations');
      const applied = new Set(rows.map((row) => row.name));

      const files = (await readdir(MIGRATIONS_DIR)).filter((file) => file.endsWith('.sql')).sort();
      let appliedCount = 0;

      for (const file of files) {
        if (applied.has(file)) {
          console.log(`[migrate] skip  ${file}`);
          continue;
        }

        const sql = await readFile(new URL(file, MIGRATIONS_DIR), 'utf8');
        // 파일 하나를 트랜잭션 하나로 실행한다. 중간에 실패하면 그 파일은 전부 취소된다.
        await client.query('begin');
        try {
          await client.query(sql);
          await client.query('insert into schema_migrations (name) values ($1)', [file]);
          await client.query('commit');
        } catch (error) {
          await client.query('rollback');
          throw new Error(`${file}: ${describeError(error)}`);
        }

        console.log(`[migrate] apply ${file}`);
        appliedCount += 1;
      }

      console.log(`[migrate] done - 새로 적용 ${appliedCount}개, 전체 ${files.length}개`);
    } catch (error) {
      console.error(`[migrate] 실패: ${describeError(error)}`);
      process.exitCode = 1;
    } finally {
      await client.end();
    }
    ```

5. 실행 명령어를 추가합니다.

    - `apps/server/package.json`의 `scripts`에 `"db:migrate": "tsx --env-file=../../.env src/db/migrate.ts"`를 추가합니다.
    - 루트 `package.json`의 `scripts`에 `"db:migrate": "npm run db:migrate -w @app/server"`를 추가합니다.

6. 동작을 확인하고 커밋합니다. push와 `main` 병합은 사용자가 따로 지시할 때 합니다.

    ```bash
    npm run typecheck
    npm run db:migrate
    npm run db:migrate
    docker compose exec db psql -U user -d transcriber -c '\dt'
    docker compose exec db psql -U user -d transcriber -c '\d segments'
    DB_URL=postgres://user:password@localhost:5999/transcriber npm run db:migrate
    npm run dev:server
    npm run dev:stt
    git add -A
    git commit -m "feat: DB 스키마 v0와 마이그레이션 스크립트 추가"
    ```

7. 기록을 남깁니다. `docs/logs/2026-10-12.md`에 단계별 상태를 적고, `TODO.md`는 변경안을 사용자에게 먼저 보고한 뒤 허락을 받고 고칩니다. 이 지침서 맨 아래 '결과'도 채웁니다.

## 마이그레이션 규칙

- 스키마를 바꿀 때는 `apps/server/migrations/`에 다음 번호의 파일(`002_….sql`)을 추가합니다. 파일은 이름 순서대로 실행됩니다.
- 이미 적용한 파일은 고치지 않습니다. 고쳐도 다시 실행되지 않아, DB와 파일이 달라집니다.
- 로컬 DB를 처음부터 다시 만들려면 `docker compose down -v`로 데이터를 지우고 `docker compose up -d`, `npm run db:migrate`를 차례로 실행합니다. **저장한 데이터가 모두 지워집니다.**

## 결정 사항과 남은 질문

- 이미 정한 것: PostgreSQL, `pg`로 직접 SQL(ORM 없음), 위 '착수 전 확인'의 다섯 가지.
- 이 지침서에서 정한 것:
  - 마이그레이션 파일은 `apps/server/migrations/`에 두고, 적용 기록 테이블 이름은 `schema_migrations`입니다.
  - 세션을 지우면 세그먼트도 함께 지워집니다(`on delete cascade`). 세션 삭제 기능은 아직 작업 목록에 없습니다.
  - 세그먼트에는 `not null`, 기본 키, 외래 키 외의 제약(예: `end_ms >= start_ms`)을 두지 않습니다. 실제 STT가 내는 값의 범위를 아직 모릅니다.
  - `db:migrate`는 `loadEnv()`를 그대로 써서 `PORT`, `STT_URL`도 있어야 실행됩니다.
- 아직 정해야 하는 것:
  - STT 이벤트의 최종 형식(D4, AI·하드웨어 파트 협의). 바뀌면 `segments`를 고치는 마이그레이션을 추가합니다.
  - 세션 상태(T06). 상태 전이를 정할 때 `status` 컬럼이 필요하면 마이그레이션으로 추가합니다.
  - SQLite 전환 여부(D8, 기기 실측 후). `001_init.sql`은 PostgreSQL 문법(`generated always as identity`, `timestamptz`)을 쓰므로, 전환하면 SQL 파일과 실행 스크립트의 DB 클라이언트를 고쳐야 합니다.
