# [T12] 웹앱 뼈대(React, 라우팅, API 클라이언트) — 지침서

2026-10-19 · 이광호

## 목표

`npm run dev:web`으로 React 웹앱을 띄우면 녹음(`/`), 히스토리 목록(`/history`), 히스토리 상세(`/history/:id`) 세 화면 사이를 오갈 수 있습니다. 화면은 서버 API를 같은 출처의 경로(`/api/…`, `/health`)로 부르고, 개발 중에는 Vite 개발 서버가 그 요청을 Express로 넘깁니다. T13(녹음 제어), T14(실시간 화면), T16(히스토리 화면)이 이 뼈대 위에 화면을 채웁니다.

## 배경과 전제, 범위

선행 작업은 T01(모노레포)이고 끝났습니다. 서버 쪽은 T10까지 끝나 있어 `/health`, 히스토리 목록·상세 API를 화면에서 바로 불러 볼 수 있습니다. 실행 전에 Docker Desktop이 켜져 있고 `docker compose up -d`로 DB가 떠 있어야 하며, 루트 `.env`가 있어야 합니다.

이 지침서는 T06~T10과 같이 구현과 같은 세션에서 썼습니다. 코드 전문은 싣지 않습니다. 코드는 저장소의 파일(커밋 `ffc04e1`)이 기준이고, 여기에는 결정과 동작, 확인 방법을 적습니다.

- 하는 것: Vite, React, React Router 설치와 설정, 화면 주소 3개와 없는 주소 화면, 공통 틀(메뉴, 서버 상태), `fetch` 래퍼와 API 함수, 개발 서버 프록시, `dev:web` 명령어.
- 하지 않는 것: 녹음 시작·종료 버튼과 API 함수(T13), 실시간 자막과 SSE 클라이언트(T14), 끊김 배너(T15), 히스토리 화면 구성과 다운로드(T16, T11), 디자인과 스타일 라이브러리, 웹앱 테스트(T17은 핵심 로직만), 기기에서 빌드 결과를 내보내는 방법.

## 화면과 API 클라이언트

| 주소 | 화면 | 내용 |
| --- | --- | --- |
| `/` | 녹음 (`RecordPage`) | 자리만 있음. T13·T14가 채웁니다 |
| `/history` | 히스토리 목록 (`HistoryListPage`) | `GET /api/sessions` 결과를 번호, 시작 시각, 세그먼트 개수, 미리보기로 한 줄씩. 번호를 누르면 상세로 |
| `/history/:id` | 히스토리 상세 (`HistoryDetailPage`) | `GET /api/sessions/:id`로 상태, 시작 시각, 세그먼트 개수. 실패하면 서버의 `message` |
| 그 밖 | 없는 주소 (`NotFoundPage`) | '페이지를 찾을 수 없습니다'와 녹음 화면 링크 |

모든 화면은 `Layout` 안에 그립니다. 위쪽에 앱 이름, 메뉴(녹음, 히스토리), 서버 상태가 있습니다. 서버 상태는 웹앱을 열 때 `/health`를 한 번 부른 결과입니다.

| 상황 | 서버 상태 | 히스토리 목록 |
| --- | --- | --- |
| 서버와 DB가 정상 | `서버: 정상` | 목록 |
| DB가 꺼짐 | `서버: DB에 연결하지 못했습니다` (`503` `DB_UNAVAILABLE`) | `서버에서 오류가 발생했습니다` (`500` `INTERNAL_ERROR`) |
| 서버가 꺼짐 | `서버: 서버에 연결하지 못했습니다` | 같은 문구 |

API 클라이언트는 세 파일입니다.

| 파일 | 내용 |
| --- | --- |
| `api/client.ts` | `request<T>(path, init)`: JSON 응답을 `T`로 돌려줍니다. 실패하면 `ApiError(status, code, message)`를 던집니다. 서버가 보낸 `{ error: { code, message } }`는 그대로 담고, `fetch` 자체가 실패하거나 프록시가 JSON 없이 `502`를 주면 `NETWORK_ERROR`, 그 밖에 JSON이 아닌 응답은 `UNEXPECTED_RESPONSE`입니다. 취소(`signal`)는 바꾸지 않고 그대로 던집니다 |
| `api/endpoints.ts` | `getHealth`, `listSessions`, `getSession(id)`. 응답 타입은 `@app/shared`의 `SessionSummary`, `Session`, `Segment`이고, 감싸는 모양(`Health`, `SessionDetail`)은 이 파일에 둡니다 |
| `api/useApiData.ts` | `useApiData(load, deps)`: `loading`, `success`(`data`), `error`(`error: ApiError`) 중 하나를 돌려줍니다. `deps`가 바뀌거나 화면을 떠나면 이전 요청을 취소합니다 |

## 구현 순서

1. Docker Desktop을 켜고 DB를 띄운 뒤 `main`에서 새 브랜치를 만듭니다.

    ```bash
    docker compose up -d --wait
    git switch -c feat/t12-web-skeleton
    ```

2. 웹 워크스페이스에 패키지를 설치합니다. React Router는 7.x를 씁니다(아래 '결정 사항' 참고).

    ```bash
    npm install -w @app/web react@^19.3.1 react-dom@^19.3.1 react-router@^7.18.4
    npm install -w @app/web -D @types/react@^19.3.0 @types/react-dom@^19.3.0
    npm install -w @app/web -D vite@^8.3.4 @vitejs/plugin-react@^6.1.2 --legacy-peer-deps
    npm install   # 옵션 없이 다시 돌려도 통과하는지 확인
    ```

    마지막 설치를 `--legacy-peer-deps` 없이 하면 npm 10.8.2가 `Cannot read properties of null (reading 'edgesOut')`로 멈춥니다. Vite의 선택적 peer 의존성을 따라가다 생기는 npm 버그입니다. 이 옵션은 이번 설치에만 쓰고 `.npmrc`에는 넣지 않습니다.

3. `apps/web`에 `index.html`, `vite.config.ts`, `tsconfig.json`(src, `jsx: react-jsx`, DOM, `types: ["vite/client"]`), `tsconfig.node.json`(vite.config.ts, `types: ["node"]`)을 둡니다. 브라우저 코드에서 `process` 같은 Node 타입이 보이지 않도록 둘을 나눕니다.

4. `vite.config.ts`는 루트 `.env`의 `PORT`를 `loadEnv`로 읽어 `/api`와 `/health`를 `http://localhost:${PORT}`로 넘깁니다. 개발 서버(`server.proxy`)와 미리보기(`preview.proxy`)에 같이 둡니다. `PORT`가 없으면 에러를 던집니다.

5. `src/api/`에 `client.ts`, `endpoints.ts`, `useApiData.ts`를, `src/components/Layout.tsx`와 `src/pages/` 네 화면, `src/router.tsx`(`createBrowserRouter`), `src/main.tsx`(`StrictMode`, `RouterProvider`)를 작성하고 `src/index.ts`를 지웁니다.

6. 스크립트를 연결합니다. 웹은 `dev: vite`, `build: vite build`, `preview: vite preview`. 루트는 `dev:web`을 더하고, `typecheck`에 `tsc --noEmit -p apps/web/tsconfig.node.json`을 더합니다.

7. 동작을 확인하고 커밋합니다. push와 `main` 병합은 사용자가 따로 지시할 때 합니다.

    ```bash
    npm run typecheck
    npm run build -w @app/web
    npm run dev:server   # 다른 터미널
    npm run dev:web      # http://localhost:5173
    git add package.json package-lock.json apps/web
    git commit -m "feat: 웹앱 뼈대(Vite, React Router, API 클라이언트) 추가"
    ```

8. 기록을 남깁니다. `docs/logs/`의 그날 일지, `docs/project-overview.md`, 이 지침서의 '결과'를 채웁니다. `TODO.md`는 변경안을 사용자에게 먼저 보고한 뒤 허락을 받고 고칩니다.

## 결정 사항과 남은 질문

- 이미 정한 것: 위 '착수 전 확인'의 다섯 가지, 서버의 응답 모양과 에러 형식(T04, T06, T10), 서버 포트는 루트 `.env`의 `PORT`(T02).
- 이 지침서에서 정한 것:
  - **React Router는 7.x(7.18.4)입니다.** 최신 8.4.0은 Node 22.22 이상을 요구하고 이 프로젝트는 Node 20입니다. 7.x는 8.x와 같은 날(2026-09-15)까지 새 판이 나와 유지되고 있습니다. Node를 올리면 8.x로 옮길 수 있습니다.
  - **Vite와 플러그인만 `--legacy-peer-deps`로 설치했습니다.** npm 10.8.2의 버그를 피하기 위해서입니다. 둘의 peer 의존성 중 필수는 `vite` 하나뿐이고 직접 설치했으므로 빠진 것은 없습니다. 옵션 없는 `npm install`과 `npm ci`는 통과합니다.
  - **화면 주소는 `/`, `/history`, `/history/:id`입니다.** 녹음이 첫 화면입니다. API의 `/api/sessions`와 겹치지 않게 화면은 '히스토리'로 부릅니다.
  - **`/health`도 프록시로 넘깁니다.** 서버에서 `/api` 밖에 있기 때문입니다.
  - **데이터는 라우터의 loader가 아니라 `useApiData` 훅으로 불러옵니다.** T14의 SSE도 effect로 다룰 것이라 한 가지 방식으로 맞췄습니다. `createBrowserRouter`를 쓰므로 나중에 loader로 바꿀 수 있습니다.
  - **응답을 감싸는 타입(`Health`, `SessionDetail`)은 웹에 둡니다.** 서버는 이 모양을 이름 있는 타입 없이 바로 만들고 있어 '같은 타입을 두 곳에 복사'한 것은 아닙니다. 서버도 타입으로 쓰게 되면 `packages/shared`로 옮깁니다.
  - **프록시가 JSON 없이 주는 `502`는 `NETWORK_ERROR`로 봅니다.** 개발 중 서버가 꺼졌을 때와, 배포 후 같은 출처에서 서버가 꺼졌을 때(`fetch` 실패) 같은 문구가 나옵니다.
  - **서버 상태는 웹앱을 열 때 한 번만 확인합니다.** 주기적인 확인과 끊김 배너는 T15입니다.
  - **개발 모드에서는 `StrictMode` 때문에 화면이 처음 뜰 때 요청이 두 번 갑니다.** 첫 요청은 바로 취소됩니다. 빌드 결과에서는 한 번입니다.
  - **스타일은 `index.html`의 몇 줄(폭, 글꼴)과 헤더의 인라인 스타일뿐입니다.**
- 아직 정해야 하는 것:
  - 기기(Rubik Pi)에서 빌드 결과를 누가 내보낼지. Express가 `apps/web/dist`를 정적 파일로 내보내면 지금처럼 같은 출처가 됩니다. 서버 listen 주소(D5)와 함께 정합니다.
  - 노트북의 웹앱이 기기의 서버를 부르는 개발 방식이 필요해지면, 프록시 대상 주소를 `PORT` 대신 따로 받을 환경변수.
  - 세션 API가 DB가 꺼졌을 때 `500` 대신 `503`을 낼지 (T13 전, T06에서 넘어옴).
  - 서버가 강제로 꺼진 세션의 `ended_at` 보정 (T16 전, T06에서 넘어옴).
