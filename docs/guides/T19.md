# [T19] STT 연동 인터페이스 합의와 문서화 — 지침서 (초안)

2026-11-03 · 이광호

> 상태: 초안입니다. 아래 '제안'은 앱 파트의 안이고, 박지윤(AI)·김범수(하드웨어)와 합의하기 전에는 구현하지 않습니다.

## 목표

D4(STT 호출 방법, 오디오 입력 형식, partial/final 이벤트 형식)를 AI·하드웨어 파트와 합의하고 문서로 남깁니다. 끝나면 T20을 추측 없이 시작할 수 있고, 데몬과 엔진에서 고칠 일의 담당이 정해져 있습니다.

## 배경과 전제, 범위

`audio-stack` `f47fbce`와 `web-app` `831382b`의 코드를 2026-11-03에 읽어 확인한 내용입니다. 데몬과 엔진을 실행해 본 것은 아닙니다. 서버와 다른 점 전체는 [2026-11-02 일지](../logs/2026-11-02.md)에 있습니다.

- **기본 설정 그대로는 붙지 않습니다.** 데몬의 `POST /api/sessions`는 웹 버튼과 같은 경로라 서버가 mock 세션을 켜고, 이어지는 `/transcripts`와 `/end`는 서버에 없는 경로입니다.
- **2xx가 아닌 응답은 대기열을 막습니다.** 데몬은 2xx가 아니면 그 항목을 맨 앞에 되돌려 3초 뒤 다시 보냅니다(`src/daemon.cpp:162-173`, `http_client.hpp:26`). 서버가 `404`처럼 다시 보내도 같은 응답을 주면 뒤의 결과가 전부 멈춥니다. 대기열이 가득 차 되돌리지 못한 항목은 `dropped`에 세지 않고 사라집니다.
- **데몬에는 녹음하지 않는 상태가 없습니다.** 켜면 바로 세션을 열고(`src/daemon.cpp:335-336`), 제어 명령은 지금 세션을 닫고 곧바로 새로 여는 `session rotate`뿐입니다.
- **정지 명령만 더하면 마지막 문장이 깨집니다.** `Session::end()`가 세션 번호를 지우고(`session.hpp`), 결과에는 받은 시점의 번호를 붙입니다(`src/daemon.cpp:474-479`). `rotate`에서는 늦은 final이 새 세션으로 가고, 번호를 지운 채 멈추면 빈 번호로 갑니다.
- **엔진은 데몬을 고치지 않고 필드를 더할 수 있습니다.** `send_result`의 `extra`와 `session_id`는 `transcript` 안에 들어가고(`client/astk_client.py:180-183`), 데몬은 이 JSON을 읽지 않고 넘깁니다.
- **`audio_t_us`는 오디오 시각이 아닙니다.** 엔진이 결과를 보낸 시각입니다(`client/astk_client.py:158`, `src/daemon.cpp:477`). `received_at`은 초 단위입니다. 둘 다 시각 계산에 쓰지 않습니다.
- **물리 버튼을 읽는 코드가 데몬에 없습니다.** `audio-stack` 문서는 버튼이 `session rotate`를 부른다고만 적고 있고, 누가 GPIO를 읽는지는 정해지지 않았습니다.

범위는 다음과 같습니다.

- 하는 것: 합의 항목을 들고 협의, 합의 문서 작성, `docs/d4-stt-questions.md` 답 칸 채우기, `docs/project-overview.md`와 `packages/shared/src/stt.ts`의 '초안' 문구 정리.
- 하지 않는 것: 수신 경로와 어댑터 구현, 마이그레이션, WAV 재생 스크립트(T20), `ctrl.sock` 연결(T27), 데몬·엔진 코드 수정(각 파트 담당), 기기 작업(T21, T26).

## 제안

### 구조

```text
물리 버튼 ─────────────┐
웹 버튼 → 서버 ─ctrl.sock┴→ audiostackd ─AUDIO→ 엔진
                            audiostackd ←RESULT─ 엔진
웹앱 ←SSE─ 서버 ←HTTP POST─ audiostackd
```

`SttEvent`의 다섯 필드는 바꾸지 않습니다. 그래서 SSE, 이어받기, DB의 `segments`, 히스토리, 내보내기, 웹 화면은 그대로입니다. 바뀌는 곳은 서버의 수신 경로, `sessions` 열 하나, 어댑터입니다.

### 수신 경로

```ini
[backend]
session_path = /api/device/sessions
transcript_path = /api/device/sessions/{session}/transcripts
end_path = /api/device/sessions/{session}/end
```

서버는 항상 2xx나 `503`으로 답합니다. 4xx로 답하면 데몬 대기열이 막히기 때문입니다.

| 상황 | 응답 | 처리 |
| --- | --- | --- |
| 정상 처리 | `201`, `202`, `200` | 데몬 문서의 예시와 같습니다 |
| DB에 닿지 못해 세션을 만들거나 닫지 못함 | `503` | 데몬이 다시 보내고, 순서는 유지됩니다 |
| 모르는 세션, 닫힌 세션, 중복 `seq`, 모르는 `type`, 빈 `text` | `202` | 버리고 서버 로그를 남깁니다 |
| 다른 세션이 진행 중일 때 새 세션 통지 | `201` | 앞 세션을 `interrupted`로 닫고 새 세션을 받습니다 |
| 같은 번호의 세션 통지가 다시 옴 | `201` | 재전송이나 웹 버튼 뒤의 통지입니다. 무시합니다 |
| 서버가 다시 켜진 뒤 그 세션의 결과가 옴 | `202` | 세션은 이미 `interrupted`입니다. 다음 세션부터 다시 받습니다 |

잘못된 JSON은 `express.json()`이 `400`으로 답합니다. 엔진이 `json.dumps`를 쓰는 동안은 일어나기 어렵고, 아래 데몬 수정으로 막습니다.

### 결과를 `SttEvent`로 바꾸는 규칙

| 필드 | 값 |
| --- | --- |
| `type` | `transcript.type`. 없으면 `final`(데몬 문서의 규칙) |
| `segmentId` | 서버가 세션별로 0부터 셉니다. partial은 지금 번호, final은 지금 번호를 쓴 뒤 1 올립니다 |
| `text` | `transcript.text`. 누적이어야 합니다(E2 확인 필요). 추가분이면 서버가 이어 붙입니다 |
| `startMs` | `t_start_ms`가 있으면 그 값. 없으면 그 세그먼트의 첫 partial을 받은 시각, partial이 없었으면 직전 세그먼트의 `endMs`. 세그먼트 안에서 바뀌지 않습니다 |
| `endMs` | `t_end_ms`가 있으면 그 값. 없으면 받은 시각 |

- 엔진 값은 세션 시작 기준 밀리초로 요청합니다. 지금 프로토콜은 'segment-relative'라고만 적혀 있어 기준을 확인해야 합니다. `SESSION_BEGIN` 뒤 받은 오디오 길이로 계산할 수 있습니다.
- 서버가 채우는 시각의 기준(0)은 세션 통지를 받은 서버 시각입니다. 인식 지연만큼 늦게 찍힙니다.
- 재전송 중복은 `seq`로 거릅니다. 세션별로 마지막 `seq`를 기억하고 그 이하는 버립니다. `seq`는 데몬이 켜진 뒤 계속 늘어나는 값이라 세션마다 1로 돌아가지 않습니다.
- `lang`, `conf`는 저장하지 않습니다. 저장할 열이 없고 화자·신뢰도는 확장 기능입니다.

### 시작과 종료

시작:

1. 물리 버튼이나 서버가 데몬에 `session start`를 보냅니다.
2. 데몬이 세션 번호를 만들어 서버에 알리고, 엔진에 `SESSION_BEGIN`을 보냅니다.
3. 서버가 `sessions` 행을 만들고 진행 중인 세션으로 둡니다.

종료:

1. 물리 버튼이나 서버가 데몬에 `session stop`을 보냅니다.
2. 데몬이 오디오 전달을 멈추고 엔진에 `SESSION_END`를 보냅니다. 세션 번호는 아직 지우지 않습니다.
3. 엔진이 남은 구간을 final로 내고 끝났다는 신호를 보냅니다.
4. 데몬이 신호를 받거나 제한 시간(제안 5초, 엔진 최대 지연 2.95초 기준)이 지나면 `/end`를 보내고 번호를 지웁니다.
5. 서버가 세그먼트를 모두 쓰고 세션을 닫은 뒤 `ended`를 보냅니다.

데몬의 전달 대기열은 순서를 지키므로 서버는 따로 기다리지 않아도 됩니다. `session rotate`도 같은 순서를 거친 뒤 새 세션을 엽니다.

웹 버튼은 서버가 `ctrl.sock`에 같은 명령을 보냅니다. 서버는 응답 `OK sess-…`의 번호로 세션을 먼저 만들고, 뒤에 온 통지는 같은 번호라 무시합니다. 그래서 `POST /api/sessions`와 `/stop`의 응답 형식은 그대로입니다.
