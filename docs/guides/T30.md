# [T30] Rubik Pi 초기 설정: OS 확인, 네트워크, SSH, 시간 — 지침서

2026-11-10 · 이광호

## 목표

Rubik Pi 3를 앱 서버를 올릴 수 있는 상태로 만듭니다. 끝나면 아래가 모두 됩니다.

1. 보드에 Ubuntu 24.04(arm64)가 있고, 내 비밀번호로 로그인됩니다.
2. Mac 터미널에서 `ssh rubikpi`로 비밀번호 없이 접속됩니다. 재부팅한 뒤에도 그대로 됩니다.
3. Mac에서 보드의 포트(시험용 8080)에 HTTP로 접속됩니다. 나중에 웹앱이 쓰는 경로입니다.
4. 보드 시계가 한국 시간이고 NTP로 맞춰져 있습니다.
5. 아무것도 설치하지 않은 상태의 메모리·디스크·CPU 기준값이 기록되어 있습니다(T21 측정과 비교).

## 배경과 전제, 범위

- 기기는 사용자가 보관하고, OS는 Ubuntu 24.04로 정했습니다(2026-11-10 사용자 결정). AI 파트가 측정한 보드도 Ubuntu 24.04입니다(2026-11-09).
- 이 보드를 AI 파트가 썼다면 `~/rubikpi/`(엔진 `runner/`, 모델 `bins/`, QNN 런타임 `sdk250/`)가 있을 수 있습니다. QNN 런타임은 `stt-engine` 저장소에 없고 Qualcomm QNN SDK 2.50에서 따로 받아야 합니다(`stt-engine` `README.md` '저장소에 없는 것'). **OS를 다시 설치하면 이 파일이 모두 지워집니다.** 그래서 지우기 전에 상태를 먼저 확인합니다.
- 서버에 로그인이 없으므로 믿을 수 있는 네트워크에서만 씁니다(`TODO.md` 'T21 준비').
- 공식 절차는 Thundercomm RUBIK Pi 3 사용자 매뉴얼 1.0.0-u(Ubuntu)를 따릅니다. 2026-11-10에 확인했습니다.
  - [Setup your device](https://www.thundercomm.com/rubik-pi-3/en/docs/rubik-pi-3-user-manual/1.0.0-u/set-up-your-device): 전원 12 V 3 A PD 3.0, Micro-USB 디버그 UART 115200, 기본 계정 `ubuntu`/`ubuntu`(첫 로그인 때 비밀번호 변경), `nmcli`로 Wi-Fi, EDL 진입 방법
  - [Reset to Factory Ubuntu Image](https://www.thundercomm.com/rubik-pi-3/en/docs/rubik-pi-3-user-manual/1.0.0-u/Troubleshooting/11.2.Reset-system-image): macOS에서 QDL로 Canonical Ubuntu 24.04 서버 이미지 설치. 기기 데이터가 모두 지워짐
- 보드 콘솔(1~6단계)은 사용자가 직접 입력합니다. SSH가 되면(7단계 뒤) Claude가 Mac에서 `ssh rubikpi`로 확인 명령을 실행합니다. 비밀번호와 Wi-Fi 암호는 사용자만 입력하고 문서에 적지 않습니다.

- 하는 것: 보드 상태 확인, (필요할 때만) OS 다시 설치, 비밀번호 변경, 네트워크, 호스트 이름과 `rubikpi.local`, 시간대, 패키지 업데이트, Mac의 SSH 키와 `~/.ssh/config`, 재부팅·포트 시험, 기준값 기록.
- 하지 않는 것: Node·PostgreSQL·이 저장소 설치(T21), 웹앱 제공 방법 결정(T21 착수 전), QNN·엔진·모델·`audio-stack` 설치(T26), 마이크와 ALSA 설정(T27), Thundercomm `install_ppa_pkgs.sh`(QNN 패키지와 `apt upgrade`를 함께 함. AI 파트의 QNN 2.50과 겹칠 수 있어 T26에서 AI 파트와 정함), 방화벽(`ufw`)과 SSH 비밀번호 로그인 끄기, 저장소 코드 변경.

## 준비물

| 물건 | 용도 | 확인할 것 |
| --- | --- | --- |
| USB-C 전원 어댑터 12 V 3 A, PD 3.0 | 전원 | 맞으면 전원 단자 옆 LED가 켜집니다. 안 켜지면 어댑터가 12 V를 못 내는 것입니다(맥북 충전기는 12 V 단계가 없어 대개 켜지지 않음) |
| Micro-USB 데이터 케이블 | 디버그 콘솔(UART) | 충전 전용 케이블이면 Mac에 장치가 생기지 않습니다 |
| USB-C 데이터 케이블 | OS 다시 설치(3단계)할 때만 | |
| 네트워크 | 5단계 | Mac과 보드가 같은 네트워크에 붙어야 합니다 |
| HDMI 모니터·키보드 | 없어도 됨 | 콘솔로 대신합니다 |

Mac에는 `screen`, `ssh-copy-id`가 이미 있습니다(2026-11-10 확인, macOS 27.2).

## 진행 순서

### 1단계. 전원과 디버그 콘솔

1. Mac 터미널에서 `ls /dev/cu.*`를 실행해 지금 목록을 봅니다.
2. Micro-USB 케이블로 보드와 Mac을 잇고, 전원 어댑터를 꽂습니다. 보드 판이 V02 이상이면 전원을 꽂으면 저절로 켜집니다.
3. 다시 `ls /dev/cu.*`를 실행해 새로 생긴 장치(예: `/dev/cu.usbserial-XXXX`)를 찾습니다.
4. `screen /dev/cu.usbserial-XXXX 115200`을 실행하고 Enter를 누릅니다.

- 확인: `login:` 프롬프트가 나옵니다. 부팅 중이면 부팅 메시지가 흐른 뒤 나옵니다.
- `screen`에서 나가기: `Ctrl-A`, `K`, `y`.
- 파란 LED가 계속 켜져 있으면 전원 버튼을 너무 오래 눌러 fastboot 상태입니다(매뉴얼 FAQ).

### 2단계. 지금 상태 확인 (아무것도 바꾸지 않음)

`ubuntu` / `ubuntu`로 로그인합니다. 이미 다른 비밀번호로 바뀌어 있으면 멈추고 박지윤·김범수에게 비밀번호를 물어봅니다.

```bash
cat /etc/os-release
uname -m
uname -r
ls -la ~ ; ls ~/rubikpi 2>/dev/null
df -h /
free -h
```

#### 2단계 판단 표

| 결과 | 다음 |
| --- | --- |
| `VERSION_ID="24.04"`, `aarch64`, 로그인 됨, `~/rubikpi` 없음 | 3단계 건너뜀. 6단계에서 `full-upgrade` |
| 위와 같고 `~/rubikpi` 있음 | 3단계 건너뜀. AI 파트 파일은 그대로 두고, 6단계에서 업그레이드 범위를 줄임 |
| 24.04가 아님(Android, Qualcomm Linux 등), 로그인 안 됨, 비밀번호를 아무도 모름 | 3단계(다시 설치). `~/rubikpi`가 있었다면 박지윤에게 먼저 확인 |

결과는 일지에 적습니다.

### 3단계. (필요할 때만) Ubuntu 24.04 다시 설치

**기기 데이터가 모두 지워집니다.** 2단계 판단 표가 다시 설치를 가리키고, 사용자가 정한 뒤에만 합니다. 공식 [Reset to Factory Ubuntu Image](https://www.thundercomm.com/rubik-pi-3/en/docs/rubik-pi-3-user-manual/1.0.0-u/Troubleshooting/11.2.Reset-system-image)의 'macOS host'를 따릅니다.

1. Mac에 `brew install libusb libxml2`.
2. 새 빈 폴더에 아래를 받습니다(2026-11-10 매뉴얼에 걸린 링크).
   - QDL 도구: [Qualcomm Software Center](https://softwarecenter.qualcomm.com/catalog/item/Qualcomm_Device_Loader) (로그인이 필요할 수 있음)
   - 서버 이미지: `https://people.canonical.com/~platform/images/qualcomm-iot/rubikpi3/ubuntu-server-24.04/x00/ubuntu-24.04-preinstalled-server-arm64+rubikpi3-20250912-127.img.xz`
   - `dtb.bin`, `rawprogram0.xml`: 같은 폴더(`.../ubuntu-server-24.04/x00/`)
   - 부트 펌웨어: `https://thundercomm.s3.dualstack.ap-northeast-1.amazonaws.com/uploads/web/rubik-pi-3/nhlos-bins/QLI.1.4-ubuntu-rubikpi3-nhlos-bins-20250912-127.tar.gz`
3. 부트 펌웨어를 풀고, 그 폴더에 이미지(`.xz`를 푼 것), `dtb.bin`, `rawprogram0.xml`, QDL 실행 파일을 넣습니다.
4. EDL 모드로 들어갑니다. 전원과 USB-C를 뺀 뒤, EDL 버튼을 누른 채로 전원을 꽂고, 계속 누른 채로 USB-C를 Mac에 꽂고 3초 기다린 뒤 버튼을 뗍니다. Ubuntu가 이미 돌고 있으면 `sudo reboot edl`로도 됩니다.
5. 확인: `system_profiler SPUSBHostDataType | grep -i 9008`에 장치가 보입니다.
6. 그 폴더에서 `./qdl prog_firehose_ddr.elf rawprogram*.xml patch*.xml`.
7. 확인: `qdl`이 오류 없이 끝나고, 보드가 다시 켜져 1단계의 콘솔에 `login:`이 나옵니다. 실패하면 전원과 USB를 뺐다 꽂고 4단계부터 다시 합니다.

### 4단계. 첫 로그인과 비밀번호

1. `ubuntu` / `ubuntu`로 로그인하면 비밀번호를 바꾸라고 나옵니다. 새 비밀번호를 정합니다.
2. 확인: `exit`로 나갔다가 새 비밀번호로 다시 로그인됩니다.

새로 설치한 직후에는 첫 부팅 설정(cloud-init)과 자동 업데이트가 몇 분 돌 수 있습니다. 6단계에서 `Could not get lock` 오류가 나면 몇 분 기다렸다 다시 합니다.

### 5단계. 네트워크

Wi-Fi(암호는 화면에서 물어봄. 명령 기록에 남지 않음):

```bash
nmcli dev wifi list
sudo nmcli --ask dev wifi connect "<SSID>"
```

랜선이면 꽂기만 합니다.

- 확인 (보드): `ip -4 -br addr`에 `wlan0`(또는 유선 단자)의 IP가 보입니다. `ping -c 3 8.8.8.8`과 `ping -c 3 archive.ubuntu.com`이 모두 응답합니다(두 번째는 DNS 확인).
- 확인 (Mac): `ping -c 3 <보드 IP>`가 응답합니다. 응답이 없으면 그 네트워크가 기기 사이 통신을 막는 것이니 다른 네트워크로 바꿉니다.

### 6단계. 이름, 시간, 업데이트

```bash
sudo hostnamectl set-hostname rubikpi
sudo timedatectl set-timezone Asia/Seoul
sudo apt update
sudo apt full-upgrade -y          # ~/rubikpi가 있으면 박지윤 확인 전까지 이 줄은 건너뜀
sudo apt install -y avahi-daemon
```

- 확인 (보드): `hostname`이 `rubikpi`. `timedatectl`에 `Time zone: Asia/Seoul`과 `System clock synchronized: yes`. `date`가 Mac 시각과 몇 초 안으로 같음.
- 확인 (Mac): `ping -c 3 rubikpi.local`이 응답합니다. 안 되면 7단계의 `HostName`에 IP를 씁니다(IP가 바뀌면 고쳐야 함).
- `full-upgrade`로 커널이 바뀌었으면 `sudo reboot` 한 번 하고 1단계 콘솔에서 다시 로그인합니다.

### 7단계. SSH 키 로그인 (Mac에서)

```bash
ssh-keygen -t ed25519            # 지금 키가 없음. 암호 문구는 사용자가 정함
ssh-copy-id ubuntu@rubikpi.local # 보드 비밀번호를 한 번 물어봄
```

`~/.ssh/config`에 추가합니다(파일이 없으면 새로 만듦).

```text
Host rubikpi
  HostName rubikpi.local
  User ubuntu
  IdentityFile ~/.ssh/id_ed25519
```

- 확인: `ssh rubikpi 'hostname; uptime'`이 보드 비밀번호를 묻지 않고 `rubikpi`와 가동 시간을 출력합니다. 이 단계부터는 Claude가 Mac에서 확인 명령을 실행할 수 있습니다.

### 8단계. 재부팅과 포트 시험

1. 사용자가 `ssh -t rubikpi sudo reboot`(또는 콘솔에서 `sudo reboot`)를 실행하고 1~2분 기다립니다.
2. 확인: 랜선이나 Wi-Fi를 다시 손대지 않아도 `ssh rubikpi`가 됩니다. `hostname`이 `rubikpi`로 남아 있습니다.
3. 포트 시험(Claude가 Mac에서 실행):

```bash
ssh rubikpi 'mkdir -p /tmp/t30-empty && (nohup timeout 30 python3 -m http.server 8080 --directory /tmp/t30-empty </dev/null >/dev/null 2>&1 &)'
curl -sI http://rubikpi.local:8080 | head -1
```

- 확인: `HTTP/1.0 200 OK`. 30초 뒤 서버는 저절로 꺼집니다.
- 재부팅 뒤 이름이 예전 것으로 돌아가면 cloud-init이 덮어쓰는 것입니다. `/etc/cloud/cloud.cfg`에 `preserve_hostname: true`를 넣고 6단계 이름 설정을 다시 합니다.

### 9단계. 기준값 기록 (Claude가 Mac에서 실행)

```bash
ssh rubikpi '. /etc/os-release; echo "$PRETTY_NAME"; uname -mr; nproc; free -h; df -h /; uptime; timedatectl show -p Timezone -p NTPSynchronized'
date "+%F %T %Z"; ssh rubikpi 'date "+%F %T %Z"'
```

결과를 이 지침서 '결과'와 일지에 적습니다(IP 주소는 적지 않음).

## 예상 시간

다시 설치하지 않으면 1시간 안팎입니다. 다시 설치하면 이미지 받기(1 GB 넘음)와 설치로 1시간쯤 더 걸립니다.
