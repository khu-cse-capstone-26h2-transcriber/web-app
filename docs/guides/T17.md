# [T17] 핵심 로직 단위 테스트(Vitest) — 지침서

2026-11-04 · 이광호

## 목표

`CLAUDE.md`가 정한 핵심 로직 세 영역에 Vitest 단위 테스트를 붙입니다. DB와 Docker가 꺼져 있어도 `npm test` 한 번으로 돌아야 합니다.

1. 내보내기 포매터: txt·md 파일 내용과 시각·길이 표시
2. 이벤트 재개: `Last-Event-ID` 해석과, 다시 접속한 쪽에 빠진 final만 먼저 보내는 것
3. 세그먼트 병합: 웹 자막에서 같은 `segmentId`의 final을 덮어쓰고 순서를 지키는 것

T20에서 실제 STT로 바꾸기 전에 이 동작을 고정해 두면, 이벤트 모양이나 순서가 바뀌었을 때 어디가 깨졌는지 바로 드러납니다.

## 배경과 전제, 범위

2026-11-04 `main`(`a5ca49a`) 기준입니다.

- **Vitest**: 아직 설치되어 있지 않고 `test` 스크립트도 없습니다. 최신판 5.1.0은 2026-11-02에 나와 이틀밖에 안 돼, 3주 전에 나온 5.0.5를 씁니다. 5.x의 요구 범위(Node `^22.12.0`, Vite `^8.0.0`, `@types/node` `^22.0.0`)를 지금 저장소가 모두 맞춥니다.
- **포매터**: `apps/server/src/export/format.ts`와 `packages/shared/src/format.ts`는 DB와 Express를 모르는 순수 함수입니다(T11, T16이 T17을 위해 그렇게 둠). 소스를 바꾸지 않습니다.
- **이벤트 재개**: `Last-Event-ID` 해석은 `apps/server/src/sessions/routes.ts`의 `parseLastEventId`(export 안 됨), 빠진 final 고르기는 `SessionManager.subscribe`에 있습니다. `SessionManager`는 `sessions/repository.ts`와 `segments/repository.ts`를 거쳐 DB를 씁니다.
- **세그먼트 병합**: 웹 `apps/web/src/api/useSessionStream.ts` 안의 `applyMessage`(export 안 됨)가 맡습니다. 훅이 아니라 순수 함수라 브라우저 환경 없이 테스트할 수 있습니다.
- **작업 트리**: 저장소 안 `.claude/worktrees/`에 다른 세션의 작업 트리가 20개 넘게 있습니다. Vitest 기본 설정은 그 아래의 테스트 파일도 찾으므로, 찾는 범위를 워크스페이스의 `src`로 좁힙니다.

- 하는 것: Vitest 설치와 설정, 루트 `npm test`, 위 세 영역의 테스트 파일 5개, 테스트에 필요한 `export` 두 곳, 관련 문서.
- 하지 않는 것: 동작 코드 변경과 리팩터링, `SegmentWriter`의 재시도·HTTP 라우트·SSE 스트림·React 훅 자체의 테스트, 커버리지 측정, jsdom 같은 브라우저 환경, CI 설정, 실제 DB를 쓰는 테스트.

### 2. 이벤트 재개

`apps/server/src/sessions/routes.test.ts` — `parseLastEventId`

| 입력 | 기대 |
| --- | --- |
| 헤더 없음, 빈 문자열 | `undefined`(처음부터) |
| `0`, `12` | 0, 12 |
| `-1`, `01`, `1.5`, `abc`, ` 3`, `9007199254740992` | `HttpError` 400 `INVALID_LAST_EVENT_ID` |

`apps/server/src/sessions/manager.test.ts` — `SessionManager.subscribe`

`./repository`와 `../segments/repository`를 `vi.mock`으로 바꿉니다. 가짜 어댑터는 `start`에서 받은 `onEvent`를 들고 있다가 테스트가 부르면 이벤트를 넣습니다. 구독자는 받은 메시지를 배열에 모읍니다.

| 상황 | 기대 |
| --- | --- |
| `Last-Event-ID` 없이 접속 | 지금까지의 final 전부를 순서대로 먼저 받고, 접속 전 partial은 받지 않음 |
| final 0~3, `afterSegmentId` 1 | 2, 3만 먼저 받음 |
| `afterSegmentId` 0 | 1부터 받음(0을 '없음'으로 보지 않음) |
| `afterSegmentId`가 마지막 final보다 큼 | 먼저 받는 것 없음 |
| 접속 뒤 이벤트 | 먼저 받은 final에 이어 partial·final이 온 순서대로 옴. 빠지거나 겹치지 않음 |
| 연결을 끊은 뒤 | 끊은 쪽은 더 받지 않고, 다른 쪽은 계속 받음 |
| 끝난 세션에 다시 접속 | 종료 때 `ended`를 받고 닫힘. 그 뒤 접속하면 409 `SESSION_NOT_ACTIVE`(T09 결정) |

### 3. 세그먼트 병합

`apps/web/src/api/useSessionStream.test.ts` — `applyMessage`

| 상황 | 기대 |
| --- | --- |
| 빈 상태에 partial | partial로 들어감 |
| 같은 구간의 final | `finals`에 들어가고 partial이 비워짐 |
| 같은 `segmentId`의 final이 다시 옴 | 덮어쓰고 줄이 늘지 않음 |
| 순서가 바뀐 final | [0, 2]에 1 → [0, 1, 2], [1, 2]에 0 → [0, 1, 2] |
| 이미 final인 구간의 partial이 늦게 옴 | 무시(상태 그대로) |
| 앞 구간의 final이 다시 옴 | 뒤 구간의 partial은 남음 |
| 뒤 구간의 final | 앞 구간의 partial을 비움 |
| 다시 연결(final 0~2, partial 3인 상태에 final 0~2가 다시 옴) | final 3개 그대로, partial 3 그대로 |
| 원래 상태 | 바꾸지 않음 |

## 구현 순서

1. `main`에서 브랜치를 만들고 이 지침서를 커밋합니다(`docs: T17 지침서 추가`).
2. Vitest를 설치합니다.
    - 루트에서 `npm install -D vitest@5.0.5`
    - 루트 `package.json`에 `"test": "vitest run"`
    - 루트 `vitest.config.ts`: `include`는 `apps/*/src/**/*.test.ts`, `packages/*/src/**/*.test.ts`, `environment`는 `node`
    - `npm audit`이 0개인지 보고 `chore: Vitest 설치와 test 스크립트 추가`로 커밋합니다.
3. 포매터 테스트 두 파일을 쓰고, `npm test`가 통과하면 `test: 내보내기 포매터 단위 테스트 추가`로 커밋합니다.
4. `parseLastEventId`에 `export`를 붙이고 재개 테스트 두 파일을 씁니다. `test: SSE 이벤트 재개 단위 테스트 추가`로 커밋합니다.
5. `applyMessage`에 `export`를 붙이고 병합 테스트를 씁니다. `test: 웹 자막 세그먼트 병합 단위 테스트 추가`로 커밋합니다.
6. 아래 '완료 기준'을 확인합니다.
7. 기록을 남깁니다. `docs/project-overview.md`, 로컬 `CLAUDE.md`, 그날 일지, 이 지침서의 '결과'를 채웁니다. `TODO.md`는 변경안을 사용자에게 먼저 보고한 뒤 허락을 받고 고칩니다.
