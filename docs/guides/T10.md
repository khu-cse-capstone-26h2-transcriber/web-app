# [T10] 히스토리 API(목록, 상세) — 지침서

2026-10-15 · 이광호

## 목표

`GET /api/sessions`로 지난 녹음 목록을 받고, `GET /api/sessions/:id`로 한 세션의 저장된 문장 전체를 받습니다. 목록에는 끝난 세션 중 내용이 있는 것만 최근 것부터 나오고, 항목마다 세그먼트 개수와 첫 문장 미리보기가 붙습니다. T11(내보내기)과 T16(히스토리 화면)은 이 API를 씁니다.

## 배경과 전제, 범위

선행 작업은 T08(세그먼트 저장)이고 끝났습니다. T08이 final마다 `segments`에 한 행씩 쓰고, T06이 `sessions`에 세션 상태를 남깁니다. 이 작업은 그 행을 읽기만 합니다. 실행 전에 Docker Desktop이 켜져 있고 `docker compose up -d`로 DB가 떠 있어야 합니다.

이 지침서는 T06~T08과 같이 구현과 같은 세션에서 썼습니다. 코드 전문은 싣지 않습니다. 코드는 저장소의 파일(커밋 `317208a`)이 기준이고, 여기에는 결정과 동작, 확인 방법을 적습니다.

- 하는 것: 공용 `Segment`, `SessionSummary` 타입, 목록 SQL(`listFinishedSessions`)과 세그먼트 SQL(`listSegments`), 라우트 `GET /`와 `GET /:id`.
- 하지 않는 것: 내보내기와 다운로드 포맷(T11, D6), 히스토리 화면(T16), 검색(T23), 세션 삭제(백로그에 없음), 마이그레이션(스키마는 바꾸지 않음), 단위 테스트(T17).

## API 동작

성공 응답은 기존 세션 API처럼 이름 있는 키로 감싸고, 에러는 `{ "error": { "code", "message" } }`입니다.

| 요청 | 응답 |
| --- | --- |
| `GET /api/sessions` | `200`과 `{ "sessions": SessionSummary[] }`. 끝난 세션(`ended`, `interrupted`) 중 세그먼트가 하나 이상인 것만, `started_at`이 늦은 것부터(같으면 번호가 큰 것부터). 없으면 빈 배열 |
| `GET /api/sessions/:id` | `200`과 `{ "session": Session, "segments": Segment[] }`. 세그먼트는 `segmentId` 순서. 녹음 중이거나 세그먼트가 없는 세션도 응답합니다(없으면 빈 배열). 없는 번호면 `404` `SESSION_NOT_FOUND`, 번호가 양의 정수가 아니면 `400` `INVALID_SESSION_ID` |
| `GET /api/sessions/active` | 전과 같습니다. `/:id`보다 앞에 있어 `active`가 번호로 읽히지 않습니다 |
| DB가 꺼졌을 때 | 두 요청 모두 `500` `INTERNAL_ERROR`. 다른 세션 API와 같습니다 |

```json
{"sessions":[{"id":23,"status":"ended","startedAt":"2026-10-15T02:16:29.993Z","endedAt":"2026-10-15T02:16:36.460Z","segmentCount":7,"preview":"안녕하세요 오늘 회의를 시작하겠습니다"}]}
```

```json
{"session":{"id":22,"status":"ended","startedAt":"2026-10-15T02:16:10.624Z","endedAt":"2026-10-15T02:16:13.639Z"},"segments":[{"segmentId":0,"text":"안녕하세요 오늘 회의를 시작하겠습니다","startMs":0,"endMs":800},{"segmentId":1,"text":"첫 번째 안건은 일정 공유입니다","startMs":800,"endMs":1800},{"segmentId":2,"text":"다음 주까지 초안을 정리해 주세요","startMs":1800,"endMs":2800}]}
```

| 타입 (`packages/shared`) | 필드 |
| --- | --- |
| `Segment` (`segment.ts`) | `segmentId`, `text`, `startMs`, `endMs`. `segments` 한 행이고, final `SttEvent`에서 `type`만 뺀 모양입니다 |
| `SessionSummary` (`session.ts`) | `Session`의 필드에 `segmentCount`(저장된 세그먼트 개수), `preview`(첫 세그먼트의 `text`, 자르지 않음)를 더함 |

## 구현 순서

1. DB를 띄우고 `main`에서 새 브랜치를 만듭니다.

    ```bash
    docker compose up -d
    git switch -c feat/t10-history-api
    ```

2. `packages/shared/src/segment.ts`에 `Segment`를, `session.ts`에 `SessionSummary extends Session`을 두고 `index.ts`에서 내보냅니다.

3. `apps/server/src/segments/repository.ts`에 `listSegments(pool, sessionId)`를 더합니다. 맨 위 주석은 '읽고 쓰는 SQL'로 고칩니다.

    ```sql
    select segment_id, text, start_ms, end_ms
    from segments
    where session_id = $1
    order by segment_id
    ```

4. `apps/server/src/sessions/repository.ts`에 `listFinishedSessions(pool)`을 더합니다. 세션마다 개수와 첫 문장을 옆에 붙이고(`cross join lateral`), 개수가 0인 세션과 녹음 중인 세션을 뺍니다. 두 하위 질의 모두 `segments`의 기본 키 `(session_id, segment_id)`를 탑니다. `count(*)`는 pg가 문자열로 주므로 `::int`로 바꿉니다.

    ```sql
    select s.id, s.status, s.started_at, s.ended_at, g.segment_count, g.preview
    from sessions s
    cross join lateral (
      select count(*)::int as segment_count,
             (select text from segments where session_id = s.id order by segment_id limit 1) as preview
      from segments
      where session_id = s.id
    ) g
    where s.status <> 'recording' and g.segment_count > 0
    order by s.started_at desc, s.id desc
    ```

5. `apps/server/src/sessions/routes.ts`를 고칩니다.
    - `createSessionRouter(pool, sessions)`로 `pool`을 받습니다. 히스토리는 DB만 읽으므로 `SessionManager`를 거치지 않습니다. `app.ts`의 호출도 맞춥니다.
    - `GET /`: `{ sessions: await listFinishedSessions(pool) }`.
    - `GET /:id`: `parseSessionId`로 번호를 읽고, `findSession`이 없으면 `404`, 있으면 `{ session, segments: await listSegments(pool, id) }`. `/active` 뒤에 둡니다.

6. 동작을 확인하고 커밋합니다. push와 `main` 병합은 사용자가 따로 지시할 때 합니다.

    ```bash
    npm run typecheck
    npm run dev:server
    curl localhost:3000/api/sessions
    curl localhost:3000/api/sessions/N
    git add packages/shared/src apps/server/src
    git commit -m "feat: 세션 히스토리 목록·상세 API 추가"
    ```

7. 기록을 남깁니다. `docs/logs/`의 그날 일지, `docs/project-overview.md`, 이 지침서의 '결과'를 채웁니다. `TODO.md`는 변경안을 사용자에게 먼저 보고한 뒤 허락을 받고 고칩니다.

## 완료 기준

아래 확인 중 'psql과 같음'은 API와 따로, `docker compose exec db psql -U user -d transcriber`로 같은 내용을 읽어 비교한다는 뜻입니다.

| 명령어 | 기대 출력 |
| --- | --- |
| `npm run typecheck` | tsc 에러 없이 종료 코드 0 |
| `curl -i localhost:3000/api/sessions` | `200`, `application/json`. 항목의 필드가 `id`, `status`, `startedAt`, `endedAt`, `segmentCount`, `preview` |
| 목록의 번호와 순서 | psql의 `select id from sessions s where status <> 'recording' and exists (select 1 from segments g where g.session_id = s.id) order by started_at desc, id desc`와 같음 |
| 목록 전체 | `recording` 항목이 없고, `segmentCount`가 0인 항목이 없음 |
| 목록의 각 항목 | `segmentCount`가 psql의 행 수, 상세의 `segments` 길이와 같고, `preview`가 `segment_id`가 가장 작은 행의 `text`와 같음 |
| 세그먼트를 2, 0, 1 순서로 넣은 임시 세션(`ended`) | 목록 맨 앞, `preview`가 0번의 `text`. 상세는 0, 1, 2 순서. 확인 뒤 임시 세션은 지움 |
| `curl localhost:3000/api/sessions/N` (끝난 세션) | `200`. `session`이 목록의 그 항목과 같은 값이고, `segments`가 psql의 `select segment_id, text, start_ms, end_ms … order by segment_id`와 같음 |
| 세그먼트가 없는 세션의 상세 | `200`, `"segments":[]` |
| `curl localhost:3000/api/sessions/999999`, `…/abc` | `404` `SESSION_NOT_FOUND`, `400` `INVALID_SESSION_ID` |
| `curl localhost:3000/api/sessions/active` | 전과 같이 `{"session":null}` (녹음 중이 아닐 때) |
| 녹음 중에 목록과 그 세션의 상세 | 목록에는 없음. 상세는 `status: recording`, `endedAt: null`, 그때까지 저장된 세그먼트 |
| 그 세션을 `stop`한 뒤 목록 | 맨 앞에 나오고 `segmentCount`가 psql의 행 수와 같음 |
| `docker compose stop db` 뒤 목록과 상세 | 둘 다 `500` `INTERNAL_ERROR`. `docker compose start db` 뒤 `200` |

## 결정 사항과 남은 질문

- 이미 정한 것: 위 '착수 전 확인'의 다섯 가지, 세션 API의 응답 모양과 에러 형식(T04, T06), final만 저장한다는 것(T08).
- 이 지침서에서 정한 것:
  - **응답 모양은 목록 `{ sessions }`, 상세 `{ session, segments }`입니다.** 기존 `{ session }`과 같이 이름 있는 키로 감쌉니다.
  - **공용 타입은 `Segment`와 `SessionSummary`입니다.** `SessionSummary`는 `Session`을 넓힌 것이라 목록 항목을 세션처럼 다룰 수 있습니다.
  - **미리보기는 첫 세그먼트의 `text`를 자르지 않고 보냅니다.** 화면에서 줄이는 것은 T16에서 정합니다.
  - **'최신순'은 `started_at`이 늦은 것부터입니다.** 같은 시각이면 번호가 큰 것부터입니다.
  - **녹음 중인 세션의 상세는 DB에 저장된 세그먼트만 보여 줍니다.** 저장 대기열(T08)에 있는 것과 아직 final이 오지 않은 문장은 들어 있지 않습니다. 실시간 내용은 스트림(T07)으로 봅니다.
  - **히스토리는 `SessionManager`를 거치지 않고 라우트에서 repository를 바로 부릅니다.** `SessionManager`는 진행 중인 세션만 맡습니다. 이를 위해 세션 라우터가 `pool`도 받습니다.
  - **녹음 길이는 응답에 넣지 않았습니다.** 화면에서 `startedAt`과 `endedAt`으로 셀 수 있습니다.
  - **스키마와 인덱스는 바꾸지 않았습니다.** 두 질의 모두 `segments`의 기본 키를 탑니다.
  - **DB가 꺼지면 `500`입니다.** 다른 세션 API와 같게 두었습니다.
- 아직 정해야 하는 것:
  - 서버가 강제로 꺼진 세션의 `ended_at` 보정 (T06에서 넘어옴). 지금은 서버를 다시 켠 시각이 들어가므로, 화면에서 `endedAt - startedAt`으로 길이를 세면 그런 세션은 실제보다 길게 나옵니다. T16 전에 보정할지, 마지막 세그먼트의 `endMs`를 길이로 쓸지 정합니다.
  - 세션 API가 DB가 꺼졌을 때 `500` 대신 `503`을 낼지 (T13 전).
  - 세그먼트가 없는 세션은 목록에서만 빠지고 DB에는 남습니다. 지울지, 시작만 하고 바로 끈 세션을 따로 다룰지는 정하지 않았습니다.
  - 목록의 limit. 세션이 많아지거나 Rubik Pi 실측(T21)에서 느리면 더합니다.
  - 다운로드 포맷 (D6, T11 전).
