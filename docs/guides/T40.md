# [T40] 히스토리 화면 디자인 — 지침서

2026-11-19 · 이광호

## 목표

히스토리 목록(`/history`), 상세(`/history/:id`), 없는 주소 화면을 확정안(F-3 목록, F-4 상세, F-7 요소와 상태)대로 바꿉니다. 끝나면 아래가 됩니다.

1. 목록: 제목 `히스토리`와 `지난 녹음 N개`, 녹음마다 카드 한 장(번호, 시작 시각, `문장 N개`, 중단됐으면 노란 `중단됨`, 첫 문장 한 줄, 오른쪽 화살표). 녹음이 진행 중이면 맨 아래에 `녹음 중인 #48은 끝난 뒤 목록에 나타납니다.`
2. 상세: `← 히스토리`, 제목 `녹음 #48`, 정보 칩(`2026-11-18 14:05 시작`, `길이 38분 12초`)과 상태 표시(종료됨 초록, 중단됨 노랑, 녹음 중 빨강), 오른쪽에 흰 'txt 내려받기'와 어두운 'md 내려받기', 구분선 아래 문장마다 왼쪽에 시각.
3. 불러오는 중, 빈 상태, 오류 문구는 지금 문구 그대로 확정안 색으로 보입니다. 없는 주소 화면도 같은 모양으로 맞춥니다.

## 배경과 전제, 범위

- 확정 디자인과 구현 방식은 T38 지침서의 '배경과 전제'와 같습니다. 화면의 동작(T16)과 문구는 그대로 두고 모양만 바꿉니다. 화면과 내려받은 파일의 시각·길이 표기가 같도록 `@app/shared`의 함수를 그대로 씁니다.
- 목록 아래 안내는 T39의 `activeSession`을 씁니다.

- 하는 것: 히스토리 목록, 상세, 내려받기 버튼, 없는 주소 화면, 녹음이 끝났을 때 목록 다시 불러오기.
- 하지 않는 것: 검색·화자·요약(P2), 서버 변경, 녹음 화면(T39), 단위 테스트(핵심 로직이 아님).

## 구현 순서

1. `useApiData`에 다시 불러오는 동안 직전 결과를 두는 선택(`keepPrevious`)을 더합니다. 지금 쓰는 곳의 동작은 그대로입니다.
2. `Layout`이 진행 중이던 녹음이 끝날 때마다 느는 번호(`historyRound`)를 `LayoutContext`로 넘깁니다(사이드바 최근 녹음과 같은 번호).
3. 목록 화면을 카드 목록으로 바꾸고, `historyRound`가 바뀌면 직전 목록을 둔 채 다시 불러옵니다. 진행 중인 녹음이 있으면 맨 아래 안내를 보입니다.
4. 상세 화면의 머리말(칩, 상태 표시), 내려받기 버튼, 문장 목록을 바꿉니다.
5. 없는 주소 화면을 같은 여백과 제목 크기로 맞춥니다.
6. 아래 '완료 기준'을 확인합니다.
7. 기록을 남깁니다(`project-overview.md`, 일지, 이 지침서 '결과'). `TODO.md`와 로컬 `CLAUDE.md`는 T38~T40을 묶어 변경안을 먼저 보고합니다.
