# [T25] T18에서 찾은 문제 처리: Node 판 고정, 의존성 취약점, 서버 상태 표시 — 지침서

2026-10-30 · 이광호

## 목표

T18(M1 점검)에서 기록만 해 둔 문제 3개를 고칩니다.

1. 저장소에 Node 판을 적고, 기준을 지원이 끝난 Node 20에서 Node 22로 올립니다. 다른 판으로 `npm ci`를 하면 실패해 바로 드러나게 합니다.
2. `npm audit`의 취약점 2개(`body-parser` high, `qs` moderate)를 없앱니다.
3. 서버가 다시 켜지면 위쪽 서버 상태가 늦어도 5초 안에 `정상`으로 돌아오게 하고, 서버가 멈춰 답하지 않을 때 `정상`으로 남지 않게 합니다.

## 배경과 전제, 범위

2026-10-30에 다시 확인한 내용입니다.

- **Node 판**: `.nvmrc`, `.node-version`, `engines`가 없습니다. 이 컴퓨터의 nvm 기본값은 22.22.0이라 새 셸에서는 22로 돕니다. Node 공식 일정(`nodejs/Release`의 `schedule.json`)에서 Node 20은 2026-04-30에 지원이 끝났고(보안 수정 없음), Node 22는 2027-04-30까지 보안 수정이 나옵니다. 지금 패키지는 모두 22를 지원합니다(Vite 8.3.4 `^20.19.0 || >=22.12.0`, React Router 7.18.4 `>=20.0.0`, Express 5.3.0 `>= 18`, pg 8.23.1 `>= 16.0.0`, tsx 4.23.15 `>=18.0.0`).
- **취약점**: 둘 다 Express 5.3.0(최신)이 끌어옵니다. Express의 범위는 `body-parser ^2.3.0`, `qs ^6.16.0`이고, 고친 판(`body-parser` 2.4.0, `qs` 6.17.1)이 이 범위 안에 있어 `package-lock.json`만 바뀝니다.
  - `body-parser`(GHSA-27r3-jxmh-p828, 압축된 요청 본문 뒤의 바이트로 인한 서비스 거부)는 해당합니다. `app.ts`의 `express.json()`이 모든 요청에 걸려 있고, 압축된 본문을 푸는 기능이 기본으로 켜져 있습니다.
  - `qs`(GHSA-6pq8-jhm2-2vcw, `qs.stringify` 서비스 거부)는 사실상 해당하지 않습니다. Express 5의 기본 쿼리 파서는 Node 내장(`simple`)이고, 우리 코드는 `urlencoded`와 `qs.stringify`를 쓰지 않습니다. 같은 명령으로 함께 올라갑니다.
- **서버 상태**: 위쪽 서버 상태는 30초마다, 그리고 실시간 연결이 다시 열렸을 때만 바로 다시 확인합니다(T15). T18의 실패 경로 B(녹음 중 서버 재시작)에서는 서버가 돌아온 뒤 `GET /api/sessions/active`가 진행 중인 녹음이 없다고 답해, 스트림을 다시 열지 않고 히스토리 상세로 넘어갑니다. 그래서 바로 다시 확인하지 않고, 마지막 실패(10:29:09)부터 30초를 기다렸습니다. 녹음하지 않을 때(히스토리를 보는 중에 서버가 다시 켜짐)도 같습니다. 또 `/health` 요청에 시간 제한이 없어, 서버가 멈춘 동안(`SIGSTOP`)에는 직전 결과(`정상`)가 계속 남는 것으로 보입니다(코드로 본 것, 이 작업에서 확인).

실행 전에 Docker Desktop이 켜져 있고 DB 컨테이너가 떠 있어야 하며, 루트 `.env`가 있어야 합니다. 3000, 4173 포트는 비어 있어야 합니다.

- 하는 것: `.nvmrc`·`.npmrc`·`engines`·`@types/node`로 Node 22 고정, `npm audit fix`, `useServerHealth.ts`의 다시 확인 간격과 시간 제한, 관련 문서.
- 하지 않는 것: 다른 패키지 판 올리기(React Router 8.x 포함), `express.json()` 빼기(지금은 본문을 읽는 라우트가 없지만 D4에서 STT 데몬이 본문을 보낼 수 있음), 서버와 `packages/shared` 코드 변경, 실시간 연결과 배너 동작 변경, 기기에 Node 설치(T21), 단위 테스트(T17), 이 컴퓨터의 nvm 설정 변경.

## 구현 순서

1. DB를 띄우고 `main`에서 새 브랜치를 만듭니다.

    ```bash
    docker compose up -d --wait
    git switch -c fix/t18-findings
    ```

2. Node 판을 고정합니다. Node 22.22.0(npm 10.9.4)에서 합니다.
    - 루트에 `.nvmrc`(`22.22.0`), `.npmrc`(`engine-strict=true`)를 만듭니다.
    - 루트 `package.json`에 `"engines": { "node": "^22.12.0" }`를 넣고, `npm install -D @types/node@^22`로 올립니다.
    - `npm run typecheck`를 통과하면 `chore: Node 기준 판을 22로 고정`으로 커밋합니다.

3. 취약점을 고칩니다. `npm audit fix`를 실행하고, `npm audit`이 0개인지, 바뀐 파일이 `package-lock.json` 하나인지 봅니다. `fix: body-parser·qs 취약점 해결`로 커밋합니다.

4. `useServerHealth.ts`를 고칩니다.
    - 확인을 시작할 때 다음 확인을 30초 뒤로 예약하는 것은 그대로 둡니다.
    - 확인이 실패하면 예약을 지우고 5초 뒤로 다시 겁니다.
    - 요청을 5초 뒤에 끊고, 그렇게 끊은 것은 `서버가 답하지 않습니다`로 보입니다. 다음 확인이 시작되거나 화면을 떠나 취소된 요청은 결과를 버립니다.
    - `npm run typecheck`, `npm run build -w @app/web`가 통과하면 `fix: 서버 상태를 실패 중 5초마다 다시 확인`으로 커밋합니다.

5. 아래 '완료 기준'을 확인합니다.

6. 기록을 남깁니다. `docs/project-overview.md`, T12·T15 지침서의 덧붙임, 로컬 `CLAUDE.md`, 그날 일지, 이 지침서의 '결과'를 채웁니다. `TODO.md`는 변경안을 사용자에게 먼저 보고한 뒤 허락을 받고 고칩니다.
