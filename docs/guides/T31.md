# [T31] Express가 웹앱 빌드 내보내기 — 지침서

2026-11-12 · 이광호

## 목표

기기(Rubik Pi)에서 Vite 없이 서버 포트 하나로 웹앱과 API를 함께 엽니다. 끝나면 아래가 됩니다.

1. `npm run build:web` 뒤 `npm run dev:server`를 띄우면 `http://<서버 주소>:3000`에서 웹앱이 열립니다.
2. `/history/12`처럼 화면 주소로 바로 들어가거나 새로고침해도 그 화면이 나옵니다.
3. API(`/api/…`, `/health`)와 SSE 스트림은 지금과 똑같이 동작합니다. 없는 API 경로는 지금처럼 JSON 404입니다.
4. 빌드가 없으면 서버는 API만 열고, 그 사실을 로그로 알립니다.
5. 노트북 개발 방식(`npm run dev:web`, 5173, Vite 프록시)은 그대로입니다.

## 배경과 전제, 범위

- T21 착수 전 결정이던 '웹앱 제공 방법'을 2026-11-12에 사용자가 정했습니다: Express가 `apps/web/dist`를 내보냄. T12에서 Vite를 고를 때 '빌드 결과가 정적 파일이라 나중에 기기의 Express가 그대로 내보낼 수 있다'고 적어 둔 방향입니다.
- 지금 Vite 개발 서버는 `localhost`에서만 열려, 노트북 브라우저로 보드의 웹앱을 볼 방법이 없습니다. `vite preview --host`도 되지만 보드에서 Vite 프로세스가 하나 더 돌아 T21 메모리 측정이 섞이고 포트가 둘이 됩니다.
- 서버는 `app.listen(env.port)`로 주소를 지정하지 않아 모든 인터페이스에서 열립니다(T04). 그래서 이 작업만으로 다른 기기에서 접속됩니다. 로그인이 없으므로 믿을 수 있는 네트워크에서만 씁니다.
- 웹앱은 API를 `/api/…`, `/health` 같은 같은 출처 경로로 부르므로(T12) 웹 코드는 바꾸지 않습니다. CORS도 필요 없습니다.
- 웹 빌드는 `vite.config.ts`가 루트 `.env`의 `PORT`를 읽으므로 `.env`가 있어야 합니다(기기에서도 같음).

- 하는 것: 서버에 웹앱 빌드 제공(정적 파일, 화면 주소 처리, 캐시 헤더), 시작 로그, 루트 `build:web` 스크립트, 관련 문서.
- 하지 않는 것: 보드에 설치·빌드(T21), 서버 자동 시작(systemd, T26·T27에서 정함), 웹 코드 변경, `vite.config.ts` 변경, HTTPS·압축·로그인, 단위 테스트(핵심 로직이 아님, CLAUDE.md 규칙).

## 구현 순서

1. `http/web.ts`에 `createWebRouter(distDir)`를 만듭니다. `index.html`이 없으면 `null`을 돌려줍니다. 있으면 `assets/`(긴 캐시), 나머지 정적 파일(`index: false`), 화면 주소 처리(위 '동작' 표)를 붙인 라우터를 돌려줍니다. 빌드 위치 `WEB_DIST_DIR`도 여기서 내보냅니다.
2. `app.ts`의 `createApp`이 웹 라우터를 인자로 받아, API 라우트 뒤·`notFoundHandler` 앞에 붙입니다. `null`이면 붙이지 않습니다.
3. `index.ts`가 `createWebRouter(WEB_DIST_DIR)`를 부르고, 시작 로그에 제공 여부를 적습니다. 빌드가 없으면 `npm run build:web` 뒤 다시 켜라고 알립니다.
4. 루트 `package.json`에 `build:web`을 넣습니다.
5. 아래 '완료 기준'을 확인합니다.
6. 기록을 남깁니다(`project-overview.md`, T12 덧붙임, 일지, 이 지침서 '결과'). `TODO.md`와 로컬 `CLAUDE.md`는 변경안을 먼저 보고합니다.
