# [T14] 실시간 트랜스크립트 화면 — 지침서

2026-10-22 · 이광호

## 목표

녹음 화면(`/`)에서 녹음 중일 때 버튼 아래에 실시간 자막을 보여 줍니다. 확정된 문장(final)이 차례로 쌓이고, 지금 말하는 중인 문장(partial)은 맨 아래에 흐린 한 줄로 늘어나다가 같은 자리에서 final로 바뀝니다. 녹음 도중에 화면을 열거나 새로고침해도 지금까지의 문장이 다시 채워지고, 어디서 끝냈든 녹음이 끝나면 히스토리 상세로 넘어갑니다.

## 배경과 전제, 범위

선행 작업 T07(SSE 스트림), T09(이어받기), T12(웹앱 뼈대), T13(녹음 제어 UI)은 끝났습니다. 실행 전에 Docker Desktop이 켜져 있고 `docker compose up -d`로 DB가 떠 있어야 하며, 루트 `.env`가 있어야 합니다.

구현은 2026-10-21에 지침서 없이 결정만 먼저 받고 진행했고(커밋 `8d45deb`), 이 지침서는 2026-10-22에 그 구현을 기준으로 썼습니다. 코드 전문은 싣지 않습니다. 코드는 저장소의 파일이 기준이고, 여기에는 결정과 동작, 확인 방법을 적습니다.

- 하는 것: 세션 스트림을 구독하는 훅, 자막 컴포넌트(final 목록, 흐린 partial 한 줄, 바닥을 보고 있을 때만 자동 스크롤), 녹음 화면에 붙이기, 스트림의 `ended`를 받으면 히스토리 상세로 이동.
- 하지 않는 것: 끊김 감지와 상단 배너, 재연결 정책, `409`로 스트림이 멈췄을 때의 문구(T15), 화면을 열어 둔 동안 다른 곳에서 시작한 녹음을 알아채는 것(D4 뒤), 서버 변경, 디자인.

## 화면 동작

| 상황 | 화면 |
| --- | --- |
| 녹음 중인데 아직 문장이 없음 | 자막 상자에 흐린 `말을 기다리는 중…` |
| partial이 옴 | 맨 아래 흐린 줄(`#888`)이 늘어남. 줄 수는 늘지 않음 |
| final이 옴 | 흐린 줄이 같은 자리에서 검은 글자로 바뀌고 줄이 하나 늘어남 |
| 바닥을 보고 있을 때 새 문장 | 바닥으로 따라 내려감 |
| 위로 올려 읽는 중에 새 문장 | 스크롤 위치를 그대로 둠. 다시 바닥으로 내리면 따라감 |
| 녹음 중 새로고침 | 지금까지의 final이 다시 채워지고 바닥에 붙음(서버가 접속하면 final을 먼저 보냄, T09) |
| 밖에서 종료(기기 버튼, 다른 탭, curl) | 스트림의 `ended`를 받고 `/history/:id`로 이동 |
| 웹의 '녹음 종료' | 종료 응답과 `ended` 중 먼저 온 쪽에서 한 번만 이동 |
| 녹음하지 않음, 확인 중 | 자막 상자를 보이지 않음 |

자막 상자는 화면 높이의 60%까지 커지고 그 뒤로는 상자 안에서 스크롤합니다. 스크린 리더가 새 문장을 읽도록 `aria-live="polite"`를 붙였습니다.

| 파일 | 바뀐 것 |
| --- | --- |
| `apps/web/src/api/useSessionStream.ts` | `useSessionStream(sessionId, onEnded)`: `EventSource`로 `/api/sessions/:id/events`를 구독해 `{ finals, partial }`을 돌려줍니다. `sessionId`가 `null`이면 구독하지 않습니다. `ended`를 받으면 스트림을 먼저 닫고 `onEnded(session)`을 부릅니다 |
| `apps/web/src/components/Transcript.tsx` | `Transcript`: final 목록과 흐린 partial 한 줄, 자동 스크롤 |
| `apps/web/src/pages/RecordPage.tsx` | 녹음 중·종료 중일 때 스트림을 구독하고 버튼 아래에 `Transcript`를 그림. 이동은 `goToHistory` 하나로 모음 |
| `apps/web/src/api/endpoints.ts` | 맨 위 주석만 고침(스트림은 `useSessionStream.ts`에 있음) |

스트림 메시지를 자막 상태에 넣는 규칙은 다음과 같습니다.

- final은 `segmentId` 자리에 넣습니다. 같은 번호가 이미 있으면 덮어쓰고, 없으면 번호 순서를 지켜 끼웁니다. 다시 접속했을 때 서버가 보내는 final이 겹쳐도 줄이 늘지 않습니다.
- final이 오면 그 번호 이하의 partial을 지웁니다.
- 이미 확정된 번호의 partial이 늦게 오면 무시합니다.
- `heartbeat`는 무시합니다.

## 구현 순서

1. Docker Desktop을 켜고 DB를 띄운 뒤 `main`에서 새 브랜치를 만듭니다.

    ```bash
    docker compose up -d --wait
    git switch -c feat/t14-live-transcript
    ```

2. `useSessionStream.ts`를 씁니다. `onEnded`는 ref에 두어, 함수가 바뀌어도 다시 접속하지 않게 합니다. `ended`를 받으면 `onEnded`보다 먼저 `source.close()`를 부릅니다. 서버가 곧 스트림을 닫는데, 그 전에 닫지 않으면 `EventSource`가 다시 접속해 `409`를 받습니다.

3. `Transcript.tsx`를 씁니다. 자동 스크롤은 `useLayoutEffect`에서 '직전에 그렸을 때의 내용 높이'와 지금 스크롤 위치로, 사용자가 바닥(40px 안)을 보고 있었는지 가립니다. `scroll` 이벤트로 바닥 여부를 기록하는 방식은 이벤트보다 다시 그리기가 먼저 올 때 위로 올린 스크롤을 바닥으로 되돌려서 쓰지 않습니다(2026-10-21에 실패를 확인함).

4. `RecordPage.tsx`에서 `phase`가 `recording`이나 `stopping`일 때 세션 번호를 훅에 넘기고, 버튼과 안내 문구 사이에 `Transcript`를 둡니다. 종료 응답과 `ended`가 둘 다 오므로 `leftRef`로 한 번만 이동합니다.

5. 동작을 확인하고 커밋합니다. Vite는 터미널(또는 백그라운드 셸)에서 `npm run dev:web`으로 띄웁니다. 2026-10-21에 미리보기 도구의 `launch.json`으로 띄운 Vite는 프록시 연결이 `EAGAIN`으로 실패했습니다.

    ```bash
    npm run typecheck
    npm run build -w @app/web
    npm run dev:server   # 다른 터미널
    npm run dev:web      # http://localhost:5173
    git add apps/web/src
    git commit -m "feat: 녹음 화면에 실시간 자막 추가"
    ```

6. 기록을 남깁니다. `docs/logs/`의 그날 일지, `docs/project-overview.md`, 이 지침서의 '결과'를 채웁니다. `TODO.md`는 변경안을 사용자에게 먼저 보고한 뒤 허락을 받고 고칩니다.

## 완료 기준

브라우저 확인은 Claude 데스크톱 앱의 브라우저 패널에서 했습니다. 글자 색과 스크롤 위치는 브라우저 콘솔(JavaScript)로 읽었습니다. 'psql과 같음'은 `docker compose exec db psql -U user -d transcriber`로 같은 내용을 읽어 비교한다는 뜻입니다. 밖에서 종료하는 것은 curl로 물리 버튼을 대신한 것입니다.

| 명령어 | 기대 출력 |
| --- | --- |
| `npm run typecheck` | tsc 에러 없이 종료 코드 0 |
| `npm run build -w @app/web` | `✓ built` |
| 브라우저 `/`에서 '녹음 시작' | 몇 초 안에 자막 상자에 final 줄(검정 `rgb(0, 0, 0)`)이 생기고, 맨 아래 partial 줄은 흐림(`rgb(136, 136, 136)`) |
| partial이 늘어나는 동안 | 줄 수는 그대로, 같은 줄이 final이 되면 검정으로 바뀌고 줄이 하나 늘어남 |
| 바닥을 보고 있을 때 몇십 초 기다림 | 바닥과의 간격이 1px 안 (`scrollHeight - scrollTop - clientHeight`) |
| 자막 상자를 위로 올림(`scrollTop = 50`) 뒤 기다림 | 새 줄이 와도 `scrollTop`이 `50`으로 유지 |
| 다시 바닥으로 내린 뒤 기다림 | 새 줄을 따라 바닥에 붙음 |
| 녹음 중 새로고침 | 지금까지의 final이 다시 채워지고 바닥에 붙음 |
| curl `POST /api/sessions/:id/stop` | 화면이 `/history/:id`로 이동, 세그먼트 개수가 psql과 같음 |
| 새 녹음을 시작하고 웹의 '녹음 종료' | `/history/:id`로 이동, `history.length`가 1만 늘어남, 세그먼트 개수가 psql과 같음 |
| 브라우저 콘솔 | 에러 없음 |
| 서버에 `SIGINT` | `[server] 종료 완료` |
| `npm run db:migrate` | `skip` 두 줄, `새로 적용 0개, 전체 2개` |
| `npm run dev:stt` | `[stt]` 15줄 |
| `git log --oneline -1` (코드 커밋 직후) | `feat: 녹음 화면에 실시간 자막 추가` |

## 결정 사항과 남은 질문

- 이미 정한 것: 위 '착수 전 확인'의 네 가지, 스트림 메시지 형식과 이어받기(T07, T09), 녹음 화면의 상태와 버튼(T13).
- 구현하면서 정한 것:
  - **이미 확정된 세그먼트의 partial이 늦게 오면 무시합니다.** final이 오면 그 번호 이하의 partial을 지웁니다.
  - **웹 버튼으로 끝낼 때는 종료 응답과 `ended` 중 먼저 온 쪽에서 한 번만 이동합니다**(`leftRef`). 확인했을 때 `history.length`는 1만 늘었습니다.
  - **바닥에서 40px 안이면 바닥을 보고 있다고 봅니다.** 자막 상자 높이는 화면의 60%까지입니다.
  - **끊겼을 때의 재연결은 `EventSource` 기본 동작에 맡깁니다.** 다시 접속하면 브라우저가 `Last-Event-ID`를 보내고, 겹치는 final은 덮어쓰므로 줄이 늘지 않습니다. 배너와 끊김 감지는 T15에서 만듭니다.
  - **자막이 아직 없으면 `말을 기다리는 중…`을 보여 줍니다.**
  - **종료 중(`stopping`)에도 구독을 유지합니다.** 종료가 실패해 녹음 중으로 돌아가도 같은 스트림을 계속 씁니다.
- 아직 정해야 하는 것:
  - 서버가 `409`(이미 끝난 세션)로 답하면 `EventSource`가 닫힌 채로 남고 화면에는 아무 문구도 보이지 않습니다. 끊긴 사이에 세션이 끝난 경우입니다. 문구와 히스토리 상세로 넘어갈지는 T15에서 함께 정합니다.
  - 서버를 끄면 `ended` 없이 끊기고 `EventSource`가 계속 다시 접속합니다. 끊김 표시는 T15입니다.
  - 화면을 열어 둔 동안 다른 곳에서 시작한 녹음을 알아채는 방법(D4 뒤). [하드웨어]
  - 실제 STT의 partial 빈도와 문장 길이에 따라 자막 상자 높이와 스크롤 기준을 다시 볼 수 있습니다(T20 뒤). [AI]
